# MindStudio Ops Profiler 版本说明 — 一体化深度解读

---

## 【定位】

本篇文档为「MindStudio Ops Profiler (msOpProf)」的**双版本发版变更说明**，同步发布内测版 **26.0.0** 与正式版 **8.3.0**，集中回答「产品配套何种 CANN / Python / 工具链版本」「两个版本各自新增了哪些算子级性能分析能力」「做了哪些优化与构建变更」「有哪些兼容性适配」四个问题，是面向开发者理解工具能力边界与升级路径的总入口。

---

## 【技术要点】

1. **双模式性能分析架构**：8.3.0 起首次正式发布，区分 **msOpProf 模式**（基于上板/真实运行的算子性能采集）与 **msOpProf simulator 模式**（基于指令级仿真），二者共享"算子代码热点图"能力，但可视化维度不同——前者侧重资源/带宽/Cache 等板上数据，后者侧重指令流水与时序吞吐。
2. **AscendC API 打点机制**：26.0.0 新增支持**通过 AscendC API 在算子 block 上打点**，采集代码在 block 上的实际耗时，用于生成"通算流水图"，构成"自定义通算融合框架"性能分析能力的核心入口。
3. **SIMT VF 指令多维指标扩展**：26.0.0 在计算内存热力图的「核间负载分析」中拓展 SIMT VF 指令的**发射效率与负载均衡**指标；在代码热点图中拓展 **Stall 分析与寄存器利用率**指标，针对性解决 SIMT VF 指令的瓶颈定位。
4. **Scalar 精细化分析**：26.0.0 在性能数据文件及「计算内存热力图-内存负载分析」中扩展 Scalar 单元的耗时阻塞相关指标，用于判断 Scalar 单元的具体阻塞位置。
5. **依赖工具链与编译适配**：26.0.0 适配 **毕昇编译器编译选项变更**，并兼容 **CANN 芯片标识变更**，覆盖多种新增芯片规格型号；安装包更名为 `mindstudio-opprof_linux.run`，新增 **pigz 依赖提示**与 **debug 编译选项**支持断点调试。
6. **依赖仓下载加速**：构建发布层面，依赖仓下载功能优化，**下载速度提升 10 倍**；构建产物、落盘文件的权限及属组同步收紧以提升软件安全。

---

## 【关键机制与数据】

- **多版本并行发布机制**：同一份 changelog 同时承载内测版 (26.0.0) 与正式版 (8.3.0) 的差异，26.0.0 在功能、优化、构建、文档四个维度均给出具体变更条目，8.3.0 作为首次正式发布仅给出功能基线。
- **性能数据呈现路径**（原文: 8.3.0 起 msOpProf 模式提供「性能数据文件」）："从多个性能指标维度展示算子详细性能数据"，是其它可视化视图（热力图、流水图、Roofline）背后的原始数据来源。
- **瓶颈定位数据流**（原文: 8.3.0 Roofline 瓶颈分析图）："构建出处理器的性能模型，然后利用该性能模型快速评估出算子的理论性能极限，协助开发者快速识别瓶颈类型"——即先建立理论上限，再用实测对照识别瓶颈类型（计算受限 / 带宽受限 等）。
- **Cache 优化闭环**（原文: 8.3.0 Cache 热力图）："可视化呈现 Cache 热力图，可显示对应指令信息，以优化 L2Cache 命中率"——以指令为锚点反查 Cache 命中表现。
- **带宽时序分析**（原文: 8.3.0 simulator 模式「内存通路吞吐率波形图」）："查看算子 MTE 日志通路的内存带宽在时序上的统计分析能力，可协助开发者识别算子各阶段的带宽使用状况，并分析带宽优化的可行性"——按 MTE 通路维度分解带宽使用的时间分布。
- **构建性能数据**：原文标注"优化依赖仓下载功能，**10 倍**提升下载速度"。
- **软件安全机制**：原文标注"变更构建产物、落盘文件权限及属组"，属于构建侧权限收紧，无具体数值参数。

## 【表格解读】

### 表 1：产品版本信息

| 产品名称 | 产品版本 | 版本类型 |
|----------|----------|----------|
| msOpProf | 26.0.0 | 内测版本 |
| msOpProf | 8.3.0 | 正式版本 |

**逐行解读：**

- **msOpProf / 26.0.0 / 内测版本**：定位为先行版本，对应 26.0.0 章节中的全部新增功能、优化、构建发布、文档类变更，是开发者尝鲜与反馈的通道。
- **msOpProf / 8.3.0 / 正式版本**：定位为 GA 版本，对应 8.3.0 章节中"首次发布"的所有功能条目，是生产环境建议使用的稳定基线。

### 表 2：相关产品版本配套说明

| msOpProf版本 | CANN版本 | Python版本 | json版本 | securec版本 | makeself版本 | llvm-project版本 |
|--------------|----------|------------|----------|-------------|--------------|------------------|
| 26.0.0 | 推荐 9.0.0 及以上 | 推荐 3.11 及以上 | v3.12.0 及以上 | v1.1.16 及以上 | release-2.5.0 及以上 | 22.1.2 及以上 |
| 8.3.0 | 8.2.RC1 及以上版本 | 推荐 3.11 及以上 | v3.12.0 及以上 | v1.1.16 及以上 | release-2.5.0 及以上 | 22.1.2 及以上 |

**逐行解读：**

- **26.0.0 行**：CANN 起步版本要求最高，**推荐 9.0.0 及以上**（明显高于 8.3.0 的 8.2.RC1），这与"适配多种新增芯片规格型号、兼容 CANN 芯片标识变更"形成因果——新 CANN 才有新芯片标识；其余 6 个依赖项（Python 3.11+、json v3.12.0+、securec v1.1.16+、makeself release-2.5.0+、llvm-project 22.1.2+）与 8.3.0 完全一致。
- **8.3.0 行**：CANN 起步版本放宽到 **8.2.RC1 及以上**，是面向已有 CANN 8.2 体系的存量用户；其余 6 个依赖项阈值与 26.0.0 完全相同，说明两个版本在非 CANN 工具链层面**基线统一**，差异集中在 CANN/芯片能力适配。

> **跨表小结**：两个表格共同定义了"安装 msOpProf 前必须就位的环境清单"——除 msOpProf 版本号、CANN 起步版本有差异外，其余依赖完全一致，构成安装前置检查的核心依据。

## 【关联】

- **与 CANN 的关系——版本配套**：26.0.0 推荐 CANN 9.0.0+、8.3.0 适配 CANN 8.2.RC1+，且 26.0.0 显式"兼容 CANN 芯片标识变更"，说明 msOpProf 的功能能力受 CANN 芯片标识体系直接约束。
- **与毕昇编译器的关系——编译适配**：26.0.0 显式"适配毕昇编译器编译选项变更"，意味着该版本的编译产物/解析路径需对齐毕昇编译器新选项，上游编译器侧的改动会被 msOpProf 同步消费。
- **与 AscendC 编程框架的关系——打点采集入口**：26.0.0 通过 AscendC API 在算子 block 上打点以生成通算流水图，8.3.0 同样在"通算流水图（通算融合算子）"中依赖 AscendC API 打点采集 block 耗时；AscendC 是 msOpProf 采集通算融合类算子性能数据的唯一编程入口。
- **与算子库的关系——性能调优对象**：26.0.0 新增"支持 shmem 算子库、asc 算子库的性能调优"，表明 msOpProf 的调优对象从通用算子扩展到这两类专用算子库。
- **与 llvm-project 的关系——二进制依赖**：配套表要求 llvm-project ≥ 22.1.2，间接影响 msOpProf 在指令级（指令流水图、指令信息排序）上的解析能力。
- **与 docs 仓的关系——文档同步**：26.0.0 文档类变更指出"在 docs 仓新增用户指南等其余文档和图片"，且安装指南被重命名为 `msopprof_install_guide.md`，提示文档内容已拆分到独立 docs 仓；本次解读原文路径 `docs/zh/release_notes/release_notes.md` 即属于该 docs 仓内。
- **与 makeself / securec / json 的关系——打包与安全依赖**：三者共同构成 msOpProf 安装包构建与运行期依赖，分别管控自解压安装、安全函数库与 JSON 解析路径。
