# mindspeed-mm 版本说明文档深度解读 (v26.1.0)

## 【定位】

本文档是 MindSpeed MM v26.1.0 的正式版本发布说明 (Release Notes),面向使用华为昇腾 NPU 进行多模态大模型分布式训练的用户,集中说明该版本的**配套关系、兼容性矩阵、新增特性、升级影响、配套文档与安全审计结果**,为版本选型、依赖对齐和升级决策提供官方依据。

## 【技术要点】

1. **产品版本标识**: MindSpeed MM v26.1.0,正式版本,2026 年 7 月发布,维护周期 6 个月。
2. **新增模型**: 新增支持 **Qwen3.5** 与 **Kimi-K2.5** 两个多模态模型。
3. **新增训练特性 (仅适用于 Qwen3.5 / Kimi-K2.5)**: 支持**激活值异步卸载 (activation asynchronous offloading)**、**chunk loss**、**chunk mbs** 三项优化机制。
4. **新增硬件支持**: 支持 **Ascend 950** 系列产品。
5. **Megatron-LM 内核锁定**: 所有分支均锁定 `Megatron = core_v0.12.1`,意味着底层 Megatron 实现版本被冻结,差异主要体现在配套框架版本。
6. **Triton-Ascend 与 CANN 强绑定**: 文档明确指出"**Triton-Ascend 版本与 CANN 版本强绑定,Triton-Ascend 的使用应该与 CANN 版本一一对应**"——CANN 9.1.0 ↔ Triton-Ascend 3.2.1,CANN 9.0.0 ↔ Triton-Ascend 3.2.1。
7. **Python 版本分化**: master 在研分支走 Python 3.12,而 26.0.0 / 26.1.0 正式分支仍为 Python 3.10。

## 【关键机制与数据】

- 原文: 26.1.0 的 MindSpeed Core 代码分支名为 **`26.1.0_core_r0.12.1`**,26.0.0 为 **`26.0.0_core_r0.12.1`**,Megatron 内核均为 `core_v0.12.1`。
- 原文: 26.1.0 配套 PyTorch **2.7.1**;master 在研分支已升级至 PyTorch **2.10.0** (体现 Python 3.12 的换代趋势)。
- 原文: TorchNPU 配套遵循"**跨向兼容**"策略,26.1.0 兼容 TorchNPU 7.3.0 / 26.0.0 / 26.1.0,**不兼容** 7.2.0;26.0.0 反向兼容 7.2.0 但**不兼容** 26.1.0。
- 原文: CANN 配套同理,26.1.0 兼容 CANN 8.5.0 / 9.0.0 / 9.1.0,**不兼容** 8.3.RC1;26.0.0 不兼容 CANN 9.1.0。
- 原文: 升级过程中"**会导致业务中断**",但"**对通信无影响**"。
- 原文: 文档对"删除特性 / 接口变更 / 已解决问题 / 遗留问题 / 漏洞修补"全部标注为"**无**",即本次为**纯增量发布**,无破坏性变更。
- 原文: 三款防病毒引擎(QiAnXin 8.0.5.5260、Kaspersky 12.0.0.6672、Bitdefender 7.5.1.200224)于 2026-07-06 完成扫描,结果均为"无病毒,无恶意"。

**逐行解读:**
- **master 行** 是面向下一代 PyTorch 2.10.0 + Python 3.12 的开发中分支,所有依赖暂标"在研版本",提供未来演进的方向锚点。
- **26.1.0 行** 为本次正式版本,锁定 PyTorch 2.7.1 / TorchNPU 26.1.0 / CANN 9.1.0 / Triton-Ascend 3.2.1 / Python 3.10。
- **26.0.0 行** 与 26.1.0 几乎一致,主要差别在 CANN(9.0.0 vs 9.1.0)与 TorchNPU(26.0.0 vs 26.1.0),即保持 CANN/TorchNPU 主版本号与 MindSpeed MM 主版本号对齐。
- 三行 Megatron 均为 `core_v0.12.1`,说明本次大模型训练底座**没有内核级升级**,新能力集中在 MindSpeed MM 自身。

### 表 2:MindSpeed MM 与 TorchNPU 版本兼容矩阵

| MindSpeed MM \ TorchNPU | 7.2.0 | 7.3.0 | 26.0.0 | 26.1.0 |

**逐行解读:**
- **26.1.0** 向前兼容 TorchNPU 7.3.0 / 26.0.0 / 26.1.0,完全放弃 7.2.0,体现版本跃迁——7.2.0 是昇腾较早版本,被新版本淘汰。
- **26.0.0** 覆盖到 7.2.0,但已不支持 26.1.0,可视为"旧版"的兼容窗口。
- "/Y"对角关系表明 **MindSpeed MM 主版本号 ↔ TorchNPU 主版本号** 是强对齐关系,跨主版本号(例如 26.0.0 跑 26.1.0 TorchNPU)不可配套。

- 26.0.0 兼容 8.3.RC1 / 8.5.0 / 9.0.0,但**不兼容** CANN 9.1.0,与 TorchNPU 表呈现完全镜像的兼容窗口,反映 **CANN 与 TorchNPU 同号同步演进**。

### 新增特性表

| 组件          | 描述       | 目的                                                                              |
| ------------- | ---------- | --------------------------------------------------------------------------------- |
| MindSpeed MM  | 新模型     | 支持 Qwen3.5, Kimi-K2.5                                                           |
| MindSpeed MM  | 新特性     | Qwen3.5、Kimi-K2.5 支持激活值异步卸载、chunk loss、chunk mbs                      |
| MindSpeed MM  | 新增硬件支持 | 支持 Ascend 950 系列产品                                                           |

**逐行解读:**
- **新模型行** 一次性扩展两个不同体系的 MoE/稠密多模态模型,扩宽应用场景。
- **新特性行** 的三项机制是**仅作用于新引入的 Qwen3.5 与 Kimi-K2.5**,并未声明对已有模型(例如 Wan2.1 / Qwen2.5-VL)的回溯支持——说明这些特性属于**新模型的配套训练范式**。
  - *激活值异步卸载*: 把前向计算中占用显存大的激活值异步搬到 Host/Device 之间,以释放 NPU HBM,支持更大 batch 或更长序列。
  - *chunk loss*: 把一个 micro-batch 内样本的 loss 按 chunk 切分,降低 loss 计算峰值显存。
  - *chunk mbs*: 把 micro-batch size 进一步分块调度,与 chunk loss 配合做显存优化。
- **新硬件行** 表示 Ascend 950 (推测为下一代昇腾训练芯片)正式被纳入支持列表,反映 26.1.0 是面向新一代硬件过渡的版本。

## 【关联】

- **与训练后端的关系**: 文档配套三份文档——`install_guide.md`(安装基础) → `quickstart.md`(Megatron 后端) → `quickstart_fsdp2.md`(FSDP2 后端),形成"安装-入门(并行范式 A)-入门(并行范式 B)"的串联结构。本次新增的 Qwen3.5 / Kimi-K2.5 及其 chunk loss / chunk mbs 等特性,目前在三份 quickstart 中尚无对应示例,**预计后续会在 Megatron 或 FSDP2 的 quickstart 中补充**。
- **与 MindSpeed Core 的耦合**: 配套表显示 26.1.0 锁定 `26.1.0_core_r0.12.1` 分支,说明 MindSpeed MM 的版本号与 MindSpeed Core 的 release tag 强绑定,任何训练任务依赖的是**两个仓的固定 commit/tag**而非浮动分支。
- **与 CANN/Triton-Ascend 的耦合**: 文档明确 Triton-Ascend 必须与 CANN 一一对应,所以表 3 的 CANN 兼容窗口**隐含决定了 Triton-Ascend 3.2.1 的可用边界**。
- **与 TorchNPU / CANN 版本演进节奏的关系**: 26.0.0 ↔ 26.0.0(CANN 9.0.0)、26.1.0 ↔ 26.1.0(CANN 9.1.0),表明 MindSpeed MM 与昇腾基础栈采用**主版本号同步**的发布策略。
- **与新增模型的关联**: 激活值异步卸载 / chunk loss / chunk mbs 三项特性**仅与 Qwen3.5 / Kimi-K2.5 绑定**,意味着其他模型暂未启用,可能因为这些模型参数规模更大、对显存压力更敏感,需要这些优化才能跑得起来。
- **与 Ascend 950 的关系**: "新增硬件支持 Ascend 950 系列产品"对应新一轮硬件迭代,通常意味着新版算子、显存布局或互联拓扑适配,**会同步对驱动固件版本提出要求**(虽然本文档未给出具体固件版本号)。
