# xLLM 硬件平台 Overview 文档深度解读

---

## 【定位】

这篇文档是 xLLM 推理引擎**多硬件后端支持的总索引页**，解决"用户面对六大国产/主流 AI 加速器该按什么统一路径部署 xLLM 服务"的问题，把各硬件的环境准备、容器镜像、运行时选择、服务启动和模型支持入口收口在同一章节下。

---

## 【技术要点】

1. **六类硬件后端并列支持**：原文列出 NVIDIA GPU、昇腾 NPU、寒武纪 MLU、海光 DCU、沐曦 MACA、摩尔线程 MUSA 共 6 个加速器平台，每个平台对应独立子页面（覆盖 CUDA、HCCL 等不同集合通信库与驱动栈）。
2. **统一四步通用流程**：原文以有序列表形式给出 (1) 按平台指南拉取/准备容器镜像 → (2) 容器内编译 xLLM 或使用含 `xllm` 的 release 镜像 → (3) 按 launch 文档选择设备后端启动服务 → (4) 在 supported_models 中核查模型与模态覆盖。
3. **容器化交付作为前提**：原文明确"根据各平台指南中的显式命令准备对应平台的容器镜像"，说明 xLLM 把容器作为跨硬件一致性的承载形态（驱动、固件、加速库统一在镜像内）。
4. **编译与预置镜像双轨**：第 2 步给出"在容器内编译 xLLM"和"直接使用已经包含 `xllm` 的 release 镜像"两条等价路径，覆盖需要自定义源码与开箱即用两种场景。
5. **运行时设备后端按平台切换**：第 3 步指向"对应平台的设备后端启动服务"，表明各硬件有专属后端抽象层（不是单一启动命令），具体设备选择由 launch 页面决定。
6. **模型与模态覆盖单独收敛**：第 4 步把"模型是否支持"独立于"硬件是否支持"进行二次校验，对应 supported_models 文档。

## 【关键机制与数据】

- **原文:** "根据各平台指南中的显式命令准备对应平台的容器镜像"——明确每种硬件有各自的官方/推荐镜像命令（命令细节在子页，本页未给出）。
- **原文:** "在容器内编译 xLLM，或直接使用已经包含 `xllm` 的 release 镜像"——交付形态包含"源码编译产物"和"预构建 release 镜像"两种。
- **原文:** "按 [启动 xllm] 中对应平台的设备后端启动服务"——启动阶段需要按硬件后端选择对应参数/命令（参数不在本页）。
- **原文:** "在 [模型支持列表] 中确认模型和模态覆盖情况"——验证步骤为"对照 supported_models 表格"（具体模型清单不在本页）。

> 本页无任何具体性能数据、吞吐量数字、显存占用或延迟指标，全部数据需进入各子页与 supported_models 查阅。

## 【使用方法】

原文以**流程步骤**而非完整命令形式给出使用方法，全部命令级细节需要进入子页：

1. **准备容器镜像**（原文）:"根据各平台指南中的显式命令准备对应平台的容器镜像"——具体命令见各 `/zh/hardware/<platform>/` 子页。
2. **获取可运行的 xLLM**（原文）:二选一
   - 在容器内编译 xLLM
   - 直接使用已经包含 `xllm` 的 release 镜像
3. **启动服务**（原文）:"按 [启动 xllm](/zh/getting_started/launch_xllm/) 中对应平台的设备后端启动服务"——具体设备后端参数在该页。
4. **验证模型支持**（原文）:"在 [模型支持列表](/zh/supported_models/) 中确认模型和模态覆盖情况"——具体清单在该页。

> 本页**未涉及**具体的 CLI 标志、环境变量名、端口号、显存/卡数配置——这些均下沉到 launch_xllm 与各硬件子页中定义。
