# 「算子设计文档模板」一体化深度解读

## 【定位】

本篇是一份**面向 TileLang（面向昇腾 NPU 的 Python 嵌入式 DSL）的算子设计文档骨架模板**，为单个昇腾算子从"数学描述 → 编程模式选型 → API 映射 → 内存规划 → Tiling → 调度 → 同步 → 验证 → 交付"的完整设计流程提供结构化填空框架，确保设计阶段就覆盖功能、性能、可验证性与风险等所有工程维度。

---

## 【技术要点】

1. **编程模式三选一**：必须从 Developer / Expert / 混合 三种模式中明确选定一种，并基于"是否含 matmul、是否含归约、是否需要流水线"四要素做选型论证（§2.2）。
2. **存储层级五段式**：模板显式列出 GM → L1 → L0A/L0B/L0C → UB 的完整搬运路径（§4.4），区分纯 Vector 路径与 Cube+Vector 路径。
3. **UB 容量硬约束**：模板以 131072 Bytes (128KB) 作为 UB 总预算上限（§4.5），所有 buffer 字节数加和需小于该值。
4. **对齐约束明确化**：模板给出"block_N=128, fp16 尾轴 128 > 16 ✓"示例，要求尾轴对齐 ≥16 字节（§5.3）。
5. **四级测试分层**：验证方案按 Level 0 最小 (32,32) → Level 1 典型 (1024,1024) → Level 2 边界 (1,1) → Level 3 性能 (8192,8192) 组织（§8.2）。
6. **精度标准预设**：float16 用 atol/rtol=1e-2，float32 用 atol/rtol=1e-4（§8.3）。
7. **交付顺序带勾选框**：模板以 ✅/⬜ 符号固化"设计文档 → Golden → 实现 → 基础测试 → 边界测试 → 性能测试"的 6 步实现顺序（§10.4）。

---

## 【关键机制与数据】

**工作原理 / 数据流（模板机制层面）：**

- **自上而下的设计流程**：从数学公式（§1.3）出发，先做公式拆解（§3.1）形成子表达式表，再映射为 TileLang API 表（§3.2），最终落到 `T.Kernel` 上下文内的 4 步伪代码："分配 buffer → T.copy 搬入 → 计算 → T.copy 搬出"（§3.3）。
- **双重约束校验机制**：在 §4.5 用 UB 总字节数做容量上限校验，在 §5.3 用对齐约束 + UB 容量 + L0 容量三个维度做 Tiling 可行性校验，形成双重门禁。
- **同步策略与 API 映射的耦合**：模板通过 §7.2 的同步点表格将"T.barrier_all 等待 DMA 搬运完成"等显式同步操作与 §3.2 的 API 调用形成位置对应关系。

**性能/规模数据（原文有的）：**

- UB 容量上限：**131072 Bytes (128KB)**（§4.5）。
- Tiling 示例块尺寸：**block_M = 128, block_N = 128**（§4.5、§5.3）。
- 单个 (128,128) float16 tile 大小：**32768 Bytes**（§4.5）。
- fp16 尾轴对齐阈值：**> 16 字节**（§5.3）。
- 测试用例代表规模：(32,32)、(1024,1024)、(1,1)、(8192,8194) 共 4 档（§8.2）。
- 动态轴运行时范围示例：**1 ~ 64K**（§4.6）。

## 【公式解读】

原文唯一显式出现的公式位置为 §1.3 的占位符：

$$
{数学公式}
$$

**逐字保留原式：**

```latex
{数学公式}
```

**符号与作用解读：** 此处为模板占位，无具体符号。模板本身约定的填写规范是：用一个 LaTeX 数学公式完整描述算子的数学定义（如 `C = A @ B` 或 `y = \text{softmax}(x)_i = \frac{e^{x_i}}{\sum_j e^{x_j}}`），该公式将作为后续 §3.1 公式拆解的唯一来源——所有子表达式分解都必须能从中推导得到。

此外模板在 §5.2 给出一个伪代码形式但数学含义明确的块划分公式：

```python
block_M = {值}  # {选择理由}
block_N = {值}  # {选择理由}
block_num = (M // block_M) * (N // block_N)
```

- **M, N**：输入张量的逻辑维度（原模板以矩阵为例）。
- **block_M, block_N**：沿 M、N 方向切分的单 block 尺寸，受 §5.3 的对齐/UB/L0 约束。
- **block_num**：总 block 数，由 `M // block_M * N // block_N` 计算——隐含假设 M、N 都能被 block 整除，非整除情况交由 §6.4 尾块处理解决。

## 【使用方法】

**启用方式：** 在算子开发项目目录下创建 `design.md`，按模板 10 节顺序逐节填空即可启用本设计流程。模板本身无独立启动命令。

**关键配置项 / 命令（原文有的）：**

1. **JIT 配置（§4.7）**：通过 `@tilelang.jit(out_idx=[...], pass_configs={...})` 装饰器声明输出索引与 pass 配置。
2. **动态轴声明（§4.6）**：使用 `T.dyn['K']` 语法声明动态轴，运行时范围需在表中填写（如 1 ~ 64K）。
3. **编程模式切换（§2）**：通过 `T.Kernel(..., is_npu=True)` 上下文选择 Developer / Expert / 混合模式。
4. **同步 API（§7.2）**：手动同步使用 `T.barrier_all()`，置于搬入后等关键点。
5. **缓冲区分配（§3.3）**：使用 `T.alloc_ub` 显式分配 UB buffer。
6. **流水线优化（§6.3）**：使用 `T.Pipelined` 控制 num_stages 与 buffer 管理。
7. **算子实现与测试文件路径（§10.1 / §10.3）**：实现文件 `examples/{算子名}/example_{算子名}.py`、设计文档 `design.md`、可选 README、可选测试 `test_{算子名}.py`（放入 `testing/`）。
8. **命名规范（§10.3）**：目录名与文件名统一使用 snake_case。

**原文未涉及：** CLI 启用命令、CI 集成入口、PR 模板等运维层面入口均未在文档中提及。
