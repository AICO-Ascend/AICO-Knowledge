## 【定位】

## 【技术要点】

1. **替换目标**：把 ATB 中 `{算子类型}` 算子替换为 ACLNN 算子，目标设备为 **昇腾 910B 和 950**，强调利用 NPU 硬件加速能力。
2. **接口兼容原则**：上层应用**无需修改代码**即可迁移——保持原有接口形态。
3. **性能预期**：原文声明"采用 ACLNN 算子后，{算子类型}算子的执行性能预计**提升 10%-30%**"，并指出通过硬件优化与内存局部性提升来实现。
4. **数据类型支持**：**float32、float16**；**Atlas 推理系列产品不支持 bf16**；量化场景下**部分算子支持 INT8**。
5. **实现模式**：继承现有 **`AclnnRunner` 基类**，必须覆写三个方法——`BuildAclnnVariantPack`、`SetAclNNWorkspaceExecutor`、`LaunchAclnnKernel`，并通过 `LoadMethod` 加载 ACLNN 函数指针，最后**注册 Runner 类型**。
6. **代码落位**：新增文件统一放在 `src/ops/ops_infer/{op_type}/{op_type}_aclnn_runner.h/cpp`。

---

## 【关键机制与数据】

- **替换后行为机制**：替换后将**优先使用 ACLNN {算子类型}算子**，原有 ATB 算子被废弃；通过接口兼容性保证上层无感。
- **数据流（基于模板描述）**：Runner 构造 → 加载 ACLNN 函数指针（`LoadMethod`）→ 构建变体包 `BuildAclnnVariantPack`（处理输入/输出张量，创建 ACLNN 张量对象）→ 设置工作空间与执行器 `SetAclNNWorkspaceExecutor`（调用 ACLNN 接口获取 workspace 大小）→ 启动内核 `LaunchAclnnKernel`（调用 ACLNN 执行计算）。
- **输入形状约束**：原文要求"所有输入输出 Tensor 的相关维度大小必须匹配"——属于硬约束。
- **性能数据**：原文仅给出 **10%-30% 性能提升预期区间**，未提供具体算子的实测 benchmark 数字。
- **依赖关系**：依赖 ACLNN 库版本、ATB 框架 Runner 机制、与量化模块的集成需额外适配。
