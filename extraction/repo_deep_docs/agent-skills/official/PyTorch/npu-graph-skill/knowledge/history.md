# 一体化深度解读：NPU 图模式知识库 (history.md)

## 【定位】

本文件是 NPU 图模式技能 (npu-graph-skill) 的**案例沉淀总账**——一份按"捕获/重放/内存/Update/编译/性能/知识问答/其他"八类分桶的 changelog 模板，用于在每次诊断或问答结束后由 Agent 提示用户是否记录，并按 `CASE_TEMPLATE.md` 格式自动追加案例，从而把零散的诊断经验沉淀为可复用的结构化知识库。

---

## 【技术要点】

1. **自动积累机制**：每次诊断与问答结束 → Agent 提示用户是否记录 → 用户确认后按 `CASE_TEMPLATE.md` 格式追加写入本文件（原文："Agent 在会话结束后提示用户是否记录，按 `CASE_TEMPLATE.md` 格式追加"）。
2. **八类故障分桶**：捕获失败、重放失败、OOM/内存、Update 失败、编译失败、性能问题、知识问答、其他——覆盖 NPU 图模式典型生命周期阶段。
3. **当前累计状态**：所有八个分类的"数量"列均为 **0**，合计 **0**——表示该知识库尚未收录任何实战案例，处于初始化阶段。
4. **占位文案统一**：八个"案例详情"小节均以同一句占位语 `暂无案例。诊断结束后选择记录，案例将追加于此。` 标注，明确说明空状态与触发填充的条件。
5. **依赖模板契约**：案例结构严格遵循同仓内的 `CASE_TEMPLATE.md`（原文未给出模板内部字段，属外部契约）。
6. **分阶段语义对齐**：案例分类与 NPU Graph 的运行时阶段一一对应——"捕获"对应图捕获阶段、"重放"对应 replay 执行阶段、"Update"对应图更新阶段——这意味着分桶不是随意标签，而是与算子生命周期绑定。

---

## 【关键机制与数据】

- **数据流（原文）**：诊断/问答会话 → 会话结束触发 Agent 提示 → 用户选择"记录" → 按 `CASE_TEMPLATE.md` 填充 → 追加到 `history.md` 对应分类下。
- **工作机制（原文）**：本文件本身**不存储诊断逻辑**，只作为"分类总览 + 案例详情"两层结构的**只追加 (append-only)** 沉淀层；写入入口由 Agent 在会话结束事件中驱动。
- **性能数据**：原文未涉及任何性能数据。
- **运行时序**：捕获阶段 → 重放阶段 → Update 阶段 / 编译阶段 / 内存阶段（贯穿）→ 性能问题（横切）→ 知识问答（横切）→ 其他（兜底）。
- **当前快照**：所有计数为 0，表示尚未发生任何被记录的诊断事件，或所有用户均尚未选择"记录"。
