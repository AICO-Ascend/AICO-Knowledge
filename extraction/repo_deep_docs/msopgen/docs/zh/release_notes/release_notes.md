## 【定位】

本文档是 **MindStudio Ops Generator (msOpGen)** 的版本说明 (changelog), 系统记录 msOpGen 两个发行版本 (26.0.0 内测版、8.3.0 正式版) 的产品版本配套关系、版本兼容性以及各版本下"新增/删除/Bugfix"三类变更, 为算子工程生成与仿真流水图生成工具的使用方提供版本对照依据。

---

## 【技术要点】

1. **两个版本并存发布**: msOpGen 26.0.0 (内测版本) 与 msOpGen 8.3.0 (正式版本) 同时收录于本说明中, 二者均无兼容性变更、无删除变更、无 Bugfix 变更。
2. **26.0.0 核心新增**: 适配 AscendC 算子新工程 (原文仅列出这一条新增项)。
3. **8.3.0 首次发布**: 新增三项能力 —— ① 基于算子原型定义输出算子工程; ② 基于性能仿真环境生成的 dump 数据文件, 输出算子仿真流水图文件; ③ 算子工程编译部署。
4. **CANN 版本配套要求**: 26.0.0 推荐 CANN 9.0.0 及以上; 8.3.0 推荐 CANN 8.2.RC1 及以上。
5. **Python 版本配套要求**: 两版本均推荐 Python 3.7 及以上。
6. **版本兼容性结论**: 原文明确"无兼容性变更", 即跨版本不存在接口/行为层面的破坏性变化。

---

## 【关键机制与数据】

按原文记录, 两个版本的工作原理/数据流可归纳为:

- **8.3.0 的算子工程生成链路 (原文)**:
  - 输入端: 算子原型定义 (operator prototype definition);
  - 输出端: 算子工程 (operator project)。
- **8.3.0 的仿真流水图生成链路 (原文)**:
  - 输入端: 性能仿真环境生成的 dump 数据文件;
  - 输出端: 算子仿真流水图文件。
- **8.3.0 的部署链路 (原文)**: 算子工程经编译后完成部署 (operator project compilation and deployment)。
- **26.0.0 的适配方向 (原文)**: 在 8.3.0 已具备的算子工程生成能力基础上, 进一步适配 AscendC 算子新工程。
- **性能数据**: 原文未涉及 (本文档仅记录功能变更, 不含性能数据)。

## 【表格解读】

原文共含两张表格, 逐字还原如下:

### 表 1: 产品版本信息

| 产品名称 | 产品版本  | 版本类型 |
|------|-------|------|
| msOpGen | 26.0.0 | 内测版本 |
| msOpGen | 8.3.0 | 正式版本 |

**逐行解读**:
- 第 1 行: 产品名 `msOpGen`, 版本号 `26.0.0`, 类型为"内测版本" —— 表明该版本尚处内部测试阶段, 通常对应较新的功能演进 (本文档中即适配 AscendC 新算子工程)。
- 第 2 行: 产品名 `msOpGen`, 版本号 `8.3.0`, 类型为"正式版本" —— 表明该版本是面向用户的稳定发行版, 同时也是 msOpGen 的"首次发布"版本 (见 8.3.0 章节描述)。

### 表 2: 相关产品版本配套说明

| msOpGen版本 | CANN版本 | Python版本 |
|----------|-----------------|----------|
| 26.0.0 | 推荐9.0.0及以上 | 推荐 Python 3.7及以上 |
| 8.3.0 | 8.2.RC1及以上 | 推荐 Python 3.7及以上 |

**逐行解读**:
- 第 1 行 (26.0.0): 由于 26.0.0 适配 AscendC 算子新工程, 因此对底层 CANN 提出了更高的最低版本要求 —— 推荐 CANN 9.0.0 及以上; Python 仍维持 3.7 及以上的推荐基线。
- 第 2 行 (8.3.0): 作为首次正式版本, 配套 CANN 8.2.RC1 及以上, 表明其面向的是 CANN 8.x 系列; Python 同样为 3.7 及以上。
- 横向对照: 两个版本对 Python 的要求一致 (3.7+), 差异集中在 CANN 版本上, 这与 26.0.0 引入 AscendC 新工程适配这一变更相吻合 —— 新的算子工程形态通常依赖更新版本的 CANN 算子栈。

> 注: 表格中 "CANN版本" 与 "Python版本" 列在原文使用同一列, 实际为三列内容 (msOpGen版本 / CANN版本 / Python版本), 此处按表头逐字还原。

## 【关联】

根据文档中显式提及的产品/模块信息, 梳理上下游与并行关系如下:

- **CANN (Compute Architecture for Neural Networks)**: msOpGen 的下游运行时依赖, 版本配套由表 2 约束。26.0.0 与 8.3.0 对 CANN 的最低版本要求不同, 反映出 msOpGen 与 CANN 算子栈的版本强绑定关系。
- **Python 环境**: 通用脚本/工程生成语言的运行环境依赖, 两个版本均要求 3.7+。
- **AscendC 算子框架**: 26.0.0 新增"适配 AscendC 算子新工程"特性, 说明 msOpGen 与 AscendC 算子编程模型存在适配耦合, 新版本需要承载 AscendC 新的工程结构。
- **算子原型定义 (operator prototype definition)**: 8.3.0 中算子工程生成的输入源, 是 msOpGen 上游的契约输入, 由调用方提供。
- **性能仿真环境及其 dump 数据文件**: 8.3.0 中仿真流水图的输入源, 表明 msOpGen 与"性能仿真环境"工具链存在数据交互 (读取 dump 文件)。
- **算子工程编译部署**: msOpGen 输出的工程进一步进入编译/部署流程, 该流程属于 msOpGen 的下游环节。
- **版本配套关系**: 26.0.0 (内测) 与 8.3.0 (正式) 在本文档中并列发布, 26.0.0 是 8.3.0 之后的演进版本, 二者共享 Python 3.7+ 的语言环境基线, 但 CANN 基线不同。
