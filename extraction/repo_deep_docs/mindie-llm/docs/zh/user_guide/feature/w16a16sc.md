# W16A16SC 稀疏量化文档深度解读

---

## 【定位】

本文档描述了 mindie-llm 引擎中 **W16A16SC 浮点稀疏压缩量化** 这一特性的端到端能力——从稀疏化算法原理、权重目录结构、压缩分片机制、量化张量 dtype/shape 规格，到基于 msModelSlim 工具链生成 W16A16SC 量化权重并完成 Qwen3-32B 推理执行的完整操作流程。

---

## 【技术要点】

1. **两步式量化流水线**：第一步 "稀疏" 通过模型稀疏工具按元素对最终精度的重要性排序，将影响小的权重置零，生成 W16A16S 中间产物；第二步 "压缩" 在多卡切分后的权重之上执行编码压缩，生成最终 W16A16SC 量化权重及索引文件。
2. **硬件与模型双重强约束**：原文 NOTE 明确——压缩算法与硬件强相关，**仅 Atlas 300I Duo 推理卡**支持浮点稀疏压缩量化；模型范围**仅支持 Qwen3-32B**。
3. **TP 切分一致性约束**：压缩阶段使用 `torchrun --nproc_per_node {TP数}` 执行多卡切分，原文要求"TP 数为张量并行个数，**需和权重运行时的张量并行个数保持一致**"。
4. **权重分片目录结构**：压缩后将权重切分为 `part0-of-4`～`part3-of-4` 共 **4 个 part 目录**，每个 part 内含 `quant_model_weight_w16a16sc.safetensors` 与 `quant_model_description.json`，体现"压缩前先加载权重并进行多卡切分"的实现。
5. **量化描述文件新增字段**：相比稀疏态 `W16A16S`，压缩态 `W16A16SC` 的 MatMul 权重在描述文件中新增三类条目——`xxx.index`（用于还原权重）、`xxx.info`（元信息）以及 `xxx.weight.outdim`（用于还原输出维度，原文示例 `c_attn.weight.outdim=2560`、`c_proj.weight.outdim=5120`）。
6. **量化张量规格定型**：表 1 锁定了 float16 原始权重量化后三个张量的 dtype——weight 转为 `int8`、quant_bias 为 `float32`、index 为 `int8`，并以"原始权重 shape 为 [n, k]"为前提给出压缩后 shape。

---

## 【关键机制与数据】

### 工作原理（原文叙述整合）

- **稀疏阶段**：以"逐元素精度影响判断"为核心，由模型稀疏工具扫描权重张量，把"对最终精度影响小的权重值置零"，保留的为 W16A16S 中间态。
- **压缩阶段**：先**加载稀疏权重**并**按张量并行维度进行多卡切分**（"压缩前会先加载权重，并进行多卡切分，压缩算法须在切分后的权重上执行"），再由权重压缩工具对切分后权重做编码压缩，输出 W16A16SC 量化权重与索引文件。
- **推理阶段**（图 1 所示量化权重推理流程）：推理时 MatMul 权重相比稀疏态新增了 `index`（用于还原权重）与 `outdim`（用于还原输出维度），二者配合完成从压缩表示到原始稠密张量的运行时还原。

### 数据流与产物规格（原文限定数字）

- 稀疏后：单目录、单一 `quant_model_weights.safetensors` 权重文件 + 单一 `quant_model_description.json` 描述文件，`model_quant_type = "W16A16S"`。
- 压缩后：分 4 个 part 目录，每 part 各持一份 `quant_model_weight_w16a16sc.safetensors` 与 `quant_model_description.json`，`model_quant_type = "W16A16SC"`。
- 描述文件中 `q_proj/k_proj/v_proj/o_proj`（稀疏态示例）与 `c_attn/c_proj`（压缩态示例）均为 W16A16SC 作用对象；`embed_tokens`、`q_norm`、`k_norm` 等保持 `FLOAT` 不被稀疏。

> 备注：原文未给出任何性能/吞吐/精度数字，仅给到权重 dtype、shape 规格，故本节不含性能数据。

## 【表格解读】

**原文表 1（逐字还原）：**

> **表 1**  float16 权重量化后 dtype 及 shape 信息（假设原始权重的 shape 为 [n, k]）

| Tensor 信息 | weight       | quant_bias | index                  |
|-------------|--------------|------------|------------------------|
| dtype       | int8         | float32    | int8                   |
| shape       | [x]<br>x 的取值范围由压缩率决定 | [n]       | [y] 存储非零元素的索引 |

**逐行解读：**

- **第 1 列 dtype = int8**：weight 张量被量化为 8 位整型。这是非零稀疏元素的核心存储形式，相对原始 float16，存储开销减半（不考虑稀疏元数据时）。
- **第 2 列 dtype = float32**：quant_bias 保持 float32，即**量化反算所需的偏置**仍以全精度保存（典型如逐通道零点/缩放因子的反向变换参数），用以在反量化时还原浮点尺度。
- **第 3 列 dtype = int8**：index 张量同样为 int8，用于存储非零元素的索引——即回答"weight 中第 i 个非零值原本位于稠密矩阵哪个位置"的问题。
- **shape [x]，"x 的取值范围由压缩率决定"**：压缩后 weight 张量的形状由压缩率决定（不是固定的 n×k），体现了稀疏压缩的非定长特性；x 仅指"压缩后非零元素的总数维度"，并非原始 n、k 的简单函数。
- **shape [n]**：quant_bias 与原始权重输出维度 n 对齐，对应**逐输出通道**的偏置结构，这是典型的 per-channel 量化布局。
- **shape [y]，"y 存储非零元素的索引"**：index 的长度 y 等于非零元素个数，表示压缩后共有 y 个有效非零权重及对应的 y 个位置索引，与 weight 的 [x] 在数量上保持一致（x = y）。

## 【使用方法】

### 前提条件（原文）

- 安装压缩工具 **msModelSlim**，安装步骤参见《msModelSlim 工具》的 "msModelSlim 安装" 章节（外部链接见【关联】）。

### 生成权重（原文，以 Qwen3-32B 为例）

1. **生成 W16A16S 浮点稀疏权重**：

    ```bash
    msmodelslim quant --model_path ${浮点权重路径} --save_path ${W16A16S量化权重保存路径} --device npu --model_type Qwen3-32B --quant_type w16a16s --trust_remote_code True
    ```

    - 原文提示："以上指令包含生成 Qwen3-32B W16A16S 浮点稀疏权重的最优参数配置。"

2. **设置 Python 库路径环境变量**（`{Python Lib Path}` 为安装 msmodelslim 时编译步骤所在的 Python 路径）：

    ```bash
    export LD_LIBRARY_PATH={Python Lib Path}/lib:$LD_LIBRARY_PATH
    ```

3. **压缩为 W16A16SC 量化权重**：

    ```bash
    torchrun --nproc_per_node {TP数} -m examples.convert.model_slim.sparse_compressor --model_path {W16A16S量化权重路径} --save_directory {W16A16SC量化权重路径}
    ```

    - 关键配置项：`--nproc_per_node {TP数}` 为张量并行个数，原文硬性约束"需和权重运行时的张量并行个数保持一致"。

### 执行推理（原文）

```bash
cd ${ATB_SPEED_HOME_PATH}
torchrun --nproc_per_node {TP数} -m examples.run_pa --model_path {W16A16SC量化权重路径}
```

- `--nproc_per_node {TP数}` 同样为张量并行个数，须与压缩阶段保持一致；演示对话内容为 "What's deep learning?"。

### 启用范围（原文限定）

- **硬件**：仅 Atlas 300I Duo 推理卡。
- **模型**：仅 Qwen3-32B。
- **量化类型标识**：稀疏态 `model_quant_type="W16A16S"`，压缩态 `model_quant_type="W16A16SC"`（在 `quant_model_description.json` 中读取并区分）。
