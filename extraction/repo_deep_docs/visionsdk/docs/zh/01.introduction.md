# Vision SDK 简介文档深度解读

## 【定位】

本篇文档是 Vision SDK 产品的总览性介绍（Overview），系统性地回答了"Vision SDK 是什么、为谁服务、采用怎样的软件架构、运行在哪些硬件与操作系统之上"这四个入门级核心问题，目的是为开发者建立产品认知地图，并引导其进入快速入门与具体开发流程的学习。

---

## 【技术要点】

1. **产品定位与归属**：Vision SDK 是 **MindSDK 中**面向图片和视频视觉分析的子 SDK，提供基础的视频、图像智能分析能力与编程框架。其关注的核心场景是 **IVA（Intelligent Video Analytics，智能视频分析）**，覆盖目标识别、视频结构化、动作行为识别等传统算法应用领域。

2. **两种开发方式**：
   - **API 接口方式**：提供原生推理 API + 算子加速库，适合有固定应用开发流程的用户，借 Vision SDK 的算法加速能力构建 CV 应用。
   - **流程编排方式**：采用模块化插件（Plugin）设计，业务流程中的功能单元被封装为独立插件，用户通过插件串接（pipeline）快速构建业务；同时支持插件自定义开发。

3. **核心产品价值（两条）**：
   - **降本增效**：将传统视频图像处理通过 **NPU 加速**，大幅度提升计算性能、降低成本。
   - **极简易用**：封装 NPU 算法加速能力，简化应用开发难度，目的是降低昇腾芯片开发的门槛。

4. **四层软件架构**（mxStream / mxPlugins / mxBase / mxTools）：
   - **mxStream**：业务流程 Stream 管理，含 StreamManager（Stream 构建/销毁、收发数据接口）与 StreamServer（基于 Vision SDK 的推理服务器，对外提供 **RESTful 接口**）。
   - **mxPlugins**：基础功能插件（数据源、数据处理、模型推理、模型后处理四类）。
   - **mxBase**：昇腾芯片功能基础库（图像解码、裁剪缩放、模型推理、算子加速），是 SDK 的底层基础。
   - **mxTools**：SDK 工具集合（插件开发 API、信息收集、卸载、单插件测试、插件信息收集）。

5. **支持硬件范围（按产品系列分组）**：覆盖三类产品系列——Atlas 200I/500 A2 推理产品、Atlas 推理系列产品、Atlas A2 推理系列产品；具体型号共 6 款：Atlas 500 A2 智能小站、Atlas 300I Pro 推理卡、Atlas 300I Duo 推理卡、Atlas 300V 视频解析卡、Atlas 300V Pro 视频解析卡、Atlas 200I SoC A1 核心板、Atlas 800I A2 推理服务器。

6. **操作系统支持要点**：**仅支持 64 位操作系统**；支持 EulerOS、Ubuntu、openEuler、CentOS、CTyunOS、KylinOS、UOS、BCLinux 等多款操作系统，具体版本因硬件型号而异。

## 【关键机制与数据】

- **原文：产品定义层级关系**——Vision SDK ⊂ MindSDK；Vision SDK 提供"智能分析能力 + 编程框架"两层封装。
- **原文：流程编排的工作机制**——"采用模块化的设计理念，将业务流程中的各个功能单元封装成独立的插件"，再"通过插件的串接快速构建业务"。
- **原文：StreamManager 接口能力**——负责 Stream 的**构建和销毁**，同时提供**向其发送数据和获取结果**的接口。
- **原文：StreamServer 对外形态**——"以 RESTful 接口对外提供视觉推理服务"，即以独立推理服务器形态部署。
- **原文：mxBase 子模块数据/算法能力**——图像处理基本运算（加、减、抠图、缩放、通道拼接、通道拆分）、模型推理与后处理、基础算法（NMS、仿射变换、匈牙利算法、卡尔曼滤波）、资源管理（初始化/去初始化、异步流程控制、设备管理、内存管理）、工具（日志、错误码、文件处理、字符串处理）。
- **原文：mxTools 子工具功能定位**——PluginToolkit（插件开发 API）、SdkInfoCollector（收集日志与资源占用，用于问题定位）、Uninstaller（卸载）、TestToolkit（单插件测试）、PluginInspector（环境中可用插件信息收集）。
- **原文：性能瓶颈与价值动机**——AI 图像算法基础的视频图像处理，"逐渐成为计算流程中的成本壁垒和性能瓶颈"，因此 Vision SDK 定位为算法加速 + 降低 CV 开发复杂度。

> 注：原文未给出具体的性能数据（如 FPS、时延、加速比等量化指标），亦未提供 NPU 型号、显存占用等硬件细节。

## 【表格解读】

### 表 1：架构图模块介绍（原文逐字还原）

| 模块 | 说明 |
|------|------|
| mxStream | 用于管理流程编排中的业务 Stream。<li>StreamManager：负责 Stream 的构建和销毁，同时提供向其发送数据和获取结果的接口。</li><li>StreamServer：基于 Vision SDK 实现的推理服务器，以 RESTful 接口对外提供视觉推理服务。</li> |
| mxPlugins | 基础功能插件，例如模型推理插件、模型后处理插件、视频编解码插件以及图像解码插件。为以流程编排方式进行快速构建应用提供基础能力。<li>MpDataSource：负责提供拉流，数据加载、数据序列化以及数据导出等功能。</li><li>MpDataProcess：负责提供数据处理，例如视频编解码，图像编解码，图像抠图、缩放、贴图以及旋转等功能。</li><li>MpModelInfer：负责提供模型推理相关功能。</li><li>MpPostProc：负责提供模型后处理相关功能。</li> |
| mxBase | 昇腾芯片功能基础库：包括图像解码、裁剪缩放、模型推理、算子加速库等。是 Vision SDK 的基础底座，开放部分 API 供用户进行自定义应用开发。<li>MbCV：负责提供图像处理相关的常用基本功能，如加、减、抠图、缩放、通道拼接、通道拆分等。</li><li>ModelInfer：负责提供模型推理以及模型后处理相关功能。</li><li>Basic algorithm：负责提供 NMS，仿射变换，匈牙利算法以及卡尔曼滤波算法等功能。</li><li>Resource Manager：负责提供资源初始化、资源去初始化、异步流程控制、设备管理、内存管理等</li><li>Utils：负责提供日志模块、错误码、文件处理、字符串处理等相关功能。</li> |
| mxTools | 提供 SDK 相关工具。</li><li>PluginToolkit：用于插件开发的 API。</li><li>SdkInfoCollector：一键式信息收集工具。主要收集 Vision SDK 日志和昇腾芯片日志，资源占用率等，用于问题定位。</li><li>Uninstaller：Vision SDK 卸载工具。</li><li>TestToolkit：单插件测试工具。</li><li>PluginInspector：插件信息收集工具。收集环境中可用插件的信息。</li> |

**逐行解读**：

- **mxStream**：聚焦于"流程编排中的 Stream 管理"——StreamManager 是**控制平面**（生命周期 + 数据出入口），StreamServer 是**服务化平面**（以 RESTful 暴露推理服务）。两者分工意味着 Vision SDK 既支持进程内编排，也支持独立部署为推理服务器。
- **mxPlugins**：覆盖推理流水线的四大功能段——**数据接入（Source）→ 数据处理（Process）→ 模型推理（Infer）→ 模型后处理（PostProc）**，正好对应典型视觉推理 pipeline 的四个阶段。MpDataProcess 列举的具体能力（视频/图像编解码、抠图、缩放、贴图、旋转）说明 Vision SDK 内置了较完整的图像预处理能力。
- **mxBase**：定位为"基础底座"，核心特征是"**开放部分 API 供用户进行自定义应用开发**"——这是用户自定义能力的入口。MbCV 提供原子级图像操作；ModelInfer 是模型推理主入口；Basic algorithm 给出检测/跟踪常用算法（NMS、仿射变换、匈牙利、卡尔曼滤波，常用于目标跟踪场景）；Resource Manager 管理 NPU 设备与内存；Utils 是通用工具集。
- **mxTools**：是开发与运维支撑工具——PluginToolkit 用于插件开发、SdkInfoCollector 用于故障定位、TestToolkit 用于单插件调试、PluginInspector 用于环境探查。这一层构成了完整的开发-测试-部署-运维闭环。

**逐行解读**：

- **Atlas 200I/500 A2 推理产品（Atlas 500 A2 智能小站）**：支持 4 款 OS，是边缘/小站类设备，覆盖欧拉系（EulerOS、openEuler）与 Ubuntu 系。
- **Atlas 推理系列产品（PCle 卡 / 核心板）**：
  - **Atlas 300I Pro** 与 **Atlas 300I Duo** OS 列表高度相似（都覆盖 Ubuntu 18.04/22.04/24.04、CentOS 7.6、各版本欧拉、CTyunOS、KylinOS），区别在于 **Duo 多支持 BCLinux 21.10**，**Pro 多支持 EulerOS 2.15**。可见 Duo 是 Pro 的升级/扩展版本。
  - **Atlas 300V 视频解析卡**：OS 列表明显**精简**（仅 4 项：Ubuntu 18.04.1/18.04.5、CentOS 7.6、EulerOS 2.12），不开放较新的 Ubuntu 22.04/24.04 与 openEuler 24.03，可能与其视频解析专用硬件定位及生命周期相关。
  - **Atlas 300V Pro**：恢复完整 OS 支持，**独家支持 UOS V20**（国产统信操作系统），针对国产化场景。
  - **Atlas 200I SoC A1 核心板**：仅支持 2 款 OS（CentOS 7.6、EulerOS 2.12），是 ARM SoC 嵌入式板卡，最精简的 OS 矩阵。
- **Atlas A2 推理系列产品（Atlas 800I A2 推理服务器）**：作为最新一代推理服务器，OS 矩阵较新（Ubuntu 22.04/24.04 LTS、openEuler 24.03、BCLinux 21.10 U4、KylinOS 系列），不向下兼容 Ubuntu 18.04 或 CentOS 7.6。

**通用观察**：所有产品系列均**仅支持 64 位操作系统**（原文显式标注）；Ubuntu、openEuler、EulerOS 是覆盖率最高的三个 OS 家族；KylinOS（麒麟）从 V10 SP3 2403 起出现在多个产品中，体现国产化适配趋势；Atlas 300V 是 OS 支持矩阵中明显**最受限**的一款。
