# b12x Linear and MoE Backends — 深度解读

## 【定位】
本篇文档描述 vLLM 如何通过 [b12x](https://pypi.org/project/b12x/) 提供的可选 CUDA kernel, 在 NVIDIA SM120/SM121 GPU 上为 Linear (线性层) 与 MoE (混合专家) 计算启用低精度 (FP4 / FP8) 量化加速, 并给出后端选择方式、量化格式组合与不支持的限制清单。

---

## 【技术要点】

1. **后端本质**: b12x 是一个独立的 PyPI 包, 提供针对 NVIDIA SM120 / SM121 GPU 的可选 CUDA kernel, 在 vLLM 中作为可插拔的 Linear / MoE 后端存在。
2. **安装方式**: 通过 vLLM 提供的 extra 一次性安装 — `uv pip install "vllm[b12x]"`。
3. **自动选择优先级**: b12x linear kernel 处于「已建立的优化后端之后、emulation (模拟) 之前」, 即非显式指定时由 vLLM 的自动选择机制按此顺序纳入候选。
4. **显式选择命令**:
   - 仅 Linear: `vllm serve <model> --linear-backend b12x`
   - 仅 MoE: `vllm serve <model> --moe-backend b12x`
   - 两个后端可独立选择。
5. **MoE 适用条件**: `--moe-backend b12x` **仅**对兼容的 **NVFP4** 或 **MXFP4** MoE 模型生效。
6. **激活 (activation) 格式默认行为**:
   - **MXFP4 MoE**: 默认使用 **MXFP8** 激活。
   - **NVFP4 MoE**: 使用 **checkpoint 自带的激活格式**。
   - MXFP4 在其 A8 路径不支持当前模型配置时, 回退到 **BF16**。
7. **强制 A16 开关**: 环境变量 `VLLM_B12X_MOE_FP4_FORCE_A16=1`, 对任意 FP4 权重格式 (MXFP4 / NVFP4) 的 MoE 强制使用 **BF16 (A16)** 激活。
8. **不支持的范围 (MoE)**: 不支持 expert parallelism、expert maps、**EXL3**、**NF3**。
9. **不支持的范围 (Linear / Dense)**: Dense **W4A16** 层不由 b12x 处理, 回退到其他兼容后端 (如 **Marlin**)。

---

## 【关键机制与数据】

- **硬件目标 (原文)**: NVIDIA SM120 与 SM121 GPU。
- **后端选择链 (原文)**: b12x linear kernel 位于自动选择流程中 — 「after established optimized backends and before emulation」, 即优先级介于已优化的成熟后端与 emulation 模拟路径之间。
- **MoE 激活路径决策逻辑 (原文)**:
  1. 若模型是 MXFP4 MoE → 默认尝试 A8 路径 (MXFP8 激活)。
  2. 若 MXFP4 的 A8 路径不支持该配置 → 自动回退 BF16。
  3. 若模型是 NVFP4 MoE → 沿用 checkpoint 自带的激活格式 (BF16 / NVFP4 / MXFP8 三者之一)。
  4. 环境变量 `VLLM_B12X_MOE_FP4_FORCE_A16=1` 可覆盖 (1)(2)(3), 强制 BF16 激活。
- **Linear / MoE 解耦 (原文)**: 文档明确「linear and MoE backends can be selected independently」, 即两者选择互不强制。
- **数据流方向 (基于文档推断)**: 用户通过 `vllm serve` 命令行参数传入 backend 选择, 运行时按所选 backend 调度 b12x CUDA kernel 完成 Linear / MoE 算子的前向计算; 激活精度由"权重格式 + 是否显式 force A16"共同决定。
- **性能数据**: 原文未提供任何 benchmark 数字、吞吐、时延或加速比数据。

## 【表格解读】

### 原文表格 (逐字还原)

| Backend | Supported configurations |
| ------- | ------------------------ |
| Linear | Per-tensor FP8, 128x128 block FP8, MXFP8, NVFP4, and MXFP4 |
| MoE    | Tensor-parallel MXFP4 weights with BF16 or MXFP8 activations; NVFP4 weights with BF16, NVFP4, or MXFP8 activations |

### 逐行解读

- **Linear 行**
  - 支持 5 种权重量化格式:
    1. **Per-tensor FP8** — 整张张量共享一份 FP8 缩放因子, 粒度最粗。
    2. **128×128 block FP8** — 以 128×128 块为粒度做 FP8 量化, 是 vLLM 现有 FP8 路径中常见的细粒度方案。
    3. **MXFP8** — Microscaling FP8, 同样是按块/微缩放因子量化。
    4. **NVFP4** — NVIDIA 4-bit 浮点格式。
    5. **MXFP4** — Microscaling FP4 格式。
  - 含义: b12x 在 Linear (dense) 层覆盖从 FP8 整张量量化到 MX/NV 系 FP4 的多种精度方案。

- **MoE 行**
  - **MXFP4 权重**路径: 仅支持 **Tensor-parallel** (TP) 切分, 激活可选 **BF16** 或 **MXFP8**。
  - **NVFP4 权重**路径: 激活可与权重同精度 (**NVFP4**), 也可降级为 **BF16** 或升级为更宽的 **MXFP8**。
  - 与 Linear 行对比: MoE 不列出 per-tensor FP8 与 128×128 block FP8, 说明 b12x 的 MoE 算子只针对 FP4 (MX/NV) 这类低精度 + 必要激活精度的组合优化。

- **表格的隐含边界**:
  - Linear 支持的格式集合 ⊋ MoE 支持的格式集合。
  - MoE 必须配合 TP 使用, 不支持 EP (表格外的限制文字明确)。
  - 激活精度的可选集合 (BF16 / MXFP8 / NVFP4) 与"权重格式 + 是否 force A16"由上文环境变量控制。

## 【使用方法】

### 1. 安装依赖 (原文)

```bash
uv pip install "vllm[b12x]"
```

### 2. 显式选择后端 (原文)

仅启用 Linear 后端:

```bash
vllm serve <model> --linear-backend b12x
```

仅启用 MoE 后端 (仅适用于 NVFP4 或 MXFP4 MoE 模型):

```bash
vllm serve <model> --moe-backend b12x
```

两个同时启用 (可独立选择, 互不依赖):

```bash
vllm serve <model> \
    --linear-backend b12x \
    --moe-backend b12x
```

### 3. 激活精度强制为 BF16 (原文)

```bash
export VLLM_B12X_MOE_FP4_FORCE_A16=1
```

- 适用范围: 任何 FP4 权重格式的 MoE (MXFP4 或 NVFP4)。
- 作用: 无论 checkpoint 自带何种激活格式、或 A8 路径是否可用, 一律走 BF16 激活。

### 4. 隐式 (自动) 选择 (原文)

不传 `--linear-backend` / `--moe-backend` 时, b12x 也会进入自动选择候选池, 但优先级排在「established optimized backends」之后、「emulation」之前。

### 5. 已知不支持的组合 (原文)

- Dense **W4A16** Linear → b12x 不处理, 需选择其他后端 (如 Marlin)。
- MoE 上使用 **expert parallelism / expert maps / EXL3 / NF3** → b12x MoE 后端不支持。

> 备注: 原文未提供性能调优、batch size 推荐、GPU 内存占用或并发配置等高级参数, 以上即原文所覆盖的全部启用与配置项。
