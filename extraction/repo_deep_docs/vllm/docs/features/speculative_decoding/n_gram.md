## 【定位】
本文档解决"如何在 vLLM 中启用基于 prompt 内 n-gram 匹配的推测式解码 (speculative decoding)"的配置问题,描述了 vLLM 通过复用 prompt 中已有的 n-gram 模式来生成候选 token、进而加速自回归推理的能力。

---

## 【技术要点】
核心机制分条如下(均基于原文代码与文字):

1. **机制定位**:Speculative decoding 中,**proposals(候选 token 序列)由 prompt 内的 n-gram 匹配产生**,而非由独立的 draft 模型产生。原文:"speculative decoding where proposals are generated by matching n-grams in the prompt"。
2. **方法标识**:`speculative_config["method"] = "ngram"` —— 通过字符串 `"ngram"` 选择该推测方法。
3. **候选长度控制**:`num_speculative_tokens = 5` —— 每次推测解码步骤中,期望/允许生成并校验的候选 token 数量为 5。
4. **查找窗口长度**:`prompt_lookup_max = 4` —— 在 prompt 中向后查找匹配 n-gram 的最大回溯长度(窗口)为 4(原文未给出"长度单位 = token 还是字符"的进一步说明,只能如实标注为"原文未说明具体单位")。
5. **运行环境**:示例使用单 GPU(`tensor_parallel_size=1`),模型为 `Qwen/Qwen3-8B`,采样参数 `temperature=0.8, top_p=0.95`。
6. **参考实现/思想来源**:指向 João Gante 的 X 线程 `https://x.com/joao_gante/status/1747322413006643259`,即 prompt-lookup decoding 的原始出处(原文仅给链接,未在正文中复述该线程内容)。

## 【关键机制与数据】
**工作原理**(基于原文可推断的部分):
- 用户在 `LLM(...)` 构造时通过 `speculative_config` 字典声明使用 n-gram 推测方法。
- 推理过程中,vLLM 不是用一个小型 draft 模型去预测后续 token,而是直接在 **当前 prompt(含已生成部分) 中向后搜索匹配的 n-gram 序列**,把匹配到的后续若干 token 作为 draft proposal 交给主模型一次性校验/接收。
- 校验后保留(commit)接受的 token,reject 的 token 按主模型分布回退并重新采样。

## 【使用方法】
启用方式(原文代码块逐字提取,无任何外推):

**Step 1 — 导入:**
```python
from vllm import LLM, SamplingParams
```

**Step 2 — 准备 prompt 与采样参数:**
```python
prompts = ["The future of AI is"]
sampling_params = SamplingParams(temperature=0.8, top_p=0.95)
```

**Step 3 — 在 `LLM(...)` 构造时传入 `speculative_config`:**
```python
llm = LLM(
    model="Qwen/Qwen3-8B",
    tensor_parallel_size=1,
    speculative_config={
        "method": "ngram",
        "num_speculative_tokens": 5,
        "prompt_lookup_max": 4,
    },
)
```

**Step 4 — 调用 `generate` 并读取结果:**
```python
outputs = llm.generate(prompts, sampling_params)

for output in outputs:
    prompt = output.prompt
    generated_text = output.outputs[0].text
    print(f"Prompt: {prompt!r}, Generated text: {generated_text!r}")
```
