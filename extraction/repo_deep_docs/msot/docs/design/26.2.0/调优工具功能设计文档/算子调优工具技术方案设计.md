# MindStudio Ops Profiler 功能设计说明书 — 一体化深度解读

---

## 【定位】

这篇文档是 **MindStudio Ops Profiler（msopprof）算子调优工具的功能设计说明书**，明确"算子调优工具"的两大场景（仿真调优 / 上板调优）、业务用例清单（含 dfx 能力与约束）、以及以"上板指令流水图"和"warp 耗时展示"为代表的关键方案设计，作为编码、测试阶段的输入与指导。

---

## 【技术要点】

1. **两类调优场景**：算子**仿真**（运行在昇腾仿真器上，输出指令级流水图、代码热点图等详细性能数据）与算子**上板**（运行在真实昇腾设备上，反映硬件真实性能，是最可靠的性能数据）。
2. **A5 vs A2/A3 代际差异**：A5 代际硬件提供 `dfx_region` 功能，可在 pipe 上打点获取准确执行时间；A2/A3 代际只有 scalar 打点 —— 因此"上板指令流水图"仅 A5 提供，工具需对未提供此能力的代际做约束声明。
3. **dfx_region 插桩机制**：编译器在计算类、搬运类指令前后植入 `dfx_region` 桩，并返回 `region_id ↔ pc` 对应关系；硬件在算子运行结束返回原始执行时间；工具解析后调用 `llvm-symbolizer` 完成调用栈的生成与展示。
4. **warp 耗时展示机制**：编译器在 simt vf 的**开始与结尾**插入桩（BEGIN_STUB / END_STUB），运行时读取 `warp_id` 与 `readCycle()` 时间戳，写入 GM（Warp Record Table），工具解析侧读取后绘入流水图。
5. **代码热点图双模式对比**：`msprof op`（上板）与 `msprof op simulator`（仿真）在寄存器查看、UB Bank 冲突、Vector 利用率、cycle 级耗时等方面互为补充 —— 仿真能拿到寄存器/UB/Vector 细节，上板能拿到真实 L2Cache 命中率与 Process Bytes。
6. **工具配套约束**："上板流水图"与"warp 耗时展示"均**依赖编译器**（即工具必须与 CANN 版本配套）；硬件返回的流水数据若存在信息丢失，工具需向用户提醒。

## 【关键机制与数据】

### ① 上板指令流水图的工作流（原文 §3.1.1.1）

四阶段流水线：

| 阶段 | 角色 | 关键动作 | 时序 |
|---|---|---|---|
| 前置插桩 | 编译器 | 对程序执行 `dfx_region` 插桩，返回 `region_id ↔ pc` 对应关系 | 算子下发**之前** |
| 运行算子 | 工具（基础组件） | 拉起已插桩的程序，程序运行时自动产出数据 | 运行插桩生效后的算子 |
| 数据返回 | 硬件 | 接收原始数据 → 格式化处理 → 返回给 C | 算子结束后触发 |
| 最终展示 | 工具（解析侧） | 获取格式化数据并完成展示（含调用栈） | 最后一步 |

> 原文："A5 代际下硬件提供 dfx_region 功能，可在对应的 pipe 上打点（而非 A2/A3 代际的 scalar 打点）获取准确的执行时间"。

### ② warp 耗时展示的工作流（原文 §3.1.1.2）

- 默认在流水图中显示每个 warp 的开始时间和终止时间。
- 编译器在 simt vf 的开始与结尾提供插桩功能。
- 桩中功能：记录当前 warp 信息 + 时刻信息 → 运行时动态写入 GM。
- 工具解析侧：从 GM 读取每条 Warp Record → 计算耗时 → 绘入"当前代码流水图界面"。

### ③ 数据流示例（Warp Record Table 原文样例）

| Warp ID | Start Timestamp | End Timestamp |
|---|---|---|
| 0 | 1000 | 2500 |
| 1 | 1100 | 2600 |
| 2 | 1020 | 2520 |

> 原文：该表直接出现在 ASCII 流程图内作为"硬件 → GM"的数据落盘示例。

**逐行解读**：
- "上板调优"为主，"仿真调优"为辅 —— 仅"指令流水图（仿真）"与"搬运带宽图"专属仿真；"算子代码热点图"与"Ctrl+C 功能"为唯一跨场景项。
- "Roofline 瓶颈分析图"与"计算内存热力图"是建模型分析：前者给出理论极限，后者给出资源维度负载画像。
- "性能数据文件"是离散的指标聚合（指令耗时、L2 命中率、内存带宽、L0/UB 带宽率、计算/搬运占比、资源冲突占比），是其他可视化功能的数据底座。
- dfx 三项均为辅助控制流能力（中断 / 终止 / 版本选择），不参与性能数据生产。

**逐行解读**：
- **仅仿真支持**（共 5 项）：Gpr Count、UB Bank 冲突、Vector 利用率、cycle 级耗时、core 信息 —— 说明仿真能拿到更细粒度的微架构/寄存器/单元级数据。
- **仅上板支持**（仅 1 项）：模拟代码行 + 指令维度的 L2Cache 命中率 —— 反映真实硬件 Cache 行为，仿真器难以复现。
- **两端均支持**（共 4 项）：Process Bytes、执行次数、源码↔指令映射、源码/PC/Pipe/Source —— 通用数据通路能力。
- 选型建议：需 cycle 级细节 / 寄存器视角 / 单元利用率 → 仿真；需真实 Cache 命中率 → 上板。

## 【公式解读】

> 原文无严格数学公式，但 **§3.1.1.2 warp 耗时展示** 给出了一段伪代码形式的插桩机制 —— 逐字保留原式如下：

```
BEGIN_STUB:
    warp_id = getWarpId();
    start_ts = readCycle();
    storeToGM(warp_id, start_ts);   // 写入 Global Memory
SIMT_VF_BEGIN:
    // 原始计算逻辑
SIMT_VF_END:
END_STUB:
    warp_id = getWarpId();
    end_ts = readCycle();
    storeToGM(warp_id, end_ts);
```

**符号含义与作用**：
- `BEGIN_STUB` / `END_STUB`：编译器插桩位置（分别在 simt vf 起始与结尾），由"插桩工具（Instrumentation）"自动识别 SIMT VF 区域边界后注入。
- `SIMT_VF_BEGIN` / `SIMT_VF_END`：用户算子的原始 simt vf 代码段边界。
- `getWarpId()`：获取当前 warp 标识。
- `readCycle()`：读取硬件 cycle 计数器，作为时间戳来源。
- `storeToGM(warp_id, ts)`：将 (warp_id, timestamp) 写入 Global Memory。
- `// 写入 Global Memory`：注释，明确数据落盘位置为 GM。
- 配对的 `BEGIN/END_STUB` 写入的 `(warp_id, start_ts)` 与 `(warp_id, end_ts)` 在 GM 中构成 Warp Record Table（见前文样例），工具解析侧据此计算每 warp 的执行时长并绘入流水图。

## 【关联】

文末内部链接标注为"(无)"，故以下关联基于正文上下文梳理：

1. **两大场景的互补关系**：算子仿真与算子上板并非互斥 —— 同一功能（如代码热点图）支持双场景，但呈现的能力面不同（详见表 2 的 6 行差异）。
2. **指令流水图的两条路径**：仿真侧（§2 业务功能第 5 行）与上板侧（§2 业务功能第 9 行）同名但代际/数据源不同 —— 仿真基于仿真器，上板依赖 A5 代际 + `dfx_region` + 编译器插桩。
3. **工具 ↔ 编译器（CANN）耦合**：上板流水图、warp 耗时展示均显式声明"依赖编译器，要求工具与编译器(cann)版本配套"（§2 约束说明 1.c、2.a）。
4. **工具 ↔ 硬件代际耦合**：A5 提供 `dfx_region` pipe 打点，A2/A3 仅 scalar 打点（A2/A3 **未提供**上板流水图能力）。
5. **工具 ↔ llvm-symbolizer**：上板流水图最终展示阶段（§3.1.1.1 表第 4 行）调用 `llvm-symbolizer` 完成调用栈的生成，工具解析侧是其下游消费者。
6. **dfx 功能对调优主流程的支撑**：Ctrl+C / 提前终止进程 / 指定仿真器版本 是控制面能力，不产出性能数据，但保障算子在异常/长耗时场景下的可终止性与版本一致性。
7. **上游 Issue**：[#129](https://gitcode.com/Ascend/msopprof/issues/129) —— 设计变更的来源与评审入口。
