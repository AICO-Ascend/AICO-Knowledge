# MindStudio Sanitizer 功能设计文档 · 一体化深度解读

## 【定位】

本文档描述昇腾芯片调试工具 **mssanitizer（MindStudio Sanitizer）** 在新版本中计划新增/增强的五项检测能力——**纯 SIMT 算子异常检测、CATLASS DSL 算子异常检测、ops-transformer 算子仓误报率收敛、非默认值 mask 寄存器的 vector 指令展示、DCCI 一致性指令漏插检测**——并规定其目标、方案、接口与验收方法,服务于 mssanitizer 2026 Q3 Roadmap（Issue #177）。

---

## 【技术要点】

1. **纯 SIMT 算子检测**：通过劫持 pure simt 算子下发的特殊 runtime 接口识别 kernel,在 SIMT 指令上做动态插桩,把各线程的内存访问/同步记录并入既有检测框架；覆盖越界、非对齐、线程间踩踏、线程间竞争、读未初始化内存、SIMT 内 `sync_thread` 同步共 6 类异常。
2. **CATLASS DSL 算子检测**：在 CATLASS DSL 编译链路中接入插桩,把指令记录纳入既有检测框架；覆盖越界、非对齐、线程间踩踏、线程间竞争、读未初始化内存、同步异常。
3. **ops-transformer 算子仓准确率**：以 **RP2 release 版本**为基线,用算子仓自带用例做单算子全量扫描,做根因分析(算法逻辑缺陷/插桩方式/合法编程模式覆盖不全)并回归,**目标误报率 < 5%**。
4. **非默认值 mask 寄存器展示**：在指令分析阶段跟踪 vector mask 寄存器(normal/counter 两种模式)的写入与读取,当某条 vector 指令执行时 mask 处于非默认值,即展示该 vector 指令及对应的 mask 模式与值；通过子命令按需开启。
5. **DCCI 漏插检测**：采用指令序列模式匹配——"SetValue(addr) 下一条指令是否紧跟 DCCI(addr)" 以及 "GetValue(addr) 上一条指令是否紧跟 DCCI(addr)"；命令行参数 **`--dcci-check <yes/no>`**,**默认 `no`**；仅对 scalar 上的 DCCI 进行检测,A5 场景与 A2/A3 保持一致。
6. **基础检测算法**：内存检测算法参考 **valgrind**,采用 **shadow memory** 维护内存状态;mssanitizer 通过命令行 CLI 提供,无新增 API,直接使用 CANN 开发环境。

---

## 【关键机制与数据】

- **整体数据流**(纯 SIMT / CATLASS DSL 共用范式):kernel 下发 → 接口劫持 / 编译链路插桩 → 记录 SIMT 线程内存访问与同步行为 → 纳入既有检测框架(shadow memory 维护内存状态,valgrind 思路)→ 输出异常结果。
- **DCCI 检测三组核心序列模式**(原文 §2.5):
  1. 核 A:`SetValue` + `DCCI` ;核 B:`DCCI` + `GetValue`
  2. 核 A:`MTE3` ;核 B:`DCCI` + `GetValue`
  3. 核 A:`SetValue` + `DCCI` ;核 B:`MTE2`
  - 缺失 DCCI 时工具应可检出。
- **关键性能/质量指标**(原文):ops-transformer 全量扫描**目标误报率 < 5%**;以 RP2 release 为回归基线。
- **既有用例/验收平台**(原文 §4.2):
  - 算子类型:mix / cube / vec / simt
  - 编程语言:AscendC / Triton / CATLASS / SHMEM
  - 调起方式:`<<<>>>` / ACLNN / PTA
  - 款型:A2 / A3 / A5 / 950
  - 寄存器 mask 验收平台:A2/A3;DCCI 验收平台:A2/A3/A5;ops-transformer 准确率验收平台:**Ascend950**;CATLASS DSL 用例:原文未明确独立验收平台。

## 【关联】

- **上游/治理**:本设计对应仓库 **mssanitizer** 的 Roadmap 与治理 Issue——[MindStudio-Sanitizer Roadmap 2026 Q3 (issue #177)](https://gitcode.com/Ascend/mssanitizer/issues/177),同时 "相关 Issue/PR" 字段直接引用 `[177](https://gitcode.com/Ascend/mssanitizer/issues/177)` 作为本设计的入口。
- **运行环境依赖**:mssanitizer 直接使用 **CANN** 开发环境(无新增 API,通过 CLI 提供);其基础内存检测算法参考 **valgrind**(采用 shadow memory)。
- **编程语言/算子模型生态**:
  - **AscendC**(既有 SIMD 算子模型,提供 SIMT/pure simt 编写能力,本设计通过 runtime 劫持 + 动态插桩与之协同)
  - **CATLASS DSL**(新编程语言,本设计在 CATLASS DSL 编译链路接入插桩)
  - **Triton / SHMEM**(出现在端到端测试覆盖矩阵中,与本设计并行支持)
  - **ops-transformer 算子仓**(开源算子仓,作为误报率收敛的扫描基线,基线版本 RP2 release)
- **跨章节特性耦合**:
  - 纯 SIMT 检测 ↔ 既有检测算法(越界/非对齐/线程间踩踏/竞争/读未初始化内存):复用关系,无冲突。
  - CATLASS DSL 检测 ↔ 既有检测算法:复用,功能覆盖与 AscendC 保持一致。
  - mask 寄存器检测 ↔ DCCI 检测:二者均为指令级分析,但 DCCI 仅针对 scalar 上的 DCCI;mask 检测针对 vector mask(normal/counter),二者作用域不同。
  - 五项能力均标注"作为额外选项启用,与原检测能力不冲突",体现"叠加式"扩展而非替代式重构。

## 【使用方法】

- **工具调用形态**(原文 §3.4.1):mssanitizer 通过 **命令行 CLI** 提供,**未新增 API**,开发环境直接使用 CANN 环境。
- **寄存器检测(mask 展示)**(原文 §3.4.2.1):
  - 启用方式:使用 **子命令** 开启 mask 寄存器检测功能。
  - 默认行为:不影响默认检测流程(按需开启)。
- **DCCI 检测**(原文 §3.4.2.2):
  - 命令行参数:`--dcci-check <yes/no>`
  - 默认值:`no`(默认关闭)
- **既有参数影响**(原文 §3.4.3):以上新增参数**均不影响原有参数使用**,可与既有检测选项并存。
- **典型使用流程**(由原文 §2 推断,非原文直接给出命令行):
  - 纯 SIMT:参考 asc 样例算子仓中 pure simt 算子样例 → 用 mssanitizer 拉起 → 检查越界/对齐/竞争/未初始化/`sync_thread` 同步异常。
  - CATLASS DSL:修改一个 CATLASS DSL 算子人为注入异常 → 用 mssanitizer 拉起 → 验证检测。
  - mask 寄存器:构造 AscendC 算子,vector 指令前配置 mask(覆盖 normal/counter 两种模式)→ 运行 → 工具展示对应 mask 模式与值。
  - DCCI:构造核间一读一写场景(三类序列模式见 §2.5)→ 故意缺失 DCCI → 启动时携带 `--dcci-check yes` 验证检出。
  - ops-transformer:以 RP2 release 为基线对算子仓做全量扫描,统计误报率回归至 < 5%。
- **E2E 测试覆盖矩阵**(原文 §4.2,供使用方参照适配范围):
  - 算子类型:mix / cube / vec / simt
  - 编程语言:AscendC / Triton / CATLASS / SHMEM
  - 调起方式:`<<<>>>` / ACLNN / PTA
  - 款型:A2 / A3 / A5 / Ascend950
