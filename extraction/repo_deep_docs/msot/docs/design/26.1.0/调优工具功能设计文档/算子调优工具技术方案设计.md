# 一体化深度解读: MindStudio Ops Profiler 功能设计文档

---

## 【定位】

这篇文档是「MindStudio Ops Profiler」(算子调优工具) 的功能设计说明书, 系统性地描述了面向昇腾 AI 处理器算子开发者的**性能调优工具能力**, 涵盖算子仿真 (在昇腾仿真器上) 与算子上板 (在真实昇腾设备上) 两条调优路径下的可视化分析功能、采集机制和约束条件, 作为后续编码与测试的输入指南。

---

## 【技术要点】

1. **双调优路径划分**: 文档将算子调优划分为两类——「算子仿真」(基于昇腾仿真器, 输出指令级流水图、代码热点图等详细数据) 与「算子上板」(基于真实昇腾硬件, 反映最可靠的硬件性能), 不同业务功能分别对应到两类调优类型中。

2. **12 项业务功能 + 3 项 dfx 功能**: 业务功能包括计算内存热力图、Roofline 瓶颈分析图、Cache 热力图、通算流水图 (MC2 算子)、指令流水图 (仿真)、算子代码热点图、性能数据文件、搬运带宽图、指令流水图 (上板)、warp 耗时展示、warp 基本信息展示; dfx 功能包括 Ctrl+C 提前终止、定时结束进程、指定仿真器版本。

3. **A5 代际硬件的 dfx_region 桩机制**: 上板指令流水图依赖 A5 代际硬件提供的 `dfx_region` 功能 (在对应 pipe 上打点, 而非 A2/A3 代际的 scalar 打点), 编译器在计算类、搬运类指令前后插入 `dfx_region` 桩, 返回 `region_id` 与 `pc` 对应关系, 运行时硬件返回执行时间。

4. **四阶段流水线**: 指令流水图方案分为「前置插桩 (编译器插 dfx_region)」→「运行算子 (工具拉起插桩后程序)」→「数据返回 (硬件格式化处理)」→「最终展示 (解析侧解析 + 调用栈生成)」, 调用栈生成依赖 `llvm-symbolizer`。

5. **simt vf 插桩获取 warp 时间戳**: warp 耗时展示功能要求编译器在 simt vf 开始/结尾处插桩, 桩内记录 `warp_id = getWarpId()` 与 `start_ts = readCycle()` / `end_ts`, 通过 `storeToGM()` 写入 Global Memory 的 Warp Record Table, 工具解析侧画出流水图。

6. **代际与版本约束**: 上板流水图在 A2/A3 代际未提供, 需硬件 (A5) + 编译器 (cann) 与工具版本配套, 硬件返回数据有信息丢失时工具需提醒用户; 代码热点图在 msprof op 与 msprof op simulator 两种模式下的能力差异显著 (例如 Gpr Count、Vector 计算利用率、cycles 耗时仅 simulator 支持, L2Cache 命中率模拟仅 msprof op 支持)。

## 【关键机制与数据】

### 上板指令流水图工作原理 (原文: 3.1.1.1)

- **前置插桩阶段**: 编译器对程序执行 `dfx_region` 插桩, 植入监控点, 返回 `region_id` 与 `pc` 的对应关系, 发生在算子下发**之前**。
- **运行算子阶段**: 工具 (基础组件) 拉起已插桩的程序, 程序运行时自动产出所需数据。
- **数据返回阶段**: 硬件接收原始数据并格式化处理返回给工具, 算子结束后触发。
- **最终展示阶段**: 工具 (解析侧) 获取格式化数据并完成展示, 包括解析硬件返回的指令执行时间信息以及调用栈信息。

> 原文约束: "当前只有 A5 代际提供该功能、A2/A3 未提供此功能。该功能依赖编译器, 要求工具与编译器 (cann) 版本配套。当前指令流水信息由硬件返回, 若硬件有信息丢失工具需要提醒用户。"

### warp 耗时展示工作原理 (原文: 3.1.1.2)

- **插桩工具职责**: 识别 SIMT VF 区域边界, 在 BEGIN 处插入 `warp_id + start_timestamp` 记录桩, 在 END 处插入 `warp_id + end_timestamp` 记录桩。
- **硬件运行时行为**: 各 Warp (Warp 0/1/2/N) 执行 VF, 将 Warp Record Table 写入 Global Memory, 字段包含 Warp ID / Start Timestamp / End Timestamp。
- **工具解析侧**: 获取每个 warp 的执行时间信息并画出流水图, 呈现在代码流水图界面。
- **原文约束**: "默认在流水图中显示每个 warp 的开始时间和终止时间", 且该功能依赖编译器, 要求工具与编译器 (cann) 版本配套。

### 业务功能与调优类型映射 (原文: 用例分析表格)

- 仅上板调优: 计算内存热力图、Roofline 瓶颈分析图、Cache 热力图、通算流水图 (MC2)、指令流水图 (上板)、warp 耗时展示、warp 基本信息展示、性能数据文件。
- 仅仿真调优: 指令流水图 (仿真)、搬运带宽图。
- 上板/仿真均支持: 算子代码热点图。
- dfx 功能: Ctrl+C 提前终止 (上板/仿真均支持)、定时结束算子进程 (上板)、指定仿真器版本 (仿真)。

**逐行解读**:
- **计算内存热力图 / Roofline / Cache 热力图**: 均属上板调优, 体现工具对真实硬件上内存层次与性能建模的可视化能力; Cache 热力图直接服务于 L2Cache 命中率优化。
- **通算流水图**: 专用于 MC2 算子, 关注通算协同瓶颈, 属于上板专属。
- **指令流水图 (仿真)**: 仿真路径下展示 simt vf 的细节 (线程数、warpId、schId), 是仿真的核心优势——指令级深度信息。
- **算子代码热点图**: 唯一同时支持上板和仿真的业务功能, 是源码-指令映射的核心入口。
- **性能数据文件**: 以文本/数据文件形式呈现, 覆盖最广指标 (指令耗时、L2cache 命中率、L0/UB/内存带宽、占比类指标), 适合自动化分析。
- **搬运带宽图**: 仿真专属, 关注 GM↔L1/UB/other 的数据搬运, 用于分析访存瓶颈。
- **指令流水图 (上板)**: 与仿真版区别在于依赖硬件 (A5) 返回的数据, 无 simt vf 细节。
- **warp 耗时展示 / warp 基本信息展示**: 均依赖编译器插桩, 上板专属。
- **dfx 三项**: Ctrl+C + 定时结束 (上板) 用于避免长时间等待; 指定仿真器版本 (仿真) 便于复现。

### 表 2: 代码热点图详细功能列举 (msprof op vs msprof op simulator)

| 特性名称 | msprof op | msprof op simulator |
|---|---|---|
| 查看寄存器使用情况 (Gpr Count) | 不支持 | 支持 |
| 模拟代码行和指令维度的 L2Cache 命中率 | 支持 | 不支持 |
| 查看与 GM 有关的数据搬运量 (Process Bytes) | 支持 | 支持 |
| Vector 计算类指令在 UB Bank 上读和写的冲突情况 | 不支持 | 支持 |
| Vector 计算单元利用率 | 不支持 | 支持 |
| 查看算子源码与指令的耗时情况 (cycles) | 不支持 | 支持 |

| 查看算子源码与指令集的映射关系 | 支持 | 支持 |
| 查看源码、指令 PC 地址、Pipe、Source | 支持 | 支持 |
| 查看 core 信息 | 不支持 | 支持 |

**逐行解读**:
- **Gpr Count / Vector UB Bank 冲突 / Vector 计算单元利用率 / cycles 耗时 / core 信息**: 这 5 项**仅 simulator 支持**, 说明仿真器在指令级细粒度分析上能力更强, 可用于评估寄存器压力、计算单元饱和度等。
- **代码行 + 指令维度的 L2Cache 命中率模拟**: **仅 msprof op 支持**, 这是实机独有的特性, 与硬件 L2Cache 行为直接关联。
- **Process Bytes / 执行次数 / 映射关系 / PC/Pipe/Source**: 两端均支持, 是代码热点图的核心公共能力, 用户无论上板还是仿真都可获得。
- **整体结论**: simulator 偏「指令级深度分析」, msprof op 偏「硬件真实行为分析」, 用户需根据调优目标选择路径。

### 表 3: 指令流水图四阶段 (原文: 3.1.1.1 表格)

| 阶段 | 角色 | 关键动作 | 时序关系 |
|---|---|---|---|
| 前置插桩 | 编译器 | 对程序执行 `dfx_region` 插桩, 植入监控点; 返回 region_id 与 pc 的对应情况 | 发生在算子下发**之前** |
| 运行算子 | 工具 (基础组件) | 拉起已插桩的程序 → 程序运行时自动产出所需数据 | 运行插桩生效后的算子 |
| 数据返回 | 硬件 | 接收原始数据 → 格式化处理 → 返回给工具 | 算子结束后触发 |
| 最终展示 | 工具 (解析侧) | 获取格式化数据并完成展示 (包括解析硬件返回的指令执行时间信息以及调用栈信息) | 最后一步, 解析侧解析并展示数据 |

**逐行解读**:
- **前置插桩 (编译器)**: 静态阶段, 必须先于算子运行完成, 保证 `region_id ↔ pc` 映射表可用。
- **运行算子 (工具基础组件)**: 实际拉起二进制, 桩代码在运行期间被触发并产生原始数据。
- **数据返回 (硬件)**: 算子运行结束后由硬件主动格式化并返回, 注意**非实时流式**, 而是批处理式。
- **最终展示 (工具解析侧)**: 解析硬件返回数据 + 调用 `llvm-symbolizer` 生成调用栈, 完成最终可视化, 是用户实际看到的环节。

## 【公式解读】

原文无数学公式。但文档包含一段**插桩伪代码** (3.1.1.2 节), 逐字保留并解释如下:

```
BEGIN_STUB:
    warp_id = getWarpId();
    start_ts = readCycle();
    storeToGM(warp_id, start_ts);  // 写入 Global Memory
SIMT_VF_BEGIN:
    // 原始计算逻辑
SIMT_VF_END:
END_STUB:
    warp_id = getWarpId();
    end_ts = readCycle();
    storeToGM(warp_id, end_ts);
```

**符号/语句解释**:
- `BEGIN_STUB` / `END_STUB`: 编译器在 SIMT VF 区域边界插入的桩代码段, 分别位于 SIMT_VF_BEGIN 之前与 SIMT_VF_END 之后。
- `getWarpId()`: 获取当前正在执行该 SIMT VF 的 warp 标识, 用于在 Warp Record Table 中区分不同 warp。
- `readCycle()`: 读取硬件 cycle 计数器, 提供高精度时间戳, 用于后续计算 warp 执行时长 = `end_ts - start_ts`。
- `storeToGM(warp_id, start_ts)` / `storeToGM(warp_id, end_ts)`: 将 (warp_id, 时间戳) 二元组写入 Global Memory 的 Warp Record Table, 供工具解析侧回读。
- `SIMT_VF_BEGIN` / `SIMT_VF_END`: SIMT Vector Function 的原始计算逻辑边界, 桩包夹在外侧。
- `// 写入 Global Memory`: 注释, 强调使用 GM (而非 L1/L2) 是因为跨 warp 数据需要持久化存储, 工具在算子结束后统一读取。

文档中另一处示意数据 (Warp Record Table):
```
┌─────────┬───────────────────┬───────────────────┐
│ Warp ID │ Start Timestamp   │ End Timestamp     │
├─────────┼───────────────────┼───────────────────┤
│ 0       │ 1000              │ 2500              │
│ 1       │ 1100              │ 2600              │
│ 2       │ 1020              │ 2520              │
```

**数据解读**: Warp 0 耗时 = 2500 - 1000 = 1500 cycles; Warp 1 耗时 = 2600 - 1100 = 1500 cycles; Warp 2 耗时 = 2520 - 1020 = 1500 cycles。三个 warp 执行时长相同, 起始时间存在错位 (1100、1020 vs 1000), 反映 SIMT 调度下的 warp 启动差异。

## 【关联】

文档中明确提及的关联模块/上下游如下:

- **编译器 (cann)**: 负责 `dfx_region` 插桩 (3.1.1.1) 与 simt vf 起止插桩 (3.1.1.2); 上板流水图与 warp 耗时展示均「要求工具与编译器 (cann) 版本配套」, 编译器还负责返回 `region_id` 与 `pc` 的对应情况。
- **昇腾硬件 (A5/A2/A3 代际)**: 上板指令流水图仅 A5 代际提供 dfx_region 功能, A2/A3 未提供; 硬件负责返回格式化数据, 若信息丢失需工具提醒用户。
- **llvm-symbolizer**: 工具解析侧在最终展示阶段调用, 用于完成调用栈的生成。
- **昇腾仿真器**: 仿真调优路径依赖, 仿真器提供指令级性能详细仿真, 输出流水图与代码热点图; dfx 功能支持指定仿真器版本。
- **GM (Global Memory) / L0 / L1 / L2 / UB**: 性能数据文件与搬运带宽图关注 GM↔L1、GM↔UB、GM↔other 的数据搬运, 以及 L0 读写带宽、UB 读写带宽、L2Cache 命中率等指标。
- **MC2 算子**: 通算流水图专为其设计, 用于识别通算瓶颈。
- **simt vf / simd vf**: simt 算子在指令流水图 (仿真) detail 中展示 simt vf 的线程数、warpId、schId 等信息; 上板流水图约束说明 A 中无法显示 simt vf 和 simd vf 的指令细节。
