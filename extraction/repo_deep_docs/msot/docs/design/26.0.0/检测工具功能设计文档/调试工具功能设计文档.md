# 算子检测工具功能设计文档 深度解读

---

## 【定位】

本设计文档描述面向昇腾芯片 AscendC 算子开发的命令行异常检测工具 **mssanitizer** 的功能域设计，提供 AscendC 单算子场景下的内存检测、竞争/同步检测能力，并以同步检测子工具 synccheck 为例给出详细实现方案。

---

## 【技术要点】

1. **工具形态与定位**：命令行工具 `mssanitizer`，由用户通过 CLI 拉起待检测程序并获得检测结果；核心需求为"mssanitizer 支持算子同步检测"。
2. **检测范围（特性场景）**：
   - AscendC 单算子内存检测：非法访问、访问对齐错误、多核踩踏（仅 GM）、内存泄漏、内存重复释放。
   - AscendC 单算子竞争与同步检测（本文详细展开的 synccheck 即此场景）。
   - 算子接入方式：算子直调、AclNN 单算子调用、PyTorch 接入。
   - CANN 软件栈的内存检测。
3. **同步检测核心机制（set_flag/wait_flag 配对）**：
   - 同步事件唯一 id = `(src, dst, eventId)`，用于索引与判定配对关系。
   - 配对算法：按 (src, dst, eventId) 为每条同步事件生成一条队列，收到新指令时查找配对指令并消除，未配对则入队；处理完毕后若队列残留 set_flag 则上报异常。
   - 同步指令原型：`void set_flag(pipe_t pipe, pipe_t tpipe, event_t eventID);` / `void wait_flag(pipe_t pipe, pipe_t tpipe, event_t eventID);`
4. **架构四模块划分**：框架模块、运行时模块、信息处理模块、检测插件模块，通过进程间通信串联，并依赖编译器提供的静态/动态插桩能力。
5. **硬件支持范围**：A2、A3、310P、A5。
6. **性能与可靠性约束**：检测耗时"整体耗时应压缩到一小时内"；算子异常退出时仍需可检出退出前的异常指令。

## 【关键机制与数据】

### 整体架构与数据流（原文："异常检测工具的整体架构设计图"）

- **框架模块**（控制面）：
  1. 解析用户命令行参数，生成检测配置与流程控制参数。
  2. 拉起用户待检测程序并使能正确的运行时模块进行劫持。
  3. 提供进程间通信（IPC）能力，接收运行时模块上报信息。
- **运行时模块**（数据采集面）：
  1. 上报 device 设备上下文信息。
  2. 针对 CANN 软件栈中 **HAL / RT / ACL** 模块的内存操作信息进行分层级上报。
  3. 上报 kernel 上下文信息（算子二进制、kernel name 等）。
  4. 扩展 `rtKernelLaunch` 系列接口参数，使能 device 侧桩信息记录并上报至框架模块。
- **信息处理模块**（分析面）：
  1. 检测算法管理（对算法抽象以方便扩展）。
  2. 桩记录预处理：将原始指令记录处理为统一描述，作为检测算法输入。
  3. 内存检测算法（非法读写、非对齐、泄漏、非法释放）。
  4. 竞争检测算法（核间 / 流水间 / 流水内）。
  5. 未初始化检测算法。
- **检测插件模块**（与编译器协同）：
  1. 向编译器提供桩插入策略查询接口。
  2. 向编译器提供各桩函数的实现（动态插桩 / 静态插桩能力）。

### 上下文与逻辑视图（原文 plantuml）

- **上下文视图**：用户 → `framework_cli` → sanitizer；sanitizer 调用并劫持算子程序的 `kernel_cli`；sanitizer 调用编译器的 `dbi_cli`（动态插桩能力）；算子程序本身调用编译器的 `compile_cli`（静态插桩能力）；sanitizer 向用户返回检测结果。
- **逻辑视图**：sanitizer 内部 `framework ↔ record_input ↔ processor`，`framework.server` 与 `runtime.client` 通过 IPC 配对，`runtime` 调用 `plugin` 的 `dbi_plugin`；外部接口 `framework_cli / output / query / instruction` 分别对外暴露。

### 同步检测（synccheck）数据流（原文：第 4 章）

- 输入：编译器插桩记录的 kernel 运行时所有 `set_flag/wait_flag` 指令。
- 处理：按 (src, dst, eventId) 维护指令队列 → 边读边配对消除 → 最终检查队列残留。
- 输出：set_flag 未配对异常，含流水信息（源流水→目的流水）、kernel name、block 信息、device 信息、代码调用栈。
- 异常报告格式示例（原文逐字保留）：
  ```
  ====== WARNING: Unpaired set_flag instructions detected 
  ======    from PIPE_MTE2 to PIPE_MTE3 in hardware_sync_mix_mix_aic 
  ======    in block aiv(0) on device 1 
  ======    code in pc current 0x1b280 (serialNo:8) 
  ======    #0 kernel.cpp:28:5
  ```

### 性能与可靠性约束（原文："2.3.4 / 2.3.5"）

- 性能：检测耗时压缩到 **一小时内**（大算子、整网、多卡场景下保证可用性）。
- 可靠性：算子异常退出时，应保证可检出退出前的异常指令。

## 【公式解读】

### 同步指令原型（原文：第 4 章"C++ 伪代码"）

```cpp
void set_flag(pipe_t pipe, pipe_t tpipe, event_t eventID);
void wait_flag(pipe_t pipe, pipe_t tpipe, event_t eventID);
```

**符号含义与作用**：
- `set_flag(...)`：在源流水 `pipe` 上发起同步事件，通知目的流水 `tpipe` 上有一个事件 `eventID` 已就绪。
- `wait_flag(...)`：在源流水 `pipe` 上等待目的流水 `tpipe` 上事件 `eventID` 就绪。
- `pipe_t pipe`：源流水标识（如 `PIPE_MTE2`，表示当前流水）。
- `pipe_t tpipe`：目的流水标识（如 `PIPE_MTE3`，表示被同步的对端流水）。
- `event_t eventID`：事件编号，用于在同一对 (源, 目的) 流水内区分多个并行同步事件。

**作用**：配对检测的唯一性 key 由三元组 `(pipe, tpipe, eventID)` 构成（即原文中的 `src, dst, eventId`）；相同的 set_flag/wait_flag 必须 (src, dst, eventId) 完全一致才能配对，否则视为不同事件。这正是 4.1 节配对算法按该三元组维护队列的依据。

## 【关联】

依据原文描述，本工具与以下模块/特性/上下游紧密关联：

- **CANN 软件栈**：运行时模块需对 HAL、RT、ACL 三层模块的内存操作信息进行分层级上报，因此 mssanitizer 的运行时模块与 CANN 的 HAL/Runtime/ACL 三层耦合。
- **AscendC 算子与编译器**：检测插件模块依赖编译器提供的静态插桩（编译期）与动态插桩（运行期）能力；上下文视图也明确 sanitizer 与编译器通过 `compile_cli / dbi_cli` 接口对接。
- **rtKernelLaunch 系列接口**：运行时模块扩展该系列接口参数以使能 device 侧桩记录，是 device/host 端事件上报的入口。
- **多种算子接入方式**：算子直调、AclNN 单算子调用、PyTorch 接入，三种接入方式共享同一套检测逻辑。
- **昇腾硬件**：A2、A3、310P、A5，构成硬件适配矩阵；多核踩踏检测范围限定为 GM（Global Memory）。

## 【使用方法】

- **入口**：命令行工具 `mssanitizer`，用户通过工具命令行（`framework_cli`）调用。
- **基本流程（原文："用户可使用工具启动待检测的程序，并得到检测结果"）**：
  1. 用户调用 mssanitizer 命令行，传入检测参数；
  2. 框架模块解析参数 → 生成检测配置；
  3. 框架模块拉起待检测算子程序，并使能运行时模块进行劫持；
  4. 运行时模块上报 device/kernel/桩记录 → 框架模块接收（IPC）；
  5. 信息处理模块运行对应检测算法（如 synccheck）→ 输出异常报告。
- **启用场景**：AscendC 单算子；接入方式可选算子直调、AclNN 单算子、PyTorch 接入。
- **支持的检测项**：内存（非法访问、对齐错误、GM 多核踩踏、泄漏、重复释放）、竞争与同步（set_flag/wait_flag 配对）、未初始化、CANN 软件栈内存。
- **特定命令/参数清单**：原文未列出具体的命令行选项名称或取值。原文未涉及。
