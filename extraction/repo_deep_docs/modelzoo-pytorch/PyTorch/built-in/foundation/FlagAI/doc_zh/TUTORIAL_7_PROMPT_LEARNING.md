## 【定位】

这篇文档是 FlagAI 项目中关于**提示学习（Prompt Learning）方法论**的概念性引导文档，目的是向读者阐述提示学习的基本范式以及提示工程中的两种主要方法（完形填空提示与前缀提示），为后续使用 FlagAI 工具包在 SuperGLUE 等下游任务上应用提示学习提供理论基础。

---

## 【技术要点】

1. **提示学习范式定位**：提示学习是预训练-微调范式的一种延伸，但与微调不同——它通过"提示工程"将下游任务转化为特定模板，而非直接微调模型参数。这一范式在**数据有限**的场景下表现良好。
2. **完形填空提示（Cloze Prompt）适用场景**：更适合使用**遮挡类语言模型**的下游任务。其构建包含两步：（1）构建由输入部分、答案部分和一些自然语言组成的模板；（2）构建从原始标签到可填选项的对应关系。
3. **前缀提示（Prefix Prompt）适用场景**：通常用于**文本生成任务**。它不直接使用自然语言设计模板，而是**修改嵌入空间**——在 Transformer 中插入前缀向量，并**冻结语言模型的其余参数**。
4. **完形填空示例任务结构**：以 NLI 任务为例，数据集包含两个输入文本——**前提（premise）**和**假设（hypothesis）**，标签表示两者关系，可能的标签字符串有三种：**entailment（一致）、contradiction（矛盾）、neutral（无偏向）**。
5. **两类提示的本质差异**：完形填空提示基于离散的 tokens 进行模板设计；前缀提示则使用**连续的向量**（continuous vectors），因此规避了人工设计模板质量对模型性能的影响过大这一问题。
6. **核心思想对比**：从工作机制上看，前缀提示相当于"从离散的 tokens 变成了连续的向量"，将提示从自然语言层迁移到了嵌入空间层。

## 【关键机制与数据】

### 提示学习的工作原理（原文叙述）

**预训练-微调范式 → 提示学习范式的转变**：
- 原文：预训练好的语言模型将被适配到各种下游任务上。
- 原文：与微调不同的是，提示学习会将原本的任务转化为一个特定的模板，这个过程被称为提示工程。

**完形填空提示的数据流**（两步流程）：
- 第一步：输入文本 + 标签 → 重组为"带有空格的段落 + 空格处可填充的选项"。
- 第二步：构建模板（输入部分 + 答案部分 + 自然语言）+ 构建"原始标签 ↔ 可填选项"的映射。

**前缀提示的数据流**：
- 原文：在 Transformer 里插入一个前缀向量，并冻结语言模型的其余参数。
- 即：修改嵌入空间（而非修改自然语言模板）。
