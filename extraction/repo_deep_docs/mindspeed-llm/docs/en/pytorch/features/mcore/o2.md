# Ascend O2 BF16 Optimizer — 一体化深度解读

---

## 【定位】
本文档描述了 `mindspeed-llm` 在昇腾 NPU 上提供的 O2 (O2-level) BF16 优化器能力, 用于**通过将优化器状态与梯度降精度到半精度 (BF16) 来显著缓解 LLM 训练过程中的显存压力**, 是与 Megatron-LM 原生混合精度 (mixed-precision) 并列、可独立开关的一套显存优化特性集合。

---

## 【技术要点】

1. **显存压力的核心来源**: 优化器 (optimizer states) 与梯度 (gradients) 在 LLM 训练中占据大量显存, 是显存优化的主要攻击面 (原文 "Background")。
2. **半精度优化器 (Half-precision optimizer)**: 通过参数 `--o2-optimizer` 启用, 将优化器状态以半精度保存, 节省 **4N/DP 字节**。
3. **半精度梯度 (Half-precision gradient)**: 通过参数 `--o2-gradient` 启用, 将梯度以半精度保存, 节省 **2N 字节**。
4. **两项特性互相独立**: 既可单独启用其中一项, 也可同时启用 (原文 "Usage Notes" 第 1 条)。
5. **算子级互斥约束**: `--o2-gradient` **必须** 与 `--no-gradient-accumulation-fusion` 同时使用, 因为 Matmul-Add 梯度累积算子不支持半精度梯度的组合 (原文 "Usage Notes" 第 2 条)。
6. **精度假设**: 当前 O2 仅支持模型参数类型为 **BF16** 的训练场景; 相比 Megatron 原生 mixed-precision, 预期会对精度产生影响 (原文 "Usage Scenarios" 第 1-2 条)。
7. **性能影响量化**: 理论上不影响性能; 实测基于 **Llama-2-7B 4K 预训练**, 性能影响 **< 1%** (原文 "Usage Notes" 第 3 条)。

---

## 【关键机制与数据】

- **工作机制 (原文)**:
  - "Use half-precision optimizer parameters and gradients to reduce memory usage significantly."
  - 即把通常以 FP32 保存的 optimizer 内部状态 (m, v 等) 与计算出的 gradients 用更低精度 (BF16) 存储, 在显存维度上做"等价压缩", 以腾出空间给更大模型或更大 batch。
  - 每个特性的节省量通过变量 `N`(模型参数量) 与 `DP`(数据并行度) 表达, 是一个**理论峰值估算**, 而非运行时的精确字节数。

- **关键变量定义 (原文)**:
  - `N` = number of model parameters (模型参数量)。
  - `DP` = data parallel degree **when the distributed parallel optimizer is enabled** (启用分布式并行优化器时的数据并行度)。若未启用分布式并行优化器, `DP = 1`。

- **性能数据 (原文)**:
  - 平台: 昇腾 (本文为 mindspeed-llm 在 Ascend 上的特性文档)。
  - 模型与负载: **Llama-2-7B** 预训练, 序列长度 **4K**。
  - 结论: 与未启用 O2 的同场景相比, O2 对训练吞吐/时延的影响 **小于 1%**。
  - 注: 原文没有给出训练 step time、MFU、显存峰值的具体数字, 仅给出 <1% 这个**单一上限式描述**, 应理解为"几乎可忽略"。

- **不影响的对照基准 (原文)**: Megatron-LM 原生 mixed-precision 训练 (这是 O2 启用时的精度对照基线, 而不是性能对照基线 — 原文明确说 O2 相比该 baseline "expected to affect accuracy")。

## 【表格解读】

原文表格逐字还原 (Markdown):

| Feature Name              | Feature Parameter  | Memory Reduction (Bytes) |
| ------------------------- | ------------------ | ------------------------ |
| Half-precision optimizer  | --o2-optimizer     | 4N/DP                    |
| Half-precision gradient   | --o2-gradient      | 2N                       |

逐行解读:

- **第一行 — Half-precision optimizer (`--o2-optimizer`)**:
  含义是将**优化器状态** (例如 Adam 的 master weights、exp_avg、exp_avg_sq) 以 BF16 存储。节省 `4N/DP` 字节, 这里分子 `4N` 体现了每个参数对应的"约 4 字节"被替换为更小精度的等价值, 分母 `DP` 表示在 ZeRO-style 的分布式并行优化器 (distributed parallel optimizer) 下, 优化器状态会被切分到 `DP` 个 rank 上, 每个 rank 只承担 `1/DP` 的优化器状态 — 因此节省量按 `N/DP` 折算。**当用户没有启用分布式并行优化器时, DP=1**, 即该公式退化为 `4N`。

- **第二行 — Half-precision gradient (`--o2-gradient`)**:
  含义是将**梯度张量**以 BF16 存储。节省 `2N` 字节, **不除以 DP** — 原文的隐含假设是梯度在 DP 之间需要保持完整 (各 rank 都有自己的本地梯度), 因此梯度节省量是参数级而非按 DP 切分。这一点也是它和 optimizer 行的关键区别, 体现了文档的精确性。

- **两张特性叠加关系**:
  两项独立可加 — 当两项同时启用时, 总理论显存节省为 `4N/DP + 2N` 字节 (原文未给出该求和形式, 是基于其独立声明 "do not depend on each other" 的自然外推)。

> 备注: 表中 `4N/DP`、`2N` 是表格单元格中的代数化数值, 原文并未以 LaTeX 公式形式给出, 因而归属"表格解读"而非"公式解读"。

## 【关联】

原文未提供内部链接 (内部链接: 无), 但通过文本措辞可以梳理出如下与外部/相邻特性的依赖与对照关系:

- **基线参照 — Megatron-LM native mixed-precision**: 原文将 O2 与之并列做"同训练场景对比"。Megatron 原生 mixed-precision 是更保守的精度策略, O2 在此基础上**进一步降低 optimizer / gradient 的精度**, 因此精度预期会变化 (而不仅仅是与 baseline 等价)。
- **依赖项 — 分布式并行优化器 (distributed parallel optimizer)**: 决定 `DP` 的取值是否 > 1, 从而改变 `--o2-optimizer` 的节省量表达式 (`4N/DP` vs `4N`)。该功能独立于 O2, 由 Megatron/MindSpeed 的并行优化器设置启用。
- **互斥项 — Matmul-Add 梯度累积 (gradient accumulation fusion)**: 这是一个独立算子优化 (将 matmul + add 的梯度累加融合), 原文明确算子**不支持**与半精度梯度的组合, 因此触发禁用开关 `--no-gradient-accumulation-fusion`。
- **组合关系 — `--no-gradient-accumulation-fusion`**: 不是 O2 自带的子参数, 而是相邻特性中的禁用式开关; 当启用 `--o2-gradient` 时, 必须同时指定它 (视为强制伴随参数)。
- **模型类型依赖 — BF16 训练通路**: O2 仅在模型参数本身为 BF16 的训练场景下受支持, 因此和 BF16 主训练通路 (而非 FP16 / FP32 主训练) 绑定。
- **评测关联 — Llama-2-7B 4K 预训练**: 唯一的性能数据点取自该配置, 与 mindspeed-llm 的 Llama 类预训练 benchmark 体系相关 (原文未给出 benchmark 模块名)。

## 【使用方法】

启用方式 (按原文):

- **启用半精度优化器** (单独): 在训练命令中加入参数 **`--o2-optimizer`**。
- **启用半精度梯度** (单独或在同时启用 optimizer 的情况下): 在训练命令中加入参数 **`--o2-gradient`**, 且**必须同时**加入 **`--no-gradient-accumulation-fusion`**。
- **两项同时启用**: 同时传 `--o2-optimizer` 与 `--o2-gradient` (后者再配套 `--no-gradient-accumulation-fusion`), 两者互不依赖。
- **可选前置条件**: 若希望 `--o2-optimizer` 的节省量按 `4N/DP` 折算, 需先**启用分布式并行优化器**; 否则 DP=1, 节省量按 `4N` 计 — 此项配置方式原文未给出具体参数名, 写"原文未涉及"。
