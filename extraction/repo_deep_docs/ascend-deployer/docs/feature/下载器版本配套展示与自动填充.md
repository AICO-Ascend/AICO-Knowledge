# 下载器版本配套展示与自动填充功能 — 一体化深度解读

## 【定位】

本文档定义 Ascend Deployer 离线下载器模块新增的 **版本配套关系展示 + 基于 NPU 版本的自动填充版本号** 能力，解决用户在下载 NPU / CANN / DL / MindSpore / Torch-npu 等强配套软件包时因版本不匹配导致安装或运行失败的问题。

---

## 【技术要点】

1. **配套关系配置生成机制**：以 `downloader/software/` 目录下软件包 JSON 文件名及其内 `required_soft` 字段为输入，结合既有的 `version_match.json`，最终生成 `release_config.json` 配套关系配置文件，并以 **NPU 主版本号** 作为配套组名称。
2. **命令行配套展示**：新增 `--show-releases` 参数（`action="store_true"`），触发后调用 `show_releases()` 函数并退出；展示形式为 **转置表格**（组件为行、发布版本为列），最大宽度 158 字符，长文本在逗号处自动换行。
3. **Windows UI 配套展示**：中间栏新增"展示配套版本"按钮，调用 `show_releases_dialog()`，弹 `Toplevel` 窗口 + `Treeview` 表格，支持水平与垂直滚动。
4. **自动填充核心函数 `fill_versions_by_npu(pkg_list)`**：扫描 `pkg_list` 中形如 `NPU==<version>` 的规格 → 在配套组中匹配包含该 NPU 版本的 release → 对未指定版本的组件填入 `components[组件]` 列表的 **第一个版本**，对已显式指定版本的组件 **不覆盖**，并打印 `[INFO] Auto-filled versions based on NPU==<ver>: ...` 日志。
5. **4 个配套版本组**：当前已落地的版本组为 **26.0、25.5、25.3、25.2**（共 4 组），组件列固定为 `["NPU", "CANN", "DL", "FaultDiag", "MindIE-image", "MindSpore", "Torch-npu", "TensorFlow"]`。
6. **运行时覆盖机制**：`release_config.json` 支持通过 `obs_downloader_config` 更新机制进行覆盖，无需修改代码即可更新配套关系。

### 表格 2：自动填充边界场景（原文 §5.4，逐字还原）

| 场景 | 行为 |
|------|------|
| 未指定 NPU 版本 | 不自动填充，返回原列表 |
| NPU 版本不在任何配套组中 | 不自动填充，返回原列表 |
| 部分包已显式指定版本 | 仅填充未指定版本的包，不覆盖已有版本 |
| 空 pkg_list | 返回空列表 |
| 配套组中某组件无版本（如 TensorFlow 在 26.0 中） | 保留原样（不带版本号） |

**逐行解读：**
- 前 2 条确立 **"NPU 版本是必要且充分触发条件"**：缺少 NPU 或 NPU 不被识别时，行为完全等价于回退到原有默认版本逻辑，避免误填错配。
- 第 3 条明确 **"显式优先级 > 自动填充"**：用户手工指定的 `CANN==8.2.RC1` 不会被 `fill_versions_by_npu` 改写，命令行示例中 `NPU==25.5.0 + CANN==8.2.RC1` 即此场景，仅 DL 被填充。
- 第 4 条保证函数对 **空输入幂等**，不抛异常。
- 第 5 条处理 **空列表组件**：当 `components[组件]=[]` 时，函数不追加版本号，与表格 1 中 TensorFlow 在 26.0/25.5/25.3 的 `-` 标记一一对应。

## 【公式解读】

原文无显式数学公式，但 `fill_versions_by_npu` 的填充规则可用伪代码表达（基于原文约束还原）：

```
输入: pkg_list = [(name_i, ver_i | None), ...]

1. npu_ver ← 扫描 pkg_list 查找首个形如 "NPU==X" 的 ver_i
2. 若 npu_ver is None: return pkg_list
3. release ← 在 release_config.releases 中查找
                使 npu_ver ∈ release.components["NPU"]
4. 若 release is None: return pkg_list
5. for each (name_i, None) in pkg_list:
       ver_default ← release.components[name_i][0]
       若 ver_default 非空: pkg_list[i].ver ← ver_default
           并记录日志 "[INFO] Auto-filled ... {name_i}=={ver_default}"
6. return pkg_list
```

**符号含义：**
- `npu_ver`：从用户传入的 `pkg_list` 中提取的 NPU 版本字符串，是触发自动填充的唯一锚点。
- `release.components["NPU"][0]`：每个配套组 NPU 列表的第一项即 NPU 匹配键，与 `name` 字段同名（主版本号）。
- `release.components[name_i][0]`：对每个组件取 **列表第一个版本**，原文明确写"列表中第一个版本为自动填充时的默认版本"。
- `pkg_list[i].ver ← ver_default`：仅对原 ver 为 `None` 的项赋值，确保"已显式指定的版本不会被覆盖"约束成立。

## 【关联】

原文文末标注"无"内部链接，但根据文档内容可识别出以下模块级上下游关系：

1. **上游数据源**
   - `downloader/software/*.json`（软件包 JSON 文件名 + `required_soft` 字段）：提供原始配套意图描述。
   - `downloader/version_match.json`（既有文件）：提供版本映射规则。
   - 两者合并 → 产出 `downloader/release_config.json`。

2. **下游消费方**
   - **命令行入口** `ascend_download.py`：消费 `release_config.json` 的两条路径 ——`--show-releases` 仅展示，`run()` 在 `download_dependency()` 调用前先调用 `fill_versions_by_npu()`。
   - **Windows UI 入口** `downloader_ui.py`：消费同一 `release_config.json`，对应三条路径 ——"展示配套版本"按钮弹窗、`start_download()` 中的 `refresh_data()` 之后调用 `fill_versions_by_npu`。
   - **底层工具库** `download_util.py`：是配套关系与自动填充逻辑的实现层，被上述两个入口共同调用。

3. **外部覆盖通道**
   - `obs_downloader_config` 更新机制：可在不修改代码的前提下覆盖 `release_config.json`，作用于 `get_release_list()` 的读取路径。

4. **与项目整体定位的关系**
   - 文档开头定义 ascend-deployer 的范围是"驱动、固件、CANN 软件包以及 MindCluster 的安装"。本特性聚焦 **CANN 软件包链** 的离线下载前置环节（表格中出现的 CANN/DL/FaultDiag/MindIE-image/MindSpore/Torch-npu/TensorFlow 均为 CANN 生态相关），属于下载器模块的可用性增强。

## 【使用方法】

### 命令行（原文 §5.3）

```bash
# 1) 仅查看配套版本表（展示后退出）
ascend-download --show-releases

# 2) 指定 NPU 版本 → 自动填充未指定包的配套版本
ascend-download --os-list Ubuntu_22.04_aarch64 --download NPU==25.5.0 CANN DL
# 输出: [INFO] Auto-filled versions based on NPU==25.5.0: CANN==8.5.0, DL==7.3.0

# 3) 已显式指定的包不被覆盖
ascend-download --os-list Ubuntu_22.04_aarch64 --download NPU==25.5.0 CANN==8.2.RC1 DL
# 输出: [INFO] Auto-filled versions based on NPU==25.5.0: DL==7.3.0

# 4) 未指定 NPU → 不触发自动填充，回退默认逻辑
ascend-download --os-list Ubuntu_22.04_aarch64 --download CANN DL
```

### Windows UI（原文 §3 + §5.2）

1. **查看配套版本**：点击中间栏新增的 **"展示配套版本"** 按钮 → 弹出 `Toplevel` 窗口内的 `Treeview` 表格（含水平/垂直滚动条）。
2. **下载时自动填充**：选择 NPU 版本而其他包未选版本 → 点击 **"开始下载"** → UI 在 `refresh_data()` 之后调用 `fill_versions_by_npu()` 自动填充其余包。

### 配置项（原文 §5.1 + §5.2）

| 项 | 用途 | 来源 |
|---|---|---|
| `--show-releases` | 命令行开关，触发配套表展示 | `ascend_download.py` 新增 argparse 参数 |
| `obs_downloader_config` | 运行时覆盖 `release_config.json` 路径 | 既有机制 |
| `release_config.json` 文件结构 | `releases[].name`（配套组名）+ `releases[].components`（组件→版本列表） | `downloader/release_config.json` |
| `RELEASE_COMPONENTS` | 表格列顺序常量 | `download_util.py` |
