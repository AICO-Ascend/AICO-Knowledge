# 深度解读：optimizer/grad offload

## 【定位】
本文档介绍 mindspeed-rl 中"优化器状态/梯度/权重卸载（offload）"能力，用于解决 Actor 模型在 RLHF 训练中**训推共卡**场景下，推理态与训练态频繁切换导致的 NPU 峰值显存过高与资源浪费问题。

---

## 【技术要点】

1. **适用算法范围**：针对 GRPO、PPO 等 RLHF 算法——此类算法单轮训练中耗时主要集中在推理阶段。
2. **问题场景**：Actor 模型在同一卡上同时存在"推理态"和"训练态"两种模式，每轮训练需在两者间切换，存在训推切换、峰值显存与资源效率三方面挑战。
3. **整体方案**：依托本仓库提供的 **训推共卡方案**（详见 `./integrated_worker.md`），通过**内存卸载（offload）+ 权重转换**两项技术，在推理阶段把训练态相关数据搬至 Host 侧内存，训练阶段再搬回 NPU 完成更新。
4. **三类卸载对象**：训练态**优化器状态（optimizer）**、训练态**梯度（grad）**、训练态**权重（param）**，三者通过 YAML 中的独立开关按需开启。
5. **核心收益**：为推理阶段腾出充足的 KV Cache 空间，降低 NPU 内存峰值，从根本上避免 OOM 引发的训练中断；同时减少资源闲置，提升端到端训练吞吐。
6. **配置入口**：参数统一挂在 YAML 的 `generate_config` 节点下，每个开关以布尔值启用，默认需用户在训练脚本中显式写入。

---

## 【关键机制与数据】

- **数据流 / 工作原理（原文概述）**：
  原文：在推理阶段将训练相关的优化器状态和梯度卸载至 Host 侧内存，训练时再将数据重新加载至 NPU 完成更新。
  即——"推理时 offload → Host 侧内存；训练时 reload → NPU → 完成参数更新"。权重转换技术则服务于训/推两种状态下模型权重的形态切换。

- **两种模式共存**：Actor 模型在每轮训练中需在"训练态"与"推理态"之间切换（原文：每轮训练中，Actor 模型需要在训练态和推理态间切换），offload 是连接这两种模式、降低单卡峰值显存的关键纽带。

## 【使用方法】

在训练脚本的 YAML 配置中加入以下参数（原文逐字摘录）：

```yaml
generate_config:
  offload_train_optimizer: true     # 设置为 true 可以使能在推理时卸载训练态优化器
  offload_train_grad: true          # 设置为 true 可以使能在推理时卸载训练态梯度
  offload_train_param: true         # 设置为 true 可以使能在推理时卸载训练态权重
```

参数说明（依原文注释）：
| 参数 | 取值 | 作用 |
|---|---|---|
| `offload_train_optimizer` | `true` / `false` | 推理时卸载训练态**优化器**状态 |
| `offload_train_grad` | `true` / `false` | 推理时卸载训练态**梯度** |
| `offload_train_param` | `true` / `false` | 推理时卸载训练态**权重** |

三项开关均需用户手动在 `generate_config` 下显式开启；原文未涉及更细粒度的参数（如卸载比例、Host 侧内存上限、调度触发时机等）。
