# PP自动并行算法

> 仓 `mindspeed` · 路径 `docs/zh/features/automated-pipeline.md` · 类型 feature · MiniMax-M3 文档深读 + 图文关联 · ver=v2
> 原文: extraction/repo_docs/mindspeed/docs/zh/features/automated-pipeline.md

【定位】  
本文面向已启用流水线并行的训练场景，通过 PP 自动并行算法分别解决流水线各 Stage 显存不均衡和流水线气泡导致的性能下降问题。

【技术要点】

1. **传统 1F1B 调度的瓶颈**  
   PP 将模型网络层切分为多个 Stage，并映射到不同设备。原文指出，1F1B 调度下靠近模型前部的 PP-Stage 显存占用明显高于后部 Stage，差距达到 **2~3 倍**，总体可训练模型规模受限于 PP-Stage 0 的显存消耗；设备负载不均或网络通信波动还会产生流水线气泡。

2. **基于 profiling 与 PP 建模的自动搜索**  
   系统基于“在线 profiling + PP 建模搜索”，分别构建内存排布和性能调度方案：
   - 内存优化模块联合搜索 PP 层分布和细粒度重计算策略，以均衡各卡显存并降低峰值内存。
   - 性能优化模块在峰值内存不超过设备最大容量的约束下，联合搜索 mbs 序列和前向反向调度序列，以缩短端到端训练时间。

3. **内存优化机制**  
   通过不均匀层切分自动寻找层分布，避免按相同层数切分导致的显存不均衡；同时将细粒度重计算安排在流水线气泡中，以进一步降低峰值内存，并尽量避免性能劣化。

4. **动态 mbs 与调度优化**  
   在给定 gbs 的条件下自动搜索 mbs 序列：启动和冷却阶段使用小 mbs 压缩气泡，稳态阶段选择更高效的 mbs 缩短计算时间。前向反向调度则通过调整计算顺序，并结合多流异步通信机制压缩稳态气泡。

5. **互斥的两种优化模式**  
   内存优化与性能优化针对不同问题，不能同时启用：显存不足时选择内存优化，流水线气泡占比过大导致性能不佳时选择性能优化。

6. **原文收益数据**  
   - Llama-2-7b、Llama-2-13b、Llama-2-70b 等使用 PP 配置训练的模型，启用内存优化后平均峰值内存减少 **11.5%**，平均性能劣化小于 **1%**。
   - Llama-2-7b、Llama-2-13b、Llama-3-8b 等使用 PP 配置训练的模型，启用性能优化后平均性能提升 **7.6%**。

【关键机制与数据】

原文: 工作流首先把模型网络层切分为多个 Stage，再将不同 Stage 放到不同设备上，使各设备负责模型不同部分的计算。小批次数据以 1F1B 方式在流水线中交替执行前向与反向计算；由于各流水设备计算负载不均衡或网络通信存在波动，后续设备可能等待前一阶段完成，从而形成流水线气泡。

原文: 内存优化模块以在线 profiling 获得的信息和 PP 建模为基础，在“层分布切分 × 细粒度重计算”的联合空间内搜索内存排布。层分布采用不均匀切分，根据各卡显存压力重新分配层，而不是让所有 Stage 承担相同层数；重计算则利用气泡时间完成，以减少激活等显存消耗。该模块同时以降低峰值内存和最小化端到端训练时间作为目标。

原文: 性能优化模块以峰值内存不超过设备最大容量为约束，自动搜索 mbs 序列和前向反向调度序列。动态 mbs 会在流水线启动和冷却阶段采用较小 mbs，使各设备更快进入或退出稳态，减少空等；进入稳态后，再选择更高效的 mbs。多流异步通信与调度顺序联合调整，用于压缩设备间等待时间。

原文: 关键使用约束为 `--pipeline-model-parallel-size >= 2`，即流水线并行规模至少为 **2**；同时，内存优化和性能优化模块不能共同启用。

原文: 在原文列出的模型与 PP 训练场景中，内存优化带来 **平均峰值内存减少 11.5%**、**平均性能劣化小于 1%**；性能优化带来 **平均性能提升 7.6%**。

【关联】

1. **与 1F1B 调度的关系**：1F1B 是当前流水线训练的基础调度背景，也是显存向 PP-Stage 0 集中和流水线气泡产生的原因；PP 自动并行算法是在该背景上的内存与性能优化层。
2. **与 PP 层切分的上下游关系**：上游输入是模型网络层，自动搜索结果是不均匀的 Stage 层分布和 Stage 到设备的映射；该结果直接影响各卡显存占用及流水线计算负载。
3. **内存优化模块内部关系**：层分布切分负责均衡静态显存开销，细粒度重计算负责进一步压低峰值内存；二者联合搜索，目标是同时改善显存和端到端时间。
4. **性能优化模块内部关系**：动态 mbs 主要控制流水线启动、稳态和冷却阶段的小批次粒度，前向反向调度决定计算顺序，多流异步通信用于配合调度并缓解通信等待。
5. **两模块的互斥关系**：二者共享 PP 训练场景，但不能同时启用，应根据主要矛盾在显存不足与气泡过大之间选择。
6. **启用入口关系**：两个模块分别通过 `--automated-pipeline` 和 `--automated-pipeline-perf` 启用，并以 `--pipeline-model-parallel-size >= 2` 为共同前提。文档文末未提供其他内部模块链接或具体实现入口。

【使用方法】

启用 PP 自动并行需要满足：

```bash
--pipeline-model-parallel-size >= 2
```

同时必须二选一，内存优化和性能优化模块不能同时使用。

1. **显存不足时，启用内存优化模块：**

```bash
--automated-pipeline
```

2. **流水线气泡过大、训练性能不佳时，启用性能优化模块：**

```bash
--automated-pipeline-perf
```

以上标志应添加在训练脚本中；原文未涉及其他具体配置参数。
