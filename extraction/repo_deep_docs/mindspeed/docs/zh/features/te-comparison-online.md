# 低精度在线比对 — 一体化深度解读

---

## 【定位】

这篇文档描述了 mindspeed 昇腾大模型加速库中一项**低精度计算实时监控能力**：通过对比 NPU 与 CPU/BF16 标杆的计算结果，帮助用户在模型训练过程中**实时检测 cast 与 quant_matmul 等低精度操作的精度偏差**，从而降低精度问题定位成本，保障低精度模块的可靠性。

---

## 【技术要点】

1. **核心机制：双路并行比对** — 启用特性后，**同时**进行 NPU 上的低精度计算和 CPU（或 BF16）上的标杆计算，并输出两者之间的误差值。
2. **覆盖的低精度操作** — 主要针对 **cast**（精度转换）和 **quant_matmul**（量化矩阵乘）两类低精度算子。
3. **两种比对标杆可选** — 提供两条独立的命令行开关：`--te-comparison-with-cpu`（以 CPU 浮点计算为标杆）和 `--te-comparison-with-bf16`（以 BF16 计算为标杆）。
4. **误差驱动的容错控制** — 每一步均输出 NPU 结果与标杆之间的误差；当误差**超出预设范围**时，系统提示错误并**终止训练过程**，防止精度异常扩散到后续迭代。
5. **适用前提** — 仅适用于**已开启低精度训练**的模型；功能本身不负责开启低精度训练。
6. **目的导向** — 该特性的目标是**精度问题实时追踪**，而非性能加速；因此会引入额外的 CPU/BF16 计算开销。

---

## 【关键机制与数据】

**工作原理**：

- **触发方式**：用户在训练启动命令行中加入 `--te-comparison-with-cpu` 或 `--te-comparison-with-bf16`，特性被激活。
- **执行流程**：对于训练中涉及的每个 cast 与 quant_matmul 算子，框架会在原有 NPU 计算路径之外，**额外**发起一条 CPU 或 BF16 计算路径（取决于用户选择的标杆），两条路径并行运行。
- **数据流**：NPU 低精度结果 → 与 CPU/BF16 标杆结果 → 计算误差（绝对值或相对值，原文未给出具体误差公式）→ 与预设阈值比对 → 若超阈值则报错并终止训练，否则继续下一轮 step。
- **输出形式**：在低精度计算的**每一步**输出误差值（原文未给出误差的具体数值范围或统计指标）。

**性能数据**：**原文未涉及**任何具体性能开销、误差阈值大小、benchmark 数字。

## 【使用方法】

启用方式（**完全来自原文**）：

1. **以 CPU 计算结果为精度标杆**：
   ```
   --te-comparison-with-cpu
   ```
   加入训练脚本的参数列表中即可开启。

2. **以 BF16 计算结果为精度标杆**：
   ```
   --te-comparison-with-bf16
   ```
   加入训练脚本的参数列表中即可开启。
