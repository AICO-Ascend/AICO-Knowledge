# MoE 负载均衡 - 专家迁移 一体化深度解读

---

## 【定位】

这篇文档描述 mindspeed 在 MoE（混合专家）模型训练中，通过**动态专家迁移**机制缓解"快慢卡"问题的方案 —— 以 EMA 预测负载、用贪心算法规划专家重分配、并通过分层细粒度控制器按需触发迁移，从而实现设备级负载均衡、抬升训练吞吐。

---

## 【技术要点】

1. **问题定位**：MoE 训练中专家负载"冷热不均"，尤其预训练阶段不同 device 上专家处理的 token 数差异大、负载变化剧烈，造成快慢卡，拖累吞吐。方案目标是通过专家迁移实现"热专家混合搭配"，把负载打散到各 device。

2. **方案框架 = 规划器 + 执行器**：规划器负责负载数据收集、负载预测、专家分配方案优化（贪心算法）；执行器负责按规划器给出的映射关系做专家参数 / 优化器状态交换，并重映射 MoE router 的 topk 专家 id。

3. **EMA 负载预测**：$ELP_{t+1} = \theta \cdot ELP_t + (1-\theta) \cdot EL_t$；$\theta$ 取值范围 **0.9–0.999**，本方案固定取 **θ=0.9**（相对历史数据更重视当前负载，对变化负载适应性更强）。在迁移前，会在 **DP 域对 ELP 做 allreduce**，保证所有 DP rank 上的预测与分配映射一致。

4. **贪心算法专家分配（5 步迭代）**：① 每个 device 的专家数与 token 数初始化为 0；② 从专家集合中找负载最大者；③ 遍历 device 找"专家数 < 预设上限且 token 数最少"的 device；④ 将该专家分配到该 device 并从集合剔除；⑤ 重复②直至分配完毕。

5. **分层细粒度控制器（是否真的迁移的"门控"）**：以**预测负载的变异系数**（标准差 / 平均值）作为负载不均指标，**只有当变异系数下降 ≥ 0.08** 时才认定迁移有效、才真正触发该层专家迁移；否则跳过，避免不必要的迁移开销（SFT 等负载稳定阶段收益尤其明显）。

6. **迁移操作 + 配置开关**：参数交换走 `alltoall`，涉及专家参数、optimizer 主参、一/二阶动量；支持分布式优化器（`use_distributed_optimizer`）、参数副本复用（`reuse_fp32_param`）与 `tp_extend_ep`；迁移触发频率由 `expert_placement_freq` 控制，默认 **50**。

---

## 【关键机制与数据】

### 数据流（迁移主路径，原文叙述）

1. **采集**：每个训练步采集每个专家的负载 $EL_t$（原文：*"专家负载数据收集功能集成在负载预测模块中"*）。
2. **预测**：在 EMA 模块中迭代更新 $ELP_{t+1} = \theta \cdot ELP_t + (1-\theta)\cdot EL_t$；EMA 本身只需要上一时刻的 $ELP_t$，**不需要保存历史负载序列**，因此"计算轻量化、预测效果也非常好"（原文）。
3. **DP 域同步**：迁移前在 DP 域对 $ELP$ 做 allreduce —— 这是**规划一致性**的关键，避免不同 DP rank 基于不同预测结果算出不同的专家分配映射（原文）。
4. **规划（贪心）**：基于 ELP 结果生成新的专家→device 映射。
5. **门控（细粒度控制器）**：计算当前 $ELP$ 的变异系数，对比执行迁移后的预测变异系数，若下降幅度 ≥ 0.08 才允许本层迁移。
6. **执行（设备间交换）**：
   - **专家参数交换**：参数取出 → `alltoall` → 更新（原文称为"较为简单"）。
   - **优化器状态交换**（原文给出的伪代码，逐字保留）：

   ```txt
   For buffer in buffers:
       For bucket in buffer.buckets:
           1.设置缓冲区：开辟与bucket容量相同的优化器状态交换buffer
           2.写入本地状态：将bucket中参数的本地优化器状态切片写入优化器状态交换buffer
           3.执行allgather操作：对优化器状态交换buffer进行dp组内的allgather操作，得到完整的优化器状态
           4.执行alltoall操作：将本地专家参数状态从优化器状态交换buffer中取出，通过alltoall操作进行专家迁移
           5.更新本地状态：保留优化器状态交换buffer中的专家参数状态切片，并更新本地优化器状态切片
           6.释放缓冲区：释放临时分配的优化器状态交换缓冲区，以节省内存资源
   ```

   注意这里的通信组合是 **dp 组内 allgather + 跨 device 的 alltoall**：allgather 用来在 DP 组内拼齐完整的优化器状态，alltoall 用来按新映射把"片段"分发给目标 device。

7. **router 端收尾**：将 MoE router 决定的 topk 专家 id 重映射到新 device 位置（原文：*"将MoE router确定的topk专家id重映射"*），完成端到端负载均衡。

## 【公式解读】

文档中只出现 1 个公式（EMA 预测），逐字保留如下：

$$
ELP_{t+1} = \theta \cdot ELP_t + (1-\theta) \cdot EL_t
$$

**符号含义（按原文）**：

| 符号 | 含义 | 说明 |
|---|---|---|
| $ELP_{t+1}$ | $t+1$ 步的**专家负载预测**（Expert Load Prediction） | 下一时刻规划器使用的"平滑后"负载估计 |
| $ELP_t$ | $t$ 步的专家负载预测 | 上一时刻的平滑估计 |
| $EL_t$ | $t$ 步**实际采集**到的专家负载数据 | 当前步真实测量值 |
| $\theta$ | EMA 权重 | 控制"历史 vs 当前"权衡 |

**作用与机制解读**：

- 这是标准的 **指数滑动平均（EMA）递推式**：当前预测 = $\theta$ × 上一步预测 + $(1-\theta)$ × 当前实测。
- **$\theta$ 的语义**：$\theta$ 越大（趋近 1），历史预测占比越大、当前实测影响越小 → 预测曲线越平滑、对突发波动越不敏感；$\theta$ 越小 → 更贴近当前实测、对负载变化反应更敏捷。
- **原文选 $\theta = 0.9$ 的理由**（原文直接给出的依据）：相比更大的 $\theta$，"当前负载数据的权重更高，更能捕捉到当前的负载特征，基于此的专家迁移对变化负载的适应性更强"。换言之，预训练阶段负载剧烈变化，本方案故意牺牲一点平滑性，换取对"热专家漂移"的快速响应。
- **计算特性**（原文）："通过迭代方法处理数据，不需要保存历史负载信息，计算轻量化，预测效果也非常好"。意味着工程实现上只需保留一个 $ELP_t$ 标量，无需维护历史序列，适合每步/每 N 步高频调用。
- **与下游模块的关系**：$ELP$ 是**规划器**的输入，也是**控制器**计算变异系数的对象（控制器对"是否触发迁移"的判断建立在 $ELP$ 之上，而不是瞬时 $EL_t$）。

## 【关联】

原文未提供文末内部链接列表（用户给定的内部链接字段为"无"）。基于文中明确点名的耦合项，归纳如下关联关系：

1. **MoE router**：执行器在迁移完成后**重映射 router 输出的 topk 专家 id**，因此本特性的正确性依赖 router 的专家 id 是逻辑 id（可被重映射），而不是物理设备 id。这是一个上下游耦合点。
2. **分布式优化器（`use_distributed_optimizer`）**：优化器状态交换步骤（伪代码）明确依赖"DP 组内 allgather + 跨 device alltoall"模型，本特性**显式支持**该特性；禁用分布式优化器时该交换路径不成立。
3. **参数副本复用（`reuse_fp32_param`）**：原文"支持参数副本复用（reuse_fp32_param）"，意味着迁移路径需要兼容 fp32 主参仅一份副本的场景；这是与 optimizer 状态切片切分的耦合点。
4. **`tp_extend_ep` 功能**：原文列为支持项，暗示 TP×EP 拓扑下专家迁移要按 EP（专家并行）维度重新打散专家，`alltoall` 的通信组需要与 EP 组对齐（原文未展开通信组构造细节）。
5. **MoE 层级结构**：控制器在**每层 transformer 内独立判断**，因此本特性是 per-layer 粒度生效；与"MoE 层数 / 层间负载差异"耦合（负载稳定阶段收益大，正是因为多数层被控制器跳过）。
6. **DP 域同步**：ELp 在 DP 域做 allreduce —— 与 **数据并行（DP）**配置耦合；DP size 与专家数 / device 拓扑共同决定规划器搜索空间。

## 【使用方法】

原文给出了 yaml 配置示例（逐字保留）：

```yaml
enable_expert_placement: True  # 专家迁移功能开关
enable_fine_grained_expert_placement: True #细粒度分层专家迁移开关，若false，则所有moe层均默认按固定频率迁移
expert_placement_freq: 50 #专家迁移频率
print_expert_load: True  #设备级专家负载打印开关
fine_grained_expert_placement_thre: 0.08 #细粒度分层专家迁移开关阈值，值越高，迁移收益要求越大
```

**配置项含义（综合原文）**：

| 配置项 | 作用 | 默认/示例 |
|---|---|---|
| `enable_expert_placement` | **专家迁移功能总开关** | `True` |
| `enable_fine_grained_expert_placement` | **分层细粒度控制器开关**；关闭后所有 MoE 层按 `expert_placement_freq` 固定频率迁移（不再做 0.08 阈值的逐层判断） | `True` |
| `expert_placement_freq` | 专家迁移触发频率（步数） | `50` |
| `print_expert_load` | 打印设备级专家负载，便于观察 | `True` |
| `fine_grained_expert_placement_thre` | 控制器阈值；**值越高，迁移收益要求越大**（即更难触发迁移），与控制器"变异系数至少下降 0.08"的判断逻辑一致 | `0.08` |

**配套能力（原文明示）**：

- 支持 **参数副本复用**（`reuse_fp32_param`）
- 支持 **分布式优化器**（`use_distributed_optimizer`）
- 支持 **`tp_extend_ep`** 功能

**典型启用方式（基于原文配置组合）**：

- **预训练（负载剧烈变化）**：保持 `enable_fine_grained_expert_placement=True`、`fine_grained_expert_placement_thre=0.08`，让控制器按 0.08 阈值在收益足够大的层触发迁移。
- **SFT（负载稳定）**：原文指"负载比较稳定，效果更加显著"——此时细粒度控制器会主动**跳过**迁移收益弱的层，从而降低迁移开销；可以保持上述默认配置。
- **关闭细粒度（兜底）**：将 `enable_fine_grained_expert_placement` 置 `False`，所有 MoE 层按 `expert_placement_freq=50` 固定频率迁移。

**注意**：原文未给出 CLI / 环境变量形式的启用命令，也未给出不同模型规模下的推荐参数扫描范围，因此"超出原文示例范围"的调优建议属于推断，本节不展开。
