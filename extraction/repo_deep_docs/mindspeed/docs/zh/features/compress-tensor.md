# `compress-activation` 文档深度解读

---

## 【定位】

本篇文档描述了 mindspeed（昇腾大模型加速库）针对**长序列训练场景下激活值与优化器状态占用显存过高**的问题，所提供的三种基于"昇腾无损压缩算子"的内存压缩特性，分别覆盖 MLP 激活值、Transformer layer 激活值、以及 AdamW 优化器动量。

---

## 【技术要点】

1. **三个独立开关**：特性一 `--compress-dense`、特性二 `--compress-activation`、特性三 `--compress-optimizer`，可按需单独或组合启用，用于压缩不同对象（MLP/Dense 激活、Transformer 激活、优化器动量）的显存占用。
2. **无损压缩底座**：所有特性均基于"自研昇腾无损压缩算子"，文档明确强调"精度无损"。
3. **多流异步掩盖**：特性一与特性二采用"多流异步"方式调度压缩算子，利用 **Vector** 算力，与 **Cube** 计算及**通信**做时间上的掩盖，使压缩/解压缩本身"基本不会导致性能劣化"。
4. **未掩盖路径**：特性三对 AdamW 一/二阶动量的压缩"未做掩盖"，会引入"小幅度的性能劣化"，这是文档中唯一明确承认会带来性能开销的特性。
5. **特性二为特性一的迭代版本**：二者互斥不可同开；特性三可与特性一或特性二任一组合；且与 `recompute_activation_function` "暂不兼容"。
6. **粒度可配**：
   - 特性一提供 `level0`（仅 Vector 压缩）与 `level1`（Vector 压缩 + 部分结果 swap 到 CPU）两档。
   - 特性二支持层号范围（如 `1-3`、`1,2,3`、`1-3,5-8,10`）以及 `0`（压缩所有层），默认 `NULL`。
   - 特性三为布尔开关，默认 `False`。

---

## 【关键机制与数据】

### 工作原理（按特性）

- **特性一（Dense/MLP 激活压缩）**
  - 记录"首节点 MLP 执行顺序"，对 Dense 层 MLP 模块产生的激活值使用多流异步方式调用昇腾无损压缩算子。
  - 算子使用 Vector 算力 → 与 Cube 计算和通信做掩盖 → 压缩/解压缩过程"基本不会导致性能劣化"。

- **特性二（Transformer layer 激活压缩）**
  - 记录各卡 transformer layer 的执行顺序，对 layer 内产生的激活值做无损压缩。
  - 同样采用多流异步 + Vector 算力 → 与 Cube 计算和通信掩盖 → 不导致性能劣化。

- **特性三（优化器动量压缩）**
  - 直接调用昇腾无损压缩算子对 AdamW 优化器的**一/二阶动量**进行**未掩盖**压缩，会引入**小幅度性能劣化**。

### 性能数据（原文标注）

- 原文："在如 Llama、Qwen 等典型模型下，开启特性一/二**平均内存收益在 3% / 7%**。"
- 原文："**qwen3-8b 模型在序列长度为 8192，并行配置为 PP4TP2CP1，开启特性二的情况下获得内存收益 6.2%**。"

> 注：上文"3% / 7%"对应"特性一/二"（前者为特性一，后者为特性二），括号顺序与原文一致；6.2% 为同一指标在 qwen3-8b（seq=8192、PP4 TP2 CP1）这一具体配置下的实测值。

## 【关联】

文档末提供了"使用约束"段落，揭示了本特性与其他组件/特性的耦合关系：

- **特性二 ↔ 特性一（互斥）**：文档原文："特性二为特性一的迭代版本，两者不能同时开启。"这意味着在 MLP/Dense 激活压缩与 Transformer layer 激活压缩之间只能二选一。
- **特性三 ↔ 特性一 / 特性二（可组合）**：文档原文："特性三可以与特性一或特性二同时开启。"即优化器动量压缩可与激活压缩叠加使用。
- **`recompute_activation_function`（不兼容）**：文档原文："当前特性与 `recompute_activation_function` 特性暂不兼容。"即本文档描述的三种压缩特性不能与重计算激活函数特性同时使用，重计算是另一种节省显存的手段。
- **底层硬件能力**：依赖自研"昇腾无损压缩算子"，使用 Vector 算力，与 Cube（矩阵计算）和集合通信做时间掩盖，硬件层面构成该特性的基础。

## 【使用方法】

以下命令/参数均来自文档原文：

- **特性一（`--compress-dense`）**

  | 取值 | 行为 |
  | --- | --- |
  | `level0` | 只进行 Vector 压缩，节省空间较少，带来极小的性能开销。 |
  | `level1` | 在进行 Vector 压缩的同时，将部分结果 swap 到 CPU 上，节省空间较多，但带来额外的性能开销。 |

- **特性二（`--compress-activation`）**
  - 文本格式：表示要压缩的 transformer 层范围，例如：
    - `1-3` 或 `1,2,3`：压缩第 1/2/3 层产生的激活值。
    - `1-3,5-8,10`：压缩第 1/2/3/5/6/7/8/10 层产生的激活值。
    - `0`：压缩所有层。
  - 默认值：`NULL`。

- **特性三（`--compress-optimizer`）**
  - 布尔开关，控制是否压缩 AdamW 优化器的一/二阶动量。
  - 默认值：`False`。

### 启用方式速查（按场景）

- 仅需压缩 MLP/Dense 激活、且追求极低开销 → `--compress-dense level0`。
- 显存压力更大、愿意换取更高压缩率 → `--compress-dense level1`（会触发 CPU swap）。
- 想按层精细选择 Transformer 激活压缩范围 → `--compress-activation` 配合层号表达式（可为 `0` 启用全局）。
- 想同时压缩优化器动量 → 追加 `--compress-optimizer`，可与上述任一特性叠加（特性一/二互斥，三者之一 + 三）。
- **不能与 `--recompute-activation-function` 同开。**

**2) 技术结论**：激活值在正向产出后即被异步压缩（vector算力），释放显存；压缩与后续Cube前向计算、通信并行掩盖；反向使用前再解压。整个流程无需等待、无精度损失。

**3) 与文档论点对应**：直接论证"特性二"——通过多流异步调用昇腾无损压缩算子，实现激活值显存压缩且基本不导致性能劣化，是"特性一"（仅压缩Dense层）的迭代扩展版。

**2) 技术结论**：压缩/解压缩可与Cube主计算及通信多流异步流水，vector算力开销被掩盖，性能基本无损。

**3) 与文档对应**：直观佐证特性二"多流异步调用昇腾无损压缩算子、压缩过程基本不导致性能劣化"的论点。
