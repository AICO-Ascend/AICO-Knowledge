# Ascend自定义空操作层 深度解读

---

## 【定位】

这篇文档描述了昇腾大模型加速库 mindspeed 中的一项流水负载均衡能力：通过将模型首尾的计算密集层（Embedding、Logits）声明为"空操作层（No-Op Layers）"，使流水线并行各阶段的实际计算负载趋于均匀，从而消除空泡、加速大模型训练。

---

## 【技术要点】

1. **针对的两类计算密集层**：分别是网络起始的 **嵌入层（Embedding Layer）**——涉及大规模词表索引查找与高维稀疏→稠密转换；以及网络末端的 **对数几率层（Logits Layer）**——一个将隐藏状态映射到输出空间的全连接层，在大规模分类任务中权重矩阵极大、矩阵乘法成为瓶颈。

2. **核心机制——空操作层（No-Op Layers）**：将指定层标记为"不执行实际计算的空层"，仅在流水线划分中占据一个 stage 的"位置"，但其内部不做前向/反向运算。其目的是让原本集中于首尾 stage 的重计算被均匀摊薄到多个 stage 上。

3. **启用方式**：通过两条命令行参数组合：
   - `--num-layers <总层数>`：模型在并行切分时使用的总层数（含空层）。
   - `--noop-layers <索引列表>`：被声明为空操作的层编号（**从 0 开始计数**）。

4. **典型示例（原文给出的唯一具体数值）**：原模型 126 层 → 改为 `--num-layers 128 --noop-layers 0,127`，即在首（编号 0）与尾（编号 127）各加 1 层空层，中间仍是 126 层执行实际计算。

5. **使用约束**：新增空层后**总层数已变化**，流水线（及虚拟流水线 VPP）的切分配置必须按含空层后的新总层数**重新调整**，否则 stage 划分会错位。

6. **预期收益边界**：原文给出唯一一个定量结论——在 **类 DeepSeekV2、百亿参数级别的 MoE 模型**上，因末端 Logits 等计算负载不均导致的瓶颈场景下，端到端训练性能提升 **>10%**。该数字仅适用于"类 DeepSeekV2、百亿参数级 MoE、且瓶颈来自 Logits 等末端负载不均"这一具体语境，并非通用收益声明。

## 【关键机制与数据】

### 工作原理

- 流水线并行（Pipeline Parallelism）将模型按层切分到不同计算节点（stage）上，每个 stage 负责连续若干层的计算。
- 当首尾层（Embedding/Logits）天然比中间 Transformer 层重时，首尾 stage 的执行时间 > 中间 stage，形成**流水线空泡（bubble）**：其余 stage 在等待首尾 stage 完成时被迫空闲。
- No-Op Layers 把"位置"与"计算量"解耦：把原本挤在首尾 stage 的一层真实计算"挪"到中间某个已有空泡的 stage 中去执行（原文未给出具体的挪动算法/重映射规则，这是文档未展开的部分），从而让每个 stage 的 wall-clock 时间更接近，缩短整体流水线 step time。

## 【使用方法】

以下内容**完全来自原文**"使用方法"小节及文末 NOTE，未做任何补充：

1. **命令行参数**：
   - `--num-layers <N>`：模型的总层数（**包含空层**）。
   - `--noop-layers <i,j,...>`：被指定为空操作层的层编号，多个编号用英文逗号分隔；层编号 **从 0 开始计数**。

3. **附加约束（原文 NOTE）**：
   > 增加空层后总层数发生变化，需要根据**包含空层的总层数**重新调整**流水线（虚拟流水线）**的配置。
