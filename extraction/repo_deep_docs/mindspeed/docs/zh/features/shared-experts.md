# 共享专家特性 — 一体化深度解读

## 【定位】
本文档描述了在昇腾大模型加速库 mindspeed 中启用 MoE 模型的"共享专家（Shared Experts）"能力的方法与原理，旨在通过为部分专家配置为全数据通路、所有 token 共享计算，降低路由专家间的参数冗余、提升参数效率。

---

## 【技术要点】

1. **共享专家与路由专家并存架构**：MoE 模块中同时存在"路由专家"（需经路由模块按概率选取）与"共享专家"（所有输入数据必经，无需路由）；二者计算结果相加后作为 MoE 模块的最终输出。
2. **共性/差异性兼顾**：路由专家关注输入数据的差异性，共享专家关注输入数据的共性，结合后增强模型泛化能力。
3. **降冗余目标**：将一部分专家设为共享专家，用于抽取和整合不同上下文中的共同知识，从而减少其他路由专家中的参数冗余。
4. **使用前提（mcore 模式）**：开启共享专家必须在 mcore 模式下，即 **不能设置 `--use-legacy-models`**。
5. **共享专家数量配置**：通过 `--n-shared-experts [int]` 指定共享专家数量。
6. **隐藏层大小配置**：共享专家中间隐藏层大小的配置命令与路由专家相同，使用 `--ffn-hidden-size [int]`。
7. **MoE 模型类型前提**：需在 MoE 场景下使用，命令为 `--moe-model-type megatron_moe`。

---

## 【关键机制与数据】

- **工作原理（原文）**：输入数据经过路由模块后，概率较高的路由专家被选中进行计算；与此同时，共享专家不参与路由，所有输入数据都会经过共享专家计算。路由专家与共享专家的结果相加得到 MoE 模块最终输出。
- **数据流**：所有 token → (分支 A) 路由模块 → 选中的路由专家计算；(分支 B) 直接进入共享专家计算 → 两路结果相加 → MoE 输出。
- **性能数据**：原文未给出任何性能/精度/吞吐等量化数据，仅定性说明"减少参数冗余、提高参数效率、确保每个路由专家专注于独特方面"。

## 【关联】

- **MoE（混合专家）模型**：共享专家特性是 MoE 架构内部的一种专家分工策略，依赖 `--moe-model-type megatron_moe` 开启 MoE 模式。
- **路由专家（Routed Experts）**：与共享专家互为补充，二者并存于同一 MoE 模块、计算结果相加。
- **mcore 模型模式**：开启共享专家的前提条件，与 `--use-legacy-models` 互斥（必须未设置 legacy 模式）。
- **外部参考文献**：DeepSeekMoE 论文 *Towards Ultimate Expert Specialization in Mixture-of-Experts Language Models*（arxiv:2401.06066），用于了解共享专家的原始设计动机与理论基础。

## 【使用方法】

**启用前提：**
- 使用 MoE 模型类型：`--moe-model-type megatron_moe`
- 使用 mcore 模式（即 **不要** 设置 `--use-legacy-models`）

**配置项：**
| 配置项 | 取值/示例 | 作用 |
|--------|-----------|------|
| `--n-shared-experts [int]` | 整型，例如 `8` | 指定共享专家数量 |
| `--ffn-hidden-size [int]` | 整型 | 共享专家中间隐藏层大小（与路由专家共用同一参数） |

**典型启用方式（按文档字段组合）：**
```bash
--moe-model-type megatron_moe \
--n-shared-experts <int> \
--ffn-hidden-size <int>
# 注：不得同时设置 --use-legacy-models
```
