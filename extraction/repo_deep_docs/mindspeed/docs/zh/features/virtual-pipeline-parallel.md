# Megatron虚拟流水线并行 — 一体化深度解读

---

## 【定位】

这篇文档描述了在昇腾大模型加速库 mindspeed 中，如何通过 **虚拟流水线并行（Virtual Pipeline Parallelism, VPP）** 技术在不增加设备数量的前提下，将模型进一步细分为更多流水线阶段，从而降低 Megatron 流水线并行固有的空泡率、提升训练资源利用率与效率。

---

## 【技术要点】

1. **核心目标**：降低空泡率（无效或低效率计算周期占比），在原有流水线并行基础上"进一步细分计算任务"，代价是增加通信量。
2. **关键拆分规则**：模型总层数 = `流水线并行大小 × 虚拟流水线并行大小 × 每虚拟阶段层数`，原文给出的算例为 `16 = 4 × 2 × 2`，因此得到 **4×2=8 个阶段**，每个阶段 **16/8=2 个层**。
3. **调度顺序**：同一物理阶段内的多个虚拟阶段交替执行，原文算例的前向顺序为 `Device 0 → Device 1 → Device 2 → Device 3 → Device 0 → Device 1 → Device 2 → Device 3`，即"轮询"所有 4 个设备两轮。
4. **启用前置依赖**：必须先开启流水线并行（`--pipeline-model-parallel-size ≥ 2`），并要求模型总层数 `L % N == 0`（N 为每个虚拟流水线阶段的层数）。
5. **启用参数**：`--num-layers-per-virtual-pipeline-stage N`，N 即每个虚拟流水线阶段的层数。
6. **已知约束**：使用 verl 框架训练时，**mbridge 与 VPP 暂不兼容**，需在未开启 mbridge 时使用该特性；保存/加载权重时必须保持 VPP 配置参数一致，否则会影响权重的准确加载与系统稳定性。

---

## 【关键机制与数据】

**工作机制（原文算例）**：

- 模型总层数 **L = 16**，张量并行大小 **TP = 1**，流水线并行大小 **PP = 4**，虚拟流水线大小 **VPP = 2**。
- 实际被划分出的阶段数 = PP × VPP = **4 × 2 = 8** 个阶段；每个阶段包含 L / (PP × VPP) = **16 / 8 = 2** 个 Transformer 层。
- 各设备上的层分布（原文）：

    ```
    Device 0: [1, 2] [9, 10]
    Device 1: [3, 4] [11, 12]
    Device 2: [5, 6] [13, 14]
    Device 3: [7, 8] [15, 16]
    ```

  每个物理设备（Device 0~3）拥有 2 个虚拟子阶段，各包含 2 层；前半段（1~8 层）按顺序排在 4 个设备的第一个虚拟阶段，后半段（9~16 层）再轮询回到 4 个设备的第二个虚拟阶段。

- 前向执行流（原文）：`Device 0 → Device 1 → Device 2 → Device 3 → Device 0 → Device 1 → Device 2 → Device 3`。这种"轮询调度"使得任意时刻 4 个设备都能处于活跃计算状态，从而显著减少原本流水线尾部的空泡等待。

**性能结论（原文）**：通过虚拟流水线并行策略，在流水线并行的基础上"成功降低了空泡比率，进一步提升了模型训练的性能和资源利用率"。原文未提供具体的量化性能数字（如加速比、空泡率下降百分比），引用论文为 *Efficient Large-Scale Language Model Training on GPU Clusters Using Megatron-LM*（Berkeley，SC 2021）。

## 【公式解读】

**原文无 LaTeX/伪代码形式的公式**。

文档内出现的两处算式为自然语言中的算术表达：

1. **阶段总数**：4 × 2 = 8
   - 含义：阶段总数 = 流水线并行大小（4）× 虚拟流水线大小（2）。
   - 作用：确定模型被切分成的流水线阶段（虚拟阶段）数量。

2. **每阶段层数**：16 / 8 = 2
   - 含义：每阶段层数 = 模型总层数（16）/ 阶段总数（8）。
   - 作用：确定每个虚拟流水线阶段中包含多少个 Transformer 层。

3. **约束条件**：L % N == 0
   - L：模型总层数；N：`--num-layers-per-virtual-pipeline-stage` 的取值。
   - 作用：保证总层数可被每个虚拟阶段的层数整除，从而均匀切分。

4. **前置条件**：`--pipeline-model-parallel-size ≥ 2`
   - 作用：虚拟流水线并行依赖流水线并行存在，必须至少有 2 个流水线阶段才有"细分"的实际意义。

## 【关联】

1. **上游依赖：流水线并行（Pipeline Parallelism, PP）**
   - 文档开篇即引用内部链接 `./pipeline-parallel.md`，并明确指出"虚拟流水线并行依赖流水线并行"。
   - VPP 不能脱离 PP 单独使用：`--pipeline-model-parallel-size ≥ 2` 是硬性条件。

2. **平行策略：张量并行（Tensor Parallelism, TP）**
   - 算例中给出 TP=1。文档未单独说明 TP 与 VPP 的协同细节，但隐含 VPP 与 TP 可正交叠加。

3. **互补技术：**
   - VPP 通过"细分阶段 + 轮询调度"降低空泡率，属于 **调度优化** 维度；与之并列的常见空泡优化技术还包括 1F1B 调度、Interleaved 调度（即本文所述 VPP 本身）等。

4. **下游生态兼容性：**
   - 权重保存/加载流程依赖 VPP 的"层分割模式"，参数不一致会导致权重错位。
   - verl 框架 + mbridge：当前存在不兼容，需要在未开启 mbridge 的前提下使用 VPP。

5. **参考论文：**
   - *Efficient Large-Scale Language Model Training on GPU Clusters Using Megatron-LM*（Berkeley，SC 2021），给出 VPP 的理论分析与原始实验数据。

## 【使用方法】

### 启用条件（原文）

1. 必须已开启 **流水线并行**，即 `--pipeline-model-parallel-size ≥ 2`。
2. 模型总层数 L 必须满足 `L % N == 0`（N 为每个虚拟阶段的层数）。

### 启用命令（原文逐字保留）

```bash
--num-layers-per-virtual-pipeline-stage  N     # N表示每个虚拟流水线阶段的层数
```

### 注意事项（原文 NOTE 逐字保留）

- 启用 VPP 后，**权重的分割模式会发生变化**；在保存或加载权重文件时，务必保持 VPP 配置参数（`--num-layers-per-virtual-pipeline-stage` 与 `--pipeline-model-parallel-size`）的一致性，否则会影响模型权重的准确加载和系统的稳定运行。
- 使用 **verl 框架训练** 时，**mbridge 与 VPP 暂不兼容**，请在未开启 mbridge 时使用该特性。
