# Rec SDK TensorFlow 简介文档深度解读

---

## 【定位】

本文档是华为昇腾推荐SDK（Rec SDK）中 TensorFlow 训练框架的概览性介绍文档，定位为"功能地图 + 架构导读 + 硬件兼容性清单"：它向用户全景式呈现 Rec SDK TensorFlow 在推荐/搜索/广告场景下所能提供的训练能力、关键功能特性、软件架构分层以及所支持的硬件与操作系统，是用户进入 Rec SDK 体系后了解"能做什么、跑在哪、怎么分层、附录在哪里"的入口文档。

---

## 【技术要点】

1. **训练基础能力**：支持单机单卡、单机多卡、多机多卡分布式训练，基于 TensorFlow 开发生态。
2. **推荐场景必备能力**：基于稀疏表方案提供特征保存/加载、特征准入、特征淘汰、非亲和算子切分等能力。
3. **多级稀疏存储**：支持加速卡内存（片上/HBM）、主机内存（DDR）、主机磁盘（SSD）三级存储，**规模可超 10TB**，并支持存储动态扩容。
4. **动态扩容机制**：片上内存支持动态扩容与非动态扩容两种方案（前者显存随训练增长）；DDR/SSD 仅支持动态扩容（内存/磁盘增长，显存不变）。**开启动态扩容时需配合专用优化器**：`SGDByAddr`、`LazyAdamByAddress`、`AdagradByAddress`。
5. **特征准入与淘汰两种触发方式**：① 按 global step 间隔触发；② 按时间间隔触发。**限制：仅支持"只开准入"或"准入+淘汰同时开"，不支持"只开淘汰"。**
6. **定制 WarmStart 限制**——当前仅支持 **TensorFlow 1.15.0 版本**下的 **HBM 模式**和 **DDR 模式**，且 Embedding 表名目前不支持名称映射。
7. **增量模型保存与加载限制**：仅支持片上内存模式、DDR 模式、SSD 模式，以及 Estimator 模式下的 **train** 和 **predict** 模式（**不支持 train_and_evaluate**），仅支持扩容与非扩容场景，且**不支持与特征准入+淘汰同时开启**。
8. **自动改图约束**：只支持运行在 TensorFlow 默认图中，**不支持用户模型新建 `tf.Graph` 定义计算图**。
9. **性能/精度工具能力**：性能工具支持 Host 侧 profiling 采集、Host/Device 双侧融合、耗时排序与可视化；精度工具支持端到算子级精度比对。

## 【关键机制与数据】

### 软件架构

> 原文：Rec SDK TensorFlow 基于推荐场景主流框架、CANN 和各种硬件和网络，对于搜索、推荐、广告模型训练的应用场景需求，提供极简易用、高性能 API，助力昇腾 AI 处理器完成搜索、推荐、广告等模型的高效训练。

分层结构为四层（接口层 → 推荐功能层 → 推荐加速层 → 稀疏存储层），是一个典型的"用户接口—业务功能—性能加速—底层存储"的纵向栈式架构，**稀疏存储层是性能与可扩展性的根基，承诺"超 10TB"级别**。

### 动态扩容工作原理

> 原文：TensorFlow 对 Embedding 的支持是通过变量实现的，用户需要预估每个表的大小……Embedding 表的大小在一开始就确认，后期无法扩大或者减小，这可能会导致显存的浪费或者空间不足。在推荐场景下，多个稀疏表的大小无法预估，为更好的适配用户场景及需求，增加稀疏表动态扩容功能。

原理：原生 TF 中 Embedding 表大小静态预估，Rec SDK 通过改造使其随训练增长。**片上内存动态扩容**意味着显存（device memory）随训练增长；**DDR/SSD 动态扩容**意味着 host 侧内存/磁盘随训练增长，device 显存保持不变。

### 动态 shape

> 原文：Rec SDK TensorFlow 训练框架支持动态 shape。动态 shape 指的是 TensorFlow 的 shape 依赖于具体的运算，算子输入是动态 shape、算子输出也是动态 shape。

这是指算子级 shape 推断——输入输出的 shape 由运算本身决定，而非预先固定。

### 自动改图

> 原文：自动改图通过修改 TensorFlow 计算图的方式，使得用户训练脚本无需创建特征类（FeatureSpec），无需调用嵌入 read emb key 算子的函数即可开始模型训练。

机制：通过图改写（graph rewriting）在图构建阶段自动注入所需的特征读取算子，降低用户接入门槛。

### 特征准入与淘汰

> 原文：当某些特征的频率过低时，对模型的训练效果不会有帮助，还会造成内存浪费以及过拟合的问题。

原理：低频特征对模型收益小且占用资源，因此通过频率过滤"准入"；同时淘汰对训练无帮助的特征节约内存。触发方式为基于 **global step 间隔** 或 **时间间隔**。

### Hot_Embedding

> 原文：推荐场景下，Key 的重复率较高，Hot_Embedding 将重复度较高的 Key 放入缓存中来加速查表的速度。

利用推荐场景 Key 重复率高的特点，做高频 Key 缓存加速查表。

### 定制 WarmStart

> 原文：兼容原生 TF 的 WarmStart 功能，支持指定稀疏表的 WarmStart。支持多路径的 WarmStart……可支撑多模型迁移学习任务的训练。

支持从多个源域模型路径加载部分/全部参数，实现连续迁移学习。

### 增量模型保存与加载

> 原文：将稀疏的参数仅保存增量模型，会极大地降低频繁保存模型带来的额外开销。同时，在训练进程结束后能尽量通过一个最近的全量的模型配合一系列的增量检查点（模型）恢复最近一次训练完成的模型参数。

数据流：训练 → 接收新数据 → 训练 → **周期性保存全量/增量** → 恢复时 = 最近全量 + 一系列增量 checkpoint。

### 一表多查

> 原文：将对一张稀疏表的多次查询合并为一次查询。

减少对同一稀疏表的重复访存次数。

### PCIe through

> 原文：使用 PCIe through 流水并行换入换出，以共享内存承载数据交换，提高 Host 侧和 Device 侧之间的数据通信吞吐率。

机制：在 PCIe 通道上以流水线方式并行换入/换出，并使用共享内存（而非单一拷贝）作为 host-device 数据交换介质，提高吞吐率。

### 性能/精度工具

> 原文：性能检测工具支持 Host 侧 profiling 数据采集，Host 侧和 Device 侧 profiling 数据融合、耗时排序、可视化，支撑性能问题定位能力；精度看护工具支持端到端算子级精度比对，支撑精度看护、问题定位能力。

工具链：Host profiling → Host+Device fusion → 耗时排序 → 可视化（性能）；端到端算子级精度比对（精度）。

## 【表格解读】

### 表 1 Rec SDK TensorFlow 软件架构模块说明

| Rec SDK TensorFlow模块 | 说明 |
|--|--|
| 接口层 | 易用性接口，简化用户接入成本，支撑用户规模化上量。 |
| 推荐功能层 | 必备核心功能，满足用户使用的要求。 |
| 推荐加速层 | 性能竞争力核心组件，为整机系统方案提供更优性能。 |
| 稀疏存储层 | 支持超10TB大规模稀疏表存储。 |

**逐行解读**：

- **接口层**：面向用户的"易用性门面"，目标是降低接入门槛并支撑规模化推广（即把 Rec SDK 的能力以最简洁的 API 暴露出去）。
- **推荐功能层**：承载必备核心业务能力——对应文档前面提到的"特征保存/加载、特征准入、特征淘汰、非亲和算子切分"等业务级功能。
- **推荐加速层**：性能竞争力的核心来源——对应 Hot_Embedding、一表多查、PCIe through、自动改图等加速手段。
- **稀疏存储层**：底层数据基座，承诺"超 10TB"级别稀疏表存储，承载多级存储（片上/HBM、DDR、SSD）和动态扩容等能力。

四层是典型的"接口→业务→加速→存储"自上而下依赖关系——上层易用性、中层功能完整性、下层性能与可扩展性。

### 表 2 支持的产品列表

| 产品型号 | 产品架构 | 操作系统版本 |
|--|--|--|
| Atlas 800T A2 训练服务器<br>Atlas 200T A2 Box16 异构子框 | <li>ARM</li><li>x86_64</li> | <li>CentOS版本：7.6</li><li>OpenEuler版本：22.03</li><li>Ubuntu版本：20.04</li> |
| Atlas 900 A3 SuperPoD 超节点 | ARM | OpenEuler版本：22.03 |

**逐行解读**：

- **Atlas 800T A2 训练服务器 / Atlas 200T A2 Box16 异构子框**：作为同一档产品列出，二者架构选项相同（ARM 与 x86_64），OS 选项最丰富——CentOS 7.6、OpenEuler 22.03、Ubuntu 20.04，覆盖三种主流 Linux 发行版，适配面广。
- **Atlas 900 A3 SuperPoD 超节点**：定位更高端的"超节点"形态，仅支持 ARM 架构 + OpenEuler 22.03（这是华为自研 OS），组合更收敛，反映其在昇腾体系内的定位。

该表揭示：Rec SDK TensorFlow 在硬件上紧贴昇腾 Atlas 系列训练产品，OS 上覆盖 CentOS/OpenEuler/Ubuntu 三系，但**架构组合上**——A2 档更灵活（ARM/x86_64）、A3 SuperPoD 更专一（仅 ARM+OpenEuler）。

## 【使用方法】

**原文未涉及具体启用命令、配置项或安装步骤**。本文档作为 introduction 概览，仅在各功能特性的 NOTE 块中给出**使用约束与限制**而非启用方法，例如：

- 开启动态扩容 → 必须选用 `SGDByAddr` / `LazyAdamByAddress` / `AdagradByAddress` 等"按地址"优化器（而非原生 TF 优化器）。
- 自动改图 → 不能自定义 `tf.Graph`，必须跑在 TF 默认图中。
- 特征准入与淘汰 → 仅支持"只开准入"或"准入+淘汰同开"两种组合。
- 定制 WarmStart → 仅支持 TF **1.15.0** 的 **HBM/DDR** 模式。
- 增量模型保存与加载 → 仅支持片上/DDR/SSD 模式 + Estimator 的 train/predict（不可 train_and_evaluate），且不可与特征准入+淘汰同时开启。

**具体的启用方式、API 调用、配置参数需查阅 `../09_appendix/appendix.md` 对应章节及 GitCode `Ascend/RecSDK` 仓库中的算子样例 Readme。**
