# Rec SDK TensorFlow 简介文档深度解读

---

## 【定位】

本文档是华为昇腾-MindX **Rec SDK TensorFlow (tf_rec_v2)** 的**总览/简介**，解决的核心问题是：**向读者说明 Rec SDK TensorFlow 在搜索/推荐/广告模型训练场景下"提供了什么能力、由哪些软件模块组成、运行在哪些昇腾硬件和操作系统之上"**，从而为后续的安装、API 调用、特性启用建立认知基线。

---

## 【技术要点】

1. **训练基础能力**：支持单机单卡训练、单机多卡分布式训练，基于 TensorFlow 框架开发模型。
2. **推荐场景稀疏表四件套**：
   - **稀疏表创建**——入口 `get_embedding_table`
   - **稀疏表查询**——入口 `embedding_lookup`
   - **稀疏表保存与加载**——入口 `embeddingtablesaver`
   - **特征准入与淘汰**——同 `get_embedding_table` 入口下的 `min_used_times`、`max_cold_secs` 两个关键参数
3. **特征准入与淘汰机制原理**：低频特征对模型训练无帮助且浪费内存并造成过拟合，因此需准入过滤、需淘汰清理。
4. **保存与加载的语义**：保存 = 模型架构 + 权重 + 优化器状态的持久化；加载 = 恢复至可用状态，支持训练中断续训或部署推理。
5. **软件架构分四层**：接口层（易用性）/ 推荐功能层（必备功能）/ 推荐加速层（性能核心）/ 稀疏存储层（超 10 TB 容量）。
6. **支持的硬件与 OS 矩阵**：覆盖 Atlas 800T A2 训练服务器、Atlas 200T A2 Box16 异构子框（ARM + x86_64，三种 Linux 发行版）、Atlas 900 A3 SuperPoD 超节点（ARM + OpenEuler 22.03）。

## 【表格解读】

### 表 1　结构图模块介绍（原文逐字还原）

|Rec SDK TensorFlow模块|说明|
|--|--|
|接口层|易用性接口，简化用户接入成本，支撑用户规模化上量。|
|推荐功能层|必备核心功能，满足用户使用的要求。|
|推荐加速层|性能竞争力核心组件，为整机系统方案提供更优性能。|
|稀疏存储层|支持超10TB大规模稀疏表存储。|

**逐行解读：**

- **接口层**：最贴近用户的一层，价值定位是"**简化用户接入成本**"，目标是支撑用户从 PoC 到规模上量——意味着该层封装了底层繁杂的硬件/分布式细节，对外暴露易用 API（`get_embedding_table`、`embedding_lookup`、`embeddingtablesaver` 等即位于此层）。
- **推荐功能层**：定位为"**必备核心功能**"，对应文档"功能介绍"中的稀疏表创建、查询、保存/加载、特征准入/淘汰——即 Rec SDK 区别于普通 TensorFlow 训练框架的差异化能力集合。
- **推荐加速层**：定位为"**性能竞争力核心组件**"，向上对接口层和功能层提供加速能力，向下衔接稀疏存储层，是"整机系统方案"性能优势的主要来源（具体实现原文未展开）。
- **稀疏存储层**：唯一给出量化的层，**原文: "支持超 10 TB 大规模稀疏表存储"**——10 TB 这一容量阈值是文档中唯一明确的性能/容量数字，直接定义了 Rec SDK 在推荐场景下能承载的 Embedding 规模上限。

### 表 2　支持的产品列表（原文逐字还原）

|产品型号|产品架构|操作系统版本|
|--|--|--|
|Atlas 800T A2 训练服务器<br>Atlas 200T A2 Box16 异构子框|<li>ARM</li><li>x86_64</li>|<li>CentOS版本：7.6</li><li>OpenEuler版本：22.03</li><li>Ubuntu版本：20.04</li>|
|Atlas 900 A3 SuperPoD 超节点|ARM|OpenEuler版本：22.03|

**逐行解读：**

- **Atlas 800T A2 训练服务器 / Atlas 200T A2 Box16 异构子框（合并为同一行）**：硬件架构同时覆盖 ARM 与 x86_64 两种主流 CPU 生态；操作系统覆盖**三种**发行版——CentOS 7.6、OpenEuler 22.03、Ubuntu 20.04，意味着在该型号上部署 Rec SDK 时有较灵活的 OS 选择空间。
- **Atlas 900 A3 SuperPoD 超节点**：仅列出 ARM 架构 + OpenEuler 22.03，是面向更大规模训练集群（如超节点级互联）的硬件形态；OS 选项收敛到一种，反映出超节点形态的软硬协同要求更严格。**注意：Atlas 900 A3 SuperPoD 行只覆盖 ARM + OpenEuler，未列 x86_64 与其他 Linux 发行版——这是表格原文事实，不可外推为"同样支持"。**

   - 本文在"稀疏表创建"段落和"特征准入与淘汰"段落**两次**指向同一个接口，说明 `get_embedding_table` 同时承担"建表"与"配置准入/淘汰策略"的双重职责——`min_used_times`、`max_cold_secs` 是建表时就需设定的策略参数，而非运行时调用。

2. **稀疏表查询 → [`embedding_lookup`](../05_api/03_model_apis.md#embedding_lookup)**
   - 与 `get_embedding_table` 构成"写/读"对偶：前者建立并配置稀疏表，后者负责训练前向/反向时按 key 取出对应 Embedding 向量。

3. **保存与加载 → [`embeddingtablesaver`](../05_api/03_model_apis.md#embeddingtablesaver)**
   - 处于训练生命周期末端/恢复起点的角色：负责将稀疏表持久化（与 TensorFlow 自身的 Checkpoint 协同），并在恢复训练时回灌 Embedding，是"训练中断续训"机制的具体实现入口。

4. **上下游/层次关联**：
   - **上游**：基于 TensorFlow 框架 + 主流推荐框架 + CANN + 昇腾硬件 → Rec SDK TensorFlow 在此之上封装。
   - **下游**：用户自行开发推荐/搜索/广告模型，调用本文提到的四大 API 来使用稀疏表与训练能力。
   - **架构映射**：四大 API 全部落在"接口层"；其底层依赖"推荐功能层"实现，并由"推荐加速层"与"稀疏存储层（超 10 TB）"提供性能与容量支撑。
