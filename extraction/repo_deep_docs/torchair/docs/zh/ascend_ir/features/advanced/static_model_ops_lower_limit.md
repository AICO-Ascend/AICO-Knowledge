# 一体化深度解读：动静子图拆分场景性能优化

---

## 【定位】

这篇文档描述 TorchAir 在**动态图模式下**提供的一个**性能调优旋钮**——允许用户自定义**静态子图算子个数的下限阈值**，在"图下发/执行耗时"与"算子融合收益"之间做权衡，从而在不同网络结构下获得最佳执行性能。

---

## 【技术要点】

1. **核心场景**：动态图模式中，存在可被聚合为静态子图的算子段；N 个算子聚合为 1 个静态子图只需**一次下发**，减少逐算子下发的开销。
2. **三类性能权衡**（原文给出的三段定性观察）：
   - 静态子图内算子**越多** → 单次图下发 + 图执行**耗时越长**。
   - 静态子图内算子**越多** → 相对于"逐算子单独下发"，**节省的执行时间越多**。
   - 静态子图内算子**越多** → 算子间**融合可能性越大**，获得更高执行性能的可能性越大。
3. **核心结论**：静态子图算子数量**并非越多越好**，需在"下发耗时"与"执行收益"间取得抵消平衡点。
4. **适用约束**：本功能**仅适用于 GE 图模式场景**。
5. **配置入口**：通过 [`torchair.get_npu_backend`](../../api/torchair/get_npu_backend.md) 的 `compiler_config` 参数，最终位于 `config.experimental_config.static_model_ops_lower_limit`。
6. **取值语义**（整型，区间 `[-1, int64 最大值]`，**不含 0 和 1**）：
   - `-1` → 所有算子采用**动态执行**。
   - `0` / `1` → **不支持**（语义上自相矛盾，原文标注"不存在此场景"）。
   - `>1`（例如 `4`）→ **阈值**：子图算子数 **< 阈值** 时保留为动态下发；**≥ 阈值** 时聚成静态子图统一下发。

---

## 【关键机制与数据】

- **工作原理**：在动态图模式下，GE 引擎识别图中可被聚合的连续算子段，将 N 个算子打包成一个静态子图。`static_model_ops_lower_limit` 作为这一聚合操作的"**最小算子数阈值**"——低于阈值的算子群不会被提升为静态子图，而保持动态执行；达到或超过阈值的算子群才触发静态子图聚合与统一下发。
- **三因素耦合的取舍逻辑**（原文定性描述，非定量公式）：
  1. 单次下发/执行开销（与子图规模正相关）；
  2. 相比逐算子下发的累积耗时节省（与子图规模正相关）；
  3. 算子间融合带来的额外性能提升（与子图规模正相关）。
  
  综合上述因素，**最优子图规模**取决于具体网络的算子分布与计算密度。
- **默认行为**：若用户未设置该参数，则**沿用 GE 的默认值**（原文未给出 GE 默认值具体数字）。
- **原文未提供任何具体 benchmark 性能数据**（如延迟、吞吐、加速比等数值），也未引用外部测试条件。
- **原文未提供示例输出或实测对比表格**。

## 【使用方法】

> **原文已给出示例代码与配置项说明，逐字保留如下**：

```python
import torch_npu
import torchair
config = torchair.CompilerConfig()
# 在动态图中设置静态子图算子个数
config.experimental_config.static_model_ops_lower_limit = 4
npu_backend = torchair.get_npu_backend(compiler_config=config)
opt_model = torch.compile(model, backend=npu_backend)
```

**启用要点**：

1. **调用链**：`torchair.CompilerConfig()` → `config.experimental_config.static_model_ops_lower_limit = N` → `torchair.get_npu_backend(compiler_config=config)` → `torch.compile(model, backend=npu_backend)`。

3. **配置项语义回顾**：
   - `-1` ⇒ 全量动态执行，**关闭**静态子图聚合。
   - `≥ 2` ⇒ 按阈值分桶；阈值越高，单次聚合的算子群越大，融合机会越多但单次执行时间越长。
4. **作用域限制**：仅 GE 图模式场景生效（原文"使用约束"明确）。
5. **默认值**：未设置时使用 GE 默认值；原文未给出默认值具体数值，故**原文未涉及推荐默认值**。
