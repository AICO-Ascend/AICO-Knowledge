# 深度解读：TorchAir 设计文档模板

## 【定位】

这是一篇**设计文档撰写模板**，用于规范 TorchAir 项目中新增或修改特性时撰写设计文档的结构、章节内容、填写约定与评审流程，本身不描述具体功能实现。

---

## 【技术要点】

1. **模板结构覆盖七大主干章节**：总体概述、特性描述（含功能/非功能需求）、软件设计（含接口/算法/流程/子模块/维测）、资料修改、测试验收、评审意见与变更记录。
2. **占位符替换强制约定**：所有 `xxx`、`功能点一`、`模块1`、`意见1` 等占位文本必须替换为实际内容；不适用的条目必须填写 `NA` 并说明原因。
3. **converter 需求判定规则**：仅当特性涉及新增/补齐/修改 FX/ATen（或 `torch.ops`）节点到 GE/Ascend IR 的转换逻辑（含注册、dtype/shape/属性映射、cast/dtype promote、融合）时才属于 converter 需求；纯运行时或图优化不属于 converter 需求。
4. **converter 开发 6 项 checklist**：覆盖算子名清单、`declare_supported`/`Support` 声明、dtype 推导核对、算子适配层融合影响、冒烟测试（`tests/smoke/converter_test.py` 与 eager 对比）、异常输入/错误信息要求。
5. **测试用例固定表头**：包含编号、测试项、标题、重要级别、预置条件、输入、操作步骤、预期结果、执行情况、备注 10 列，并要求标明测试环境（CANN、torch_npu、TorchAir、PyTorch、Python、OS、硬件）。
6. **文档与 README 联动要求**：新增/修改特性需同步修改 `README.md` 特性介绍章节；对外接口新增或变更需同步修改 `SECURITY_README.md` 中 "TorchAir 常用类和公开接口介绍" 章节。

---

## 【关键机制与数据】

**工作原理（原文描述的设计文档撰写与评审流程）：**

- **第一阶段 — 总体概述**：声明特性名称与目的，并在文档开头声明测试环境（版本、性能、精度、测试结论均需注明）。
- **第二阶段 — 特性描述**：
  - 2.1 整体介绍：问题背景 → 竞品分析 → 当前现状 → 预期目标（功能、精度、性能可验证目标）。
  - 2.2 设计约束与依赖：明确支持/不支持场景、与其他特性的依赖和正交性、明确"不在范围"内容。
  - 2.3 功能需求：按"需求编号、优先级、前置条件、输入、处理、输出、验收条件"逐条列出功能点。
  - 2.4 非功能需求：版本兼容性（HDK/CANN、torch_npu/torchair、Python/PyTorch/OS/硬件）+ 编译/执行性能基线与目标。
- **第三阶段 — 软件设计**：对外接口 API 签名、关键算法（伪代码、复杂度）、关键数据结构、Mermaid/图片流程图、子模块改动清单（路径/改动点/接口）、可维可测（日志/调试开关/回滚）、错误码与日志级别。
- **第四阶段 — 资料与测试**：列出 README/资料修改项与对接人；构造基础用例、整网测试、converter 冒烟测试用例；明确功能/精度/性能/兼容性验收标准。
- **第五阶段 — 评审记录**：每条意见需包含评审人、日期、问题、处理结论、责任人、完成状态；变更记录需含日期、版本、变更人、变更摘要。

原文未提供具体性能数据、API、代码路径或数字指标。

- **测试用例标题**（验证模型图模式编译与执行）：说明用例验证目标，模板示例是端到端的图模式基本可用性验证。

- **预期结果**：要求双指标——编译和执行成功 + 与 eager 误差在容限内一致，对应功能与精度两个维度。
- **用例执行情况**（未执行）：状态字段，使用时应替换为"通过/失败/阻塞/未执行"等实际状态。
- **备注**（示例用例，使用时请替换）：模板自我标注，提示该行为示例内容，需按真实特性重写。

## 【使用方法】

**启用方式与填写步骤（原文给出的模板使用方法）：**

1. **复制模板**：将 `xxx`、`功能点一`、`模块1`、`意见1` 等所有占位符替换为实际特性名称、需求点、模块路径、评审意见；不得保留占位文本。
2. **按章节顺序填写**：
   - 第 1 节声明特性名称、目的与测试环境。
   - 第 2.1 节按"问题背景 → 竞品分析 → 当前现状 → 预期目标"顺序撰写，避免与总体概述重复。
   - 第 2.2–2.4 节填写设计约束、依赖、功能/非功能需求（含 HDK/CANN、torch_npu 兼容性矩阵）。
   - 第 2.5 节提供对外接口 API 签名、伪代码、Mermaid 流程图、子模块改动清单。
   - 第 2.6 节勾选 README.md 与 SECURITY_README.md 是否需修改及对接人。
   - 第 2.7 节按 10 列表格构造测试用例，覆盖功能/精度/性能/兼容性验收标准。
   - 第 2.8 节记录评审意见与变更日志。
3. **首次术语规范化**：缩写或专有术语首次出现时给出全称或定义，后续保持术语和大小写一致。
4. **converter 特性额外流程**：执行 6 项 checklist；在 `tests/smoke/converter_test.py` 路径下编写冒烟测试，使用 `python3 smoke/converter_test.py` 命令运行并与 eager 对比。
5. **不适用的处理**：任何不适用的条目填写 `NA/不涉及` 并说明原因。
6. **评审与变更追踪**：每条评审意见需含评审人、日期、问题、处理结论、责任人、完成状态；变更需记录日期、版本、变更人、变更摘要。
