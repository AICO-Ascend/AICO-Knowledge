# msModelSlim 架构文档深度解读

## 【定位】
本文档系统阐述 msModelSlim 量化压缩工具的整体架构设计，回答「如何组织、管理和沉淀模型量化与压缩相关知识」这一核心问题，描述其「知识领域+知识应用」双轨抽象与四层（接口/应用/领域/基础设施）分层架构。

---

## 【技术要点】

1. **四层架构划分**：msModelSlim 整体分为**接口层**、**应用层**、**领域层**和**基础设施层**，各层职责明确——接口层提供命令行工具（含一键量化、敏感层分析、自动调优等命令），应用层编排知识作业流，领域层封装知识领域，基础设施层完成外部依赖适配。

2. **量化模式（Quantization Mode）作为架构基石**：将一类模式一致的量化结构称为一种量化模式（例如 W8A8 INT8 静态量化）。一旦模式明确，量化结构的参数集合与量化/反量化过程随之确定，可预估理论性能与精度趋势。

3. **基于 YAML 的量化描述语言**：提供具有良好可读性、易调整性与可分享性的量化方案描述语言，算法配置透传至量化算法代码，格式允许算法专家自定义；推理专家无需编写算法代码，按约定格式录入参数即可触发算法执行。

4. **量化算法分类**：根据量化参数计算是否依赖激活值特征，分为**有校准算法**（需在特定数据集上推理以捕获激活值特征）与**无校准算法**（仅需加载权重即可完成参数计算）。

5. **细粒度校准单元拆解**：基于特定校准数据集的量化方案中，多算法参数校准过程被分解为一系列基本校准单元，每个校准单元以「**一批数据, 一段推理, 一个量化算法**」三元组表示，旨在充分利用算力与内存，以较低资源占用和耗时完成量化。

6. **模型适配两阶段设计**：① 组件内解耦（将各组件代码分解为「模型适配逻辑」和「核心机制」）；② 统一适配框架（聚合所有组件的模型适配逻辑到统一框架中，新增模型仅需新增适配器）。

7. **伪量化（Fake Quantization）机制**：利用高精度数值计算模拟低精度推理过程，还原输入输出映射，用于反馈量化精度；但因失去硬件亲和性，**无法获得量化带来的性能收益**。

8. **接口协议机制**：应用、领域和组件**显式地**提出对基础设施的诉求，归纳为「接口协议」；基础设施适配响应这些诉求。一个基础设施可同时实现多种接口协议。

## 【关键机制与数据】

### 工作原理与数据流

**量化三步法**（模型结构替换流程）：
1. **模式匹配**：找到需要替换的结构位点
2. **参数计算与结构创建**：计算量化参数并生成量化结构
3. **结构替换**：用量化结构替换原始结构

**三方协作链**：量化工具为量化结构准备量化参数和量化权重 → 算子提供设备亲和的量化结构实现单元 → 框架将算子组装成完整量化结构并加载权重/参数。

**IR 中间表示定位**：
- 原文: IR 是量化知识体系的**基石**，服务于所有推理框架和所有硬件设备；
- 原文: IR 不应绑定任何硬件设备，不还原推理框架的实际前向过程，而是对量化模式形式化描述，还原输入输出映射；
- 原文: 低精度数据格式的数值总能被高精度数据格式精确表示，因此不必依赖与硬件设备绑定的低精度量化算子。

**多卡量化权重合并策略**：原文: 在多卡加速场景下，不同卡各自负责部分量化结构，因此量化格式需要考虑如何合并多片量化权重（例如平均、拼接或选取主卡结果）。

### 量化模式示例
- 原文: **W8A8 INT8 静态量化**作为典型量化模式示例
- 原文: **W8A8 MXFP8** 量化精度损失小

### 模型结构识别示例
- 原文: 以 SmoothQuant 算法为例，平滑过程需要识别并处理 "Norm-Linear" 模型结构对；DeepSeek 模型与 Qwen 模型有着截然不同的 "Norm-Linear" 结构对。

## 【关联】

文档涉及多个核心抽象与模块的相互关系：

### 上下游与协作关系
- **量化团队 ↔ 算子团队 ↔ 推理团队**：基于统一量化模式理解，三方独立设计权重、算子和组图，最终合并验收部署。
- **量化工具 ↔ 外部基础设施**：与数据库、模型库、性能工具、测评工具、推理框架等协作；外部依赖在 msModelSlim 中统称为「基础设施」。
- **应用 ↔ 组件**：应用是抽象的流程，必须与具体知识组件结合才能完成任务。原文举例: 一键量化应用配合 DeepSeek 模型适配、W8A8 量化算法，实现 DeepSeek 模型 W8A8 量化；切换为 W4A8 仅需替换量化算法组件。

### 关键领域映射
- **`IR` 领域**：具体化量化模式，作为量化知识体系的基石，服务于所有推理框架与硬件设备。
- **`Processor` 领域**：管理量化算法（基于推理校准的模型子结构处理）。
- **`Model` 模型适配**：作为一种基础设施，体现内部知识（如算法、调度）对外部模型知识的依赖。
- **`Format` 领域**：承载量化格式知识，关注各量化模式参数的持久化方式与整体量化策略的描述方式。

### 接口协议层次
- **基础设施接口协议**：应用/领域/组件向基础设施提出的诉求。
- **模型适配接口协议**：内部知识对模型信息的诉求。原文举例: W8A8 MXFP8 量化未使用离群值抑制算法，则无需实现 SmoothQuant 接口协议；若 W8A8 已实现 QuaRot 旋转抑制接口协议，后续 W4A8 可继续复用。

### 算法 → 推理框架协同
原文: 量化结构替换需要与推理框架同步完成，而量化参数计算是量化工具的核心职责。
