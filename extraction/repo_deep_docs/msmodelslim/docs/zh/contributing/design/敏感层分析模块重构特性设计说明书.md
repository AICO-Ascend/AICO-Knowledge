# 「msModelSlim 敏感层分析模块重构特性设计说明书」深度解读

---

## 【定位】

这篇文档描述 msModelSlim 敏感层分析模块的重构设计：将原本独立的敏感层分析服务升级为可复用量化服务调度、可逐层调度与上下文管理、并具备可插拔 processor 与敏感度指标框架的调度化、算法化统一能力（落入版本 26.0.0，原文日期 20260122）。

---

## 【技术要点】

1. **调度复用**：在量化服务（Quant Service）现有调度框架（Scheduler → Runner → Processor）内增加敏感层分析调度流程，提供与量化一致的入口（`msmodelslim analyze`，原文"方案整体架构图"）。
2. **流程对齐**：支持逐层调度与量化感知上下文，使敏感层分析能够嵌入量化流程执行（原文 1.1 范围、第 3 条）。
3. **处理器抽象（processor）**：敏感度算法以可插拔 processor 形式组织，覆盖线性层与 attention 结构（含 MHA / MLA / DSA / SWA，原文"缩略语清单"）。
4. **指标统一**：敏感度打分采用统一指标接口（`SensitivityMetric`），支持可组合的多指标评分（原文 4.5 新增接口）。
5. **资源与硬件依赖**：依赖 NPU 设备，建议至少 32GB 内存、50GB 可用存储；操作系统 Linux，编程语言 Python 3.8+，依赖 PyTorch 与量化服务组件（原文 2.3.1、2.3.2）。
6. **兼容性约束**：保持对既有敏感层分析配置与调用方式的兼容，内部实现可替换（原文 1.2 备注、2.3.6、4.3）。

---

## 【关键机制与数据】

**工作原理（调度—算法分层，原文"方案整体架构图"）**

> 原文（mermaid）：
>
> ```
> U[用户命令行接口msmodelslim analyze] --> A[AnalysisApplication加载配置/初始化上下文/组织分析流程]
> A --> Q[Quant Service 调度能力]
> subgraph QS[Quant Service 现有调度能力]
>     S[Scheduler]
>     R[Runner]
>     P[Processor 机制]
>     S --> R --> P
> end
> Q --> S
> P --> AP[敏感度分析 Processor]
> AP --> M1[指标A]
> AP --> M2[指标B]
> AP --> M3[指标C]
> ```

机制要点（原文"处理流程"ASCII）：
1. 用户触发 `AnalysisApplication.run()`；
2. 调度层初始化上下文（加载配置 / 解析分析任务 / 注册 processor 与指标）；
3. 逐层调度执行敏感度分析（识别层类型与结构 → 选择并执行敏感度 processor → 指标子类计算评分 → 汇总结果并输出）。

**性能/资源数据（原文有）**：
- 内存：建议至少 32GB（原文 2.3.1）。
- 存储：建议至少 50GB 可用空间（原文 2.3.1）。
- 规避方案：资源不足时可减少分析层数或降低分析频次（原文 2.3.1）。
- 性能说明：调度开销可控；重构后通过调度与并行机制可降低单次分析整体耗时（原文 2.3.4、4.7.1）。**原文未给出具体耗时/加速比的量化数字**。

5. **日志与结果管理模块**：统一输出与可追溯性，原文 2.3、5.1。
6. **模型适配器**：提供结构信息与层级描述，原文 2.3 "需要模型适配器提供结构信息与层级描述"。
7. **评估特性 / 自动调优特性**：敏感度结果可能被引用，原文 2.3.7、2.3"与评估特性的交互"。
8. **量化主流程**：保持调度失败可隔离、单层失败不影响主流程，原文 2.3.5、4.7.3。
9. **attention 结构族**（MHA/MLA/DSA/SWA）：作为 processor 的结构适配对象，原文缩略语清单、4.6.3。

## 【使用方法】

**启用方式 / 配置项 / 命令（原文有）**：

- 命令行入口：`msmodelslim analyze`（原文"方案整体架构图"中 `U[用户命令行接口msmodelslim analyze]`）。
- 配置文件：统一采用 YAML 配置方式（原文 2.2 "统一的YAML配置方式"）。
- 调度入口：复用量化服务的调度入口（Scheduler → Runner → Processor 链路，原文图 1）。
- 新增/扩展接口（用于控制与扩展，原文 4.5）：
  - `AnalysisDispatchConfig`：配置模型，定义敏感层分析调度参数。
  - `SensitivityProcessor`：抽象接口，定义敏感度分析 processor 统一入口。
  - `SensitivityMetric`：抽象接口，定义敏感度指标的输入与输出。
- 量化调度入口扩展：支持敏感层分析调度任务注册（原文 4.5"修改接口"）。
- 平台/版本约束：Linux + Python 3.8+ + PyTorch + NPU 环境；建议内存 ≥ 32GB、可用存储 ≥ 50GB（原文 2.3.1、2.3.2）。
- 资源不足时：减少分析层数或降低分析频次（原文 2.3.1 规避方案）。
- 小型化部署：可关闭敏感层分析调度以减少资源消耗（原文 4.7.5）。

**原文未涉及**：具体的命令行参数完整列表、YAML 配置项完整 schema、processor / metric 的具体算法实现细节及自测用例的预期输出（原文 4.9 仅列出测试方向，未给出用例断言）。
