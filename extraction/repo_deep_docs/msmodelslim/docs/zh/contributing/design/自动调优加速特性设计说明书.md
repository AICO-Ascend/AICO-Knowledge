# msModelSlim 自动调优加速特性设计说明书 深度解读

---

## 【定位】

这篇文档解决的是 msModelSlim 已有「精度反馈自动调优」流程中的三类效率与可靠性痛点——量化模型输出乱码时仍跑完整测评、意外中断后无法恢复已评估结果、用户需手动配置算法搜索空间——并通过三个加速优化点（乱码跳过、断点续调、专家经验策略）来提升调优效率与鲁棒性。

---

## 【技术要点】

1. **三个核心 Use Case（即三个加速优化点）**
   - **Use Case 一 · 对话乱码时跳过数据集测评**：在精度评估前增加预检查（乱码检测），若判定为乱码则直接返回精度 0，跳过完整数据集测评。
   - **Use Case 二 · 自动调优支持断点续调**：通过精度缓存与历史索引复用已评估配置结果，支持调优中断后从断点恢复。
   - **Use Case 三 · 基于专家经验的调优策略**：新增 `expert_experience` 策略模块，按模型结构类型（MHA/MLA/DSA/SWA/GatedDeltaNet 等）自动查表生成搜索空间。

2. **三种调优策略与适配器接口契约**
   - `standing_high`：始终自动敏感层分析。
   - `binary_fallback`：配置了非空 `rollback_candidates` 时跳过敏感层分析。
   - `standing_high_with_experience`：另须实现 `StandingHighWithExperienceInterface`（含 `load_model`、离群值抑制探测）。
   - 三种策略在需自动敏感层分析时，模型适配器均须实现 `ModelSlimPipelineInterfaceV1`（即 `PipelineInterface`，与 CLI `msmodelslim analyze` 同）。
   - 敏感层分析由 `PipelineAnalysisService`/Runner 调用 `init_model`、pipeline 方法，策略侧不预先 `load_model`。

3. **量化—评估—调优—历史—适配器的模块交互链**
   - 调优依赖：量化服务模块、评估服务模块、调优策略模块、历史管理模块、模型适配器模块。
   - 调优成功后，最终量化配置可保存到「最佳实践库」。
   - 评估依赖 vLLM-Ascend 进行量化后模型的服务化启动与推理。

4. **关键性能与可靠性目标**
   - 预计节省 **10–30%** 的评估时间（基于乱码跳过与缓存复用）。
   - 调优成功率：已支持模型系列应达 **80% 以上**。
   - 断点续调恢复成功率：历史精度缓存恢复应达 **99% 以上**。

5. **硬件 / 软件 / 资源基线**
   - 硬件：至少 1 张 NPU 卡（推荐 2 张以上），至少 32GB 内存（推荐 64GB+），至少 100GB 存储（推荐 200GB+）。
   - 操作系统：Linux（推荐 Ubuntu 20.04+ 或 CentOS 7+）。
   - 语言/依赖：Python 3.8+；PyTorch；vLLM-Ascend；AISbench；Pydantic。
   - 用户接口：`msmodelslim tune` 命令行 + YAML 调优计划配置文件。

6. **License 合规边界**：引入 PyTorch（BSD）、vLLM-Ascend（Apache 2.0）、AISbench（Apache 2.0）、Pydantic（MIT）均为允许商业使用的开源许可，不影响项目 License。

## 【关键机制与数据】

**工作原理（按三个 Use Case 串接）**

1. **入口与配置**
   - 用户通过 `msmodelslim tune` 命令 + YAML 调优计划配置文件 触发自动调优。
   - 调优流程核心链路：量化服务 → 评估服务 → 调优策略 → 历史管理 → 模型适配器。

2. **Use Case 一 · 乱码预检查 → 跳过无效评估（原文 4.6.1 / 4.6.2）**
   - 在数据集测评前增加「乱码检测检查项」与「预检查流程」。
   - 检测到乱码 → 直接返回精度 0 → 跳过数据集测评，节省评估算力。
   - 数据流：模型量化 → 预检查（乱码检测）→ 若乱码则终止测评并记录精度=0；若正常则进入完整数据集测评。

3. **Use Case 二 · 断点续调（原文 5.6.1–5.6.4）**
   - 「精度缓存」记录已评估的量化配置—精度结果。
   - 「历史索引」支撑快速查找。
   - 「缓存复用机制」：重启调优时自动检测并复用历史精度缓存，避免重复评估。
   - 「断点续调流程」：意外中断（系统故障、手动停止等）后，从缓存恢复，继续迭代。

4. **Use Case 三 · 专家经验策略（原文 6.6.1–6.6.5）**
   - 新增 `expert_experience` 策略模块（新策略模块）。
   - 模型结构类型识别（MHA/MLA/DSA/SWA/GatedDeltaNet 等）。
   - 专家经验表存储「模型结构类型 → 算法搜索空间」的映射。
   - 自动查表机制按识别结果生成搜索空间，无需用户手填。
   - 策略实现方式封装在 `standing_high_with_experience` 路径上。

**性能/可靠性数据（原文有的才列）**
- 原文：节省 **10–30%** 的评估时间（乱码跳过 + 缓存复用）。
- 原文：调优成功率 **≥80%**。
- 原文：断点续调恢复成功率 **≥99%**。
- 原文：内存 32GB+（模型加载 10–50GB + 量化 10–20GB + 评估服务 5–10GB）。
- 原文：存储 100GB+（量化模型 10–50GB + 评估/历史 10–50GB + 临时 20–50GB）。
- 原文：NPU ≥1 张（推荐 2+）。

## 【关联】

- **与「量化服务模块」的关联**：调优依赖量化服务支持多种量化配置（Use Case 一/二/三都需要量化作为前置步骤）。
- **与「评估服务模块」的关联**：Use Case 一在评估前插入预检查流程，Use Case 二把评估结果写入精度缓存供后续复用。
- **与「调优策略模块」的关联**：在原有策略基础上新增 `expert_experience` 模块（Use Case 三），并区分 `standing_high` / `binary_fallback` / `standing_high_with_experience` 三种策略路径。
- **与「历史管理模块」的关联**：Use Case 二围绕精度缓存、历史索引、缓存复用、断点续调四个子模块（5.6.1–5.6.4），是历史管理模块的核心增强。
- **与「模型适配器模块」的关联**：所有策略共用 `ModelSlimPipelineInterfaceV1`（`PipelineInterface`）；`standing_high_with_experience` 额外要求 `StandingHighWithExperienceInterface`（含 `load_model`、离群值抑制探测）。
- **与「最佳实践库」的关联**：调优成功后，最终量化配置可保存到最佳实践库（用于复用）。
- **与 CLI 的关联**：`msmodelslim tune`（启动调优）、`msmodelslim analyze`（与 `PipelineInterface` 同源，可独立运行敏感层分析）。
- **与上游 SIG 的关联**：所属 SIG 组为 **msit**，落入版本 **26.0.0**（来自文档元数据表）。
- **下游依赖**：PyTorch（模型加载/量化）、vLLM-Ascend（量化后模型服务化推理）、AISbench（精度评估）、Pydantic（配置/数据建模）。
- **不涉及的关联**：原文 1.1 明确「精度反馈自动调优流程本身是已有功能，不在本特性范围内」，即三个加速点是叠加在已有自动调优之上的优化层，不重写主流程。

## 【使用方法】

- **命令行入口（原文 2.2）**：
  - 启动调优：`msmodelslim tune`
  - 配套分析：`msmodelslim analyze`（与 `PipelineInterface` 同源）

- **配置文件（原文 2.2）**：YAML 格式的调优计划配置文件。

- **关键配置项（原文 2.3 与其他需求及特性的交互分析）**：
  - `rollback_candidates`：`binary_fallback` 策略下，**非空时跳过敏感层分析**，为空时执行敏感层分析。

- **前置环境（原文 2.3.1 / 2.3.2）**：
  - 至少 1 张 NPU 卡（推荐 2+）；32GB+ 内存；100GB+ 存储。
  - Linux（Ubuntu 20.04+ / CentOS 7+），Python 3.8+。
  - 安装依赖：PyTorch、vLLM-Ascend、AISbench、Pydantic。

- **资源不足时的规避方案（原文 2.3.1）**：
  - 内存不足：减少 batch size 或使用模型并行。
  - 存储不足：定期清理历史记录或使用外部存储。

- **未涉及项**：原文未给出具体的 YAML 配置示例、具体 CLI 参数名（如 `--resume`、`--strategy` 等）或完整命令模板，亦未给出乱码检测阈值、缓存键生成算法（仅在缩略语表里出现 MD5，推测用于指纹但未在正文展开）。
