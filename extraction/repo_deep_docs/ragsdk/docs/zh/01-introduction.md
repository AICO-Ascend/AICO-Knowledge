【定位】
本篇文档是「ragsdk」(昇腾面向大语言模型的知识检索增强开发套件) 的总览级简介, 旨在向读者说明 RAG SDK 的产品定位、核心能力、软件架构层级划分以及所支持的硬件与操作系统, 作为后续模块化接口与垂域调优文档的入口。

【技术要点】
1. **产品定位**: RAG SDK 是昇腾面向大语言模型的知识检索增强开发套件, 解决大模型知识更新缓慢以及垂直领域知识回答弱的问题; 提供模块化功能接口 (含向量模型垂域微调数据生成、检索、知识管理等), 但不包含用户、权限等业务强相关功能。
2. **三大主要功能**:
   - 快速搭建: 提供模块化功能接口与预置端到端工作流模板, 用户通过极少量代码即可拉起问答服务。
   - 多模态解析: 支持文档、表格、PDF、图片等多种类型文件的解析, 为大模型提供多样性语料。
   - 高性能推理: 提供昇腾亲和模型优化加速, 提升吞吐、缩短响应时间。
3. **目标读者**: 华为技术支持工程师、渠道伙伴技术支持工程师。
4. **软件架构七层模块**: RAG Python API、知识管理、索引、向量化、检索、缓存、应用加速算子层。
5. **向量化双形态**: 支持本地部署和服务化部署两种形态, 服务化框架采用 text-embeddings-inference; 同时支持嵌入模型与重排模型 (embedding 类、reranker 类)。
6. **检索加速机制**: 利用昇腾 NPU 异构检索加速框架, 针对高维空间中的海量数据提供高性能检索; 流程包含查询转换→查询向量化→搜索与重排→结果回灌大模型。
7. **缓存机制**: 对接开源 gptcache, 支持完全一致缓存 (memory cache) 和语义相似缓存 (similarity cache)。
8. **支持的硬件 (3 类)**: Atlas 300I Duo 推理卡、Atlas 800I A2 推理服务器、Atlas 800I A3 超节点服务器。
9. **支持的操作系统 (13 项)**: 涵盖 Ubuntu 三个版本、KylinOS、BCLinux、EulerOS (aarch64/x86_64 多个版本)、openEuler、CUlinux、CtyunOS 等。

【关键机制与数据】
- **RAG 价值定位 (原文)**: 通过为大模型接入外部知识库, 有效提升问答系统的准确率, 解决大模型的幻觉和时效性问题; 以较低成本将基础大模型转换为领域专用大模型。
- **索引构建工作流 (原文)**: 语料收集 → 语料解析 → 语料切割 → 索引构建 (向量化), 生成的索引基于知识管理模块的内容, 并依赖向量化的结果完成检索的高效匹配。
- **检索数据流 (原文)**: 接收用户查询 → 调用大模型对查询文本进行查询转换 → 生成查询向量 → 依据查询向量进行搜索和重排 → 把搜索结果返回给大模型进行进一步处理。
- **知识管理范围 (原文)**: 支持用户创建多个知识库; 每个知识库可上传文档、表格、图片等文件; 检索时可选择作为大模型的外挂知识库。
- **缓存作用 (原文)**: 通过缓存已查询的结果减少重复计算, 提升检索速度。
- **应用加速算子层作用 (原文)**: 优化向量化、检索等核心模块的运行效率, 确保整体系统快速响应。
- **对接生态 (原文)**: 向量化层支持对接大语言模型、图像生成模型服务; 整体支持对接开源生态。

【关联】
- **RAG Python API (模块)**: 作为整套能力的对外门面, 向下调用知识管理、索引、向量化、检索、缓存与应用加速算子层的能力, 是用户实际接触的入口层。
- **知识管理 ↔ 索引**: 知识管理为索引提供数据基础; 索引依赖知识管理的内容并将其转化为可检索的向量结构。
- **向量化 ↔ 检索**: 向量化是检索的前置依赖 (embedding 类生成查询/语料向量, reranker 类用于结果重排); 检索又反向消费索引产物, 三者形成"语料→索引→检索"链路。
- **缓存 ↔ 检索/向量化**: 缓存层对接 gptcache, 对检索/向量化的中间及最终结果进行加速, 减少重复计算。
- **应用加速算子层**: 横切于向量化与检索, 提供昇腾亲和的算子级优化, 向上确保整个 RAG 流水线的吞吐与时延表现。
- **外部生态对接**: 向量化层对接 text-embeddings-inference (服务化框架) 与第三方大语言模型、图像生成模型服务; 缓存层对接开源 gptcache; 整体支持对接开源生态。
