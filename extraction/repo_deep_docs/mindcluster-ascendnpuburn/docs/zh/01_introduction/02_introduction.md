# 一体化深度解读：Ascend NPU-Burn 特性介绍

## 【定位】
本文档系统介绍 **Ascend NPU-Burn** 工具的四大核心能力（SDC 检测机制、压测用例、用例配置、多卡并行）以及整体软件架构，是面向昇腾 NPU 芯片/链路硬件的故障压测工具的能力总览页。

---

## 【技术要点】

1. **SDC 检测三步机制**：首次执行输出作 Golden 基线 → 后续执行结果与基线**逐元素比较** → 任何元素不一致即判定 SDC 故障；Device 侧带**超时阈值**保护，防止压测进程长时卡死。
2. **基础算子覆盖范围**：覆盖 **AIC、AIV、Atomic** 三类计算单元，以及 **Fixpipe 量化单元**与 **CV 同步**场景，覆盖面针对昇腾硬件特性。
3. **组合算子并行下发**：通过并行下发基础算子模拟复杂计算场景，目的是**提升压测效率**而非仅增加用例数。
4. **负向用例驱动失效模式**：通过分析实际故障场景挖掘失效模式，目标是**提升压测覆盖范围**（与正向用例互补）。
5. **多维可配置参数**：数据类型（FP32/FP16/BF16 等）、数据分布模式（**高斯分布、均匀分布**等）、Shape 大小三类维度，通过**配置文件**快速集成。
6. **多卡并行模型**：在 **OS 域内**多卡并行压测，通过**每进程绑定不同 NPU**实现并行执行（典型的进程级亲和性绑定）。

---

## 【关键机制与数据】

**SDC 检测工作原理（原文描述的工作流）：**

```
[首次执行]  算子 → 输出结果 → 存储为 Golden 值
[后续执行]  算子 → 输出结果 ─┐
                            ├→ 逐元素比较
            Golden 值    ───┘
                                ↓
                   任一元素不一致 → 判定 SDC 故障
```

**关键保护机制（原文）：** Device 侧每次执行设有**超时阈值**，超时即上报超时异常，防止压测进程长时卡住。

**压测用例三层结构（原文描述）：**
- **基础层**：单一基础算子 → 覆盖 AIC/AIV/Atomic/Fixpipe/CV sync 五类硬件单元
- **组合层**：基础算子并行下发 → 模拟复杂场景（提效）
- **负向层**：故障场景驱动 → 挖掘失效模式（提覆盖）

**并行模型（原文描述）：**
- 范围：**OS 域内**
- 方式：每**进程**绑定到不同 NPU（1 进程 ↔ 1 NPU 的亲和绑定）
- 拓扑：未涉及多机/跨 OS 域

**架构定位（原文）：**
- **基于**：PyTorch + CANN 框架
- **面向**：华为昇腾 NPU 芯片
- **角色**：检测工具（架构详见图1 `figures/architecture.png`，原文以图片占位符呈现，无内嵌文字细节）

> 注：原文未给出具体的超时阈值数值、卡数上限、AIC/AIV 的具体算子清单、FP32/FP16/BF16 的精度容差配置、Shape 范围等具体参数。
