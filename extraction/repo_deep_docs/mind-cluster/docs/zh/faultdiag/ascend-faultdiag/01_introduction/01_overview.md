# 一体化深度解读：ascend-faultdiag 概述文档

---

## 【定位】

本文档是 MindCluster 中 **Ascend FaultDiag (ascend-fd)** 组件的入门级总览文档，回答"这个组件是什么、能为昇腾 AI 集群做什么、在哪些场景下如何被集成使用"的问题——即一款面向昇腾 AI 集群的日志诊断工具，提供**日志清洗 + 故障诊断**两大核心能力，覆盖训练/推理任务异常退出与性能劣化场景。

---

## 【技术要点】

1. **工具定位**：ascend-fd 是面向昇腾 AI 集群的**日志诊断工具**，定位场景为训练/推理任务"异常退出或性能劣化"时的自动化分析。
2. **两大核心功能**：
   - **日志清洗**：对原始日志与监测指标信息进行过滤、提取有效信息。
   - **故障诊断**：基于清洗结果分析故障根因节点与故障事件，输出诊断报告。
3. **四种诊断类型**：
   - 根因节点分析（依据 HCCL 集群通信报错）
   - 故障事件分析（依据故障知识图谱中的故障模式）
   - 设备资源分析（定位计算降频与 CPU 资源抢占）
   - 网络拥塞分析（定位集群级网络拥塞）
4. **两种集成场景**：全量应用场景（依赖训练/推理、CANN、主机侧资源、硬件数据）与基础应用场景（仅依赖训练/推理日志与 CANN 应用类日志）。
5. **部署方式**：用户需在**每台设备**安装 ascend-fd 组件。
6. **标准使用流程（4 步）**：日志采集 → 日志清洗 → 清洗结果转储 → 故障诊断。

---

## 【关键机制与数据】

- **工作原理（原文串联）**：
  - ascend-fd 通过在每台设备上采集原始日志与监测指标数据 → 由清洗功能进行过滤与有效信息提取 → 将各节点清洗结果汇总（转储）至同一台设备/AI 运维平台 → 在该平台/通用设备上执行诊断，输出根因诊断报告。
- **数据来源差异**：
  - **全量场景（训练）**：训练日志 + 主机资源日志 + NPU 日志 + 硬件日志。
  - **全量场景（推理）**：推理任务日志 + CANN 应用类日志 + Device 侧日志 + MindIE 组件日志。
  - **基础场景**：训练/推理日志 + CANN 应用类日志（采集内容更简单）。
- **诊断依赖的关键数据/逻辑**：
  - 根因节点分析依赖 **HCCL 集群通信报错信息**；
  - 故障事件分析依赖**故障知识图谱中包含的故障模式**；
  - 设备资源分析关注**计算降频**与 **CPU 资源抢占**；
  - 网络拥塞分析关注**节点间网络状态**。
- **适用对象**：原文未提供具体性能数据（如诊断耗时、采样率、阈值等），均为定性描述。
- **原文标注的性能/数据**：原文无具体性能数字；所有描述均为能力性描述。

## 【表格解读】

### 表格 1：核心能力表（原文逐字还原）

| 能力 | 说明 |
|------|------|
| 日志清洗 | 对原始日志和监测指标信息进行清洗，过滤并提取有效信息，为诊断任务提供数据支持。 |
| 故障诊断 | 基于清洗后的数据，分析故障根因节点和故障事件，输出诊断报告。支持以下诊断类型：<ul><li>**根因节点分析**：根据集群通信 HCCL 报错信息，定位引发错误的根因服务器节点。</li><li>**故障事件分析**：根据故障知识图谱包含的故障模式，分析节点所在设备的问题。</li><li>**设备资源分析**：分析设备的资源状态，定位计算降频与 CPU 资源抢占问题。</li><li>**网络拥塞分析**：分析节点间的网络状态，定位集群场景下的网络拥塞问题。</li></ul> |

**逐行解读**：
- **日志清洗行**：作为故障诊断的前置环节，对象既包括原始日志，也包括监测指标信息；产出为"有效信息"，下游消费者是诊断任务。
- **故障诊断行**：承接清洗环节，输入是清洗后的数据，输出是诊断报告。其下细分四种诊断类型：
  - **根因节点分析**：依赖 **HCCL 集群通信报错**，输出是引发错误的根因**服务器节点**（粒度到"节点"，而非进程或任务）。
  - **故障事件分析**：依赖**故障知识图谱中的故障模式**，输出是节点所在**设备的问题**（粒度到"设备"）。
  - **设备资源分析**：聚焦设备资源状态，重点诊断**计算降频**与 **CPU 资源抢占**两类问题。
  - **网络拥塞分析**：分析**节点间网络状态**，针对的是**集群场景**下的网络拥塞。

### 表格 2：集成方案对比表（原文逐字还原）

| 场景名称 | 用户 | 任务类型 | 特点 |
|----------|------|----------|------|
| 全量应用场景 | 企业、政府、事业单位等（具有 AI 集群运维平台能力） | 训练任务、推理任务 | 依赖于训练或推理、CANN 和主机侧资源以及硬件相关数据，采集内容较复杂，适用于 AI 集群运维平台用户进行复杂的任务诊断。 |
| 基础应用场景 | 个人 | 训练任务、推理任务 | 可以仅依赖训练或推理日志与 CANN 应用类日志，采集内容和方法简单，适用于个人用户进行基础任务诊断。 |

**逐行解读**：
- **全量应用场景行**：用户门槛是"具有 AI 集群运维平台能力"（企业/政府/事业单位等）；任务覆盖训练 + 推理；数据依赖覆盖训练或推理层、CANN 层、主机侧资源层、硬件层，特点是"采集内容较复杂"、"适用于复杂任务诊断"，转储目标为 **AI 运维平台**进行根因诊断。
- **基础应用场景行**：用户为"个人"；任务同样是训练 + 推理；数据依赖仅训练/推理日志 + CANN 应用类日志，特点是"采集内容和方法简单"、"适用于基础任务诊断"，转储目标为"通用设备"。

- **功能上下游关系**：

- **集成场景与功能关系**：全量场景可调用所有诊断能力（因数据完整），基础场景因仅依赖训练/推理日志与 CANN 应用类日志，受限于数据可得性，更适合"基础任务诊断"。
- **使用流程链路**：日志采集 → 日志清洗 → 清洗结果转储 → 故障诊断，构成端到端使用闭环，"转储"环节在不同场景下目标不同（全量 → AI 运维平台；基础 → 通用设备）。

## 【使用方法】

- **启用/部署方式（原文）**：用户需在**每台设备**安装 ascend-fd 组件，使用清洗功能进行过滤、提取有效信息。
- **典型使用流程（原文逐字还原）**：
  1. **日志采集**：从各台训练/推理设备上收集日志文件。
  2. **日志清洗**：对日志进行清洗，提取有效信息。
  3. **清洗结果转储**：将各节点的清洗结果汇总到同一台设备上。
  4. **故障诊断**：分析故障根因。
- **两种场景下的差异化操作（原文）**：
  - **全量应用场景**：训练或推理任务结束后需采集对应全套日志与指标数据，转储至 **AI 运维平台**进行根因诊断。
  - **基础应用场景**：任务结束后收集训练/推理日志与 CANN 应用类日志，经清洗后转储至**通用设备**进行根因诊断。
- **配置项/具体命令**：原文未涉及具体的配置文件路径、命令行参数、API 调用方式等使用细节。
