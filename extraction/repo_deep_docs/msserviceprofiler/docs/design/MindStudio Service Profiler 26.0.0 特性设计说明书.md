# MindStudio Service Profiler 26.0.0 特性设计说明书 · 一体化深度解读

---

## 【定位】

本文档阐述 MindStudio Service Profiler 在 26.0.0 版本中围绕 **AI 推理服务化（vLLM、SGLang、多模态）** 场景构建的端到端可观测性增强方案，覆盖指标监测、Trace 链路追踪、性能剖析三大支柱，目标是为推理服务提供生产级可观测能力，支撑金融、云服务、企业级用户的监测、告警、容量规划与性能调优需求。

---

## 【技术要点】

1. **自定义指标采集与动态控制**：支持函数执行时间、内部变量、入参/出参作为 metric 值或 label，支持 `metric` 与 `profiling` 同函数同时采集，支持简单计算（数组长度、字典取值、类型转换）；通过修改配置文件可控制 metrics 采集启停，支持多次启停与配置热更新，且与 profiling 解耦控制以减小运行时压力。

2. **DP/Role 自动标签注入**：所有自定义 metric 自动包含 `dp` 和 `role` 两个 label —— 调度进程自动注入实际值，请求进程使用默认值 `-1`，重点解决 DP（Data Parallel）负载不均场景下的负载均衡问题排查。

3. **vLLM 核心指标 + 投机推理 + DPLB 指标**：复用 vLLM 原生 metric，采集 TPS、时延统计、时间拆解、BatchSize、输入/输出长度、DP 请求长度、block 数量分配等核心指标；投机解码侧采集平均接受步长、接受率、token 数量等；通过 Grafana 正确呈现。

4. **Trace 能力与大模型专家并行方案适配**：在 Motor 仓添加 Trace 采集，生成 spanID 与原有 TraceID 对接，并将 traceID 写入日志；通过环境变量支持 TraceID 自动生成，支持概率采样与错误采样机制，专门覆盖大规模专家并行方案（MoE）场景。

5. **SGLang 框架深度适配**：复用 vLLM 配置逻辑，支持 SGLang 服务化核心指标采集（调度执行过程、KVCache、请求队列）；在解析阶段自动使能 torch profiler 数据解析，并通过 service profiler 控制 torch profiler 的启停，支持堆栈、内存、采集步数等开关配置。

6. **存储与解析性能优化**：算子数据由原 CSV 改为 DB 格式以减少磁盘空间；变更落盘数据格式为可视化 slice 表，支持多 db 同时展示；提供 token 级采集（基于 step 函数触发，线程安全）、条件自动开启算子采集（按 batchsize 与发生次数触发）、快速解析流程、两份数据按 span 名称比对并输出 CSV 报告、span 关键信息汇总等能力；profiling 控制由文件修改改为 **命令行方式**，通过独立进程监测配置变化。

---

## 【关键机制与数据】

- **性能影响约束（原文）**："数据采集对推理性能的影响需控制在 **5% 以内**"；大数据量采集时的存储和传输开销需优化。
- **采集与展示链路（原文）**：数据采集 → 向上对接 Grafana 可视化、APM 调用链平台、告警通知系统；向下对接 vLLM 推理引擎、SGLang 框架、多模态模型；横向对接 Prometheus 监测系统、OpenTelemetry 标准、Torch Profiler。
- **运行约束（原文）**：操作系统为 Linux；编程语言为 Python，**python3.8 以上**；硬件支持昇腾 NPU 与 NVIDIA GPU；支持 CentOS、Ubuntu 等主流 Linux 发行版；支持 Docker、Kubernetes 容器化部署。
- **采集范围（原文）**：包含推理服务化场景的 **性能数据采集、数据解析、数据分析** 三大模块；并定义 5 大子能力域（指标监测体系、Trace 链路追踪、性能剖析能力、易用性、标准化建设）。
- **采样与触发机制（原文）**：TraceID 自动生成支持 **概率采样 + 错误采样** 两种触发；算子采集支持按 **batchsize 与发生次数** 条件触发，并支持自动关闭；token 级采集基于 **step 函数** 触发采集启停，强调线程安全。
- **数据存储演进（原文）**：算子数据由 CSV 改为 DB 格式以节省磁盘空间；落盘格式改为 **可视化 slice 表** 以提升解析性能；017 号需求明确指出需"提供大数据量告警和配置指导"。
- **标准化（原文）**：026 号需求要求"制定统一采集标准，规范 domain 和 span 定义，对外提供标准接口，统一解析逻辑"，奠定多框架统一标准基础。

## 【关联】

文档明确给出的横向、上下游关联关系如下：

- **向上（可视化与告警层）**：Grafana 可视化（用于 001、006、007、008 的指标展示）、APM 调用链平台（用于 Trace 接入）、告警通知系统（用于异常自动告警，见场景一-子场景1.2）。
- **向下（被监测对象）**：vLLM 推理引擎（001–008、018、024 主战场）、SGLang 框架（011–013）、多模态模型/vLLM-omni（014）、MindIE（016 兼容）。
- **横向（生态标准与工具）**：Prometheus 监测系统、OpenTelemetry 标准、Torch Profiler（016 接入）、Motor 仓（009 Trace 能力新增）。
- **内部产品集成**：与华为云 APM、Insight 可视化产品深度集成（027 提到 Insight 泳道优化）。
- **下游交付能力依赖**：
  - 001 监测大盘 ↔ 020 数据比对（009 Trace 提供数据基础）；
  - 001 ↔ 026 采集标准（标准化为多框架统一展示提供规范）；
  - 002 动态启停 ↔ 028 命令行控制（均为降低运行时压力与提升易用性服务）；
  - 011–013（SGLang 适配）↔ 026 标准化建设（复用 vLLM 配置逻辑并对齐标准）。
