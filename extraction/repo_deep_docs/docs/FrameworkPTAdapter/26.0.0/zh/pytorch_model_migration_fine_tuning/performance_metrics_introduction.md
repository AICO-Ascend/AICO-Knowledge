## 【技术要点】

1. **指标优先级排序明确**：原文给出固定的优先级链 `吞吐率 > 单步迭代时间 > 线性度 > 内存占用 > 带宽占比 > 训练效率 > 浮点计算次数每秒 > 算力利用率`, 意味着在进行性能问题定位与调优时, 应按此顺序逐级排查。
2. **双计量维度覆盖**: 吞吐率同时支持 `samples/s` 与 `tokens/s` 两种单位, 适配 CV/NLP 等不同模型族; 浮点计算能力以 `TFLOPS` 计, 与硬件算力比较直接挂钩。
3. **指标维度多元化**: 体系同时包含**时间维度**（单步迭代时间 s）、**比率维度**（线性度 values、内存占用 %、带宽占比 %、算力利用率 %）、**产出维度**（训练效率 tokens/day）、**算力维度**（TFLOPS）以及**通信/并行专项维度**（通信性能指标 %、Pipeline 并行效率指标 %）。
4. **指标分层思想**: 表 1 列出 9 个指标（含通信性能指标、Pipeline 并行效率指标两个专项项）, 但文档开头优先级链只列出 8 个, 说明通信与 Pipeline 并行效率作为**专项指标**在常规训练场景外独立考量。

## 【表格解读】

**表 1 性能指标说明**（原文逐字还原）:

| 指标名称 | 单位 |
| -- | -- |
| 吞吐率 | samples/s、tokens/s |
| 单步迭代时间 | s |
| 线性度 | values |
| 内存占用 | % |
| 训练效率 | tokens/day |

| Pipeline 并行效率指标 | % |

**逐行解读**:

| 行 | 解读 |
| -- | -- |
| 吞吐率 | 训练过程中单位时间处理的样本/Token 数量, 直接反映训练产能; 单位支持两种, 说明文档兼顾**样本级（CV 为主）**与**Token 级（NLP/LLM 为主）**两类模型的产出衡量 |
| 单步迭代时间 | 完成一次前向+反向+优化器更新所需的总时间, 单位秒; 用于定位时延瓶颈 |
| 线性度 | 多卡/多节点扩展时实际加速比相对于理想线性加速比的偏离程度, 单位 `values`（无量纲比值）; 越接近 1 表示并行扩展性越好 |
| 内存占用 | 已用显存占总显存的百分比; 决定能否上更大 batch 或更长序列 |
| 训练效率 | 长时间训练（一天）可处理的 Token 量, 是**产能维度**的长期衡量, 单位 `tokens/day` |
| 浮点计算次数每秒 | 硬件理论/实际算力指标, 单位 `TFLOPS`（10¹² 次浮点运算/秒）; 用于与硬件标称算力对比, 评估算子层面优化空间 |
| 算力利用率 | 实际 TFLOPS 占硬件峰值 TFLOPS 的百分比; 与上一项配合使用 |
| 通信性能指标 | 集合通信（AllReduce 等）效率占比, 单位 %; 在分布式训练中是带宽/延迟瓶颈的核心度量 |
| Pipeline 并行效率指标 | Pipeline 并行（流水线并行）场景下的气泡/有效计算占比, 单位 %; 用于评估流水线切分策略优劣 |
