## KV cache 复用谱系
- **vLLM / PagedAttention**（[[efficient-memory-management-for-large-language-model-serving-with-pagedattention]]，#52）：**谱系根**——首次把 OS 虚拟内存 + 分页引入 LLM serving：KV block(page) + block table(page table) + COW(fork) + 抢占式 swap/recompute。KV 有效利用率 20.4%(Orca Max) → 96.3%，吞吐 2–4× over SOTA。后续所有 paging/eviction/hierarchy 工作的 block 抽象来源。
- **SGLang RadixAttention**（#43）：把"简单系统提示共享"升级为"radix tree + 叶子优先 LRU + cache-aware 调度"多级树结构自动复用，覆盖 few-shot/self-consistency/multi-turn/ToT 四级共享模式。在 vLLM *显式* 前缀共享之上做 *自动* 前缀树复用。
- **Mooncake**（[[mooncake-a-kvcache-centric-disaggregated-architecture-for-llm-serving]]，#45）：**跨节点 disagg 锚点**。vLLM block 从"单机内存管理单位"推广为"跨节点调度/迁移/复制/swap 的全局单位"，KV 在 GPU/CPU/DRAM/SSD 分层迁移；KVCache-centric，prefill(compute-bound)/decode(memory-bound) 物理分离 + 全局池。reuse 逻辑与 vLLM 类似但 vLLM 仅本地（§6.1）。生产 trace：ArXiv +20%、L-Eval +40%、Simulated +50%~+525%、Real +75% 请求且 TBT 满足率 ~100% vs vLLM 57%；调度 TTFT 6.26s vs random 92.07s。
- **IndexCache**（[[indexcache-accelerating-sparse-attention-via-cross-layer-index-reuse]]，#1）：**跨层 sparse-index 复用锚点**——复用的是 sparse attention 的 *index 张量*（哪些 token 被 attend），不是 KV 张量；与 SGLang 前缀复用、Mooncake 跨节点 KV 池三条正交路径。1.82× prefill / 1.48× decode @ 200K，cross-layer overlap 0.7–1.0。正交于 [[kimi-linear-an-expressive-efficient-attention-architecture]]（架构级降二次 vs 算子级去冗余，可叠加）。DeepSeek-V3.2/GLM-5 默认 DSA-style sparse attention，作者预期 cross-layer index reuse 成前沿 LLM 推理标配。
- **Prefill-as-a-Service**（[[prefill-as-a-service-kvcache-of-next-generation-models-could-go-cross-datacenter]]，#58）：**跨 DC disagg apex**——把 prefill 当跨数据中心服务，KV cache 跨 commodity Ethernet 迁移。仅当 hybrid-attention 模型（KDA/SWA/linear）把 KV 吞吐 Φ_kv 降一个数量级才 plausible（MiMo 4.66 vs MiniMax-M2.5 59.93 Gbps @32K = 13×；Ring-2.5-1T ~36× KV 内存节省）。PrfaaS-PD vs Homogeneous PD vs Naive Hetero PD：Λ_max 3.24/2.11/2.45 req/s（1.54×），Mean/P90 TTFT 2.22/3.51s。Mooncake = intra-DC KV pool 根，PaasS = cross-DC 扩展（同 Moonshot AI 团队）。与 [[cacheblend-fast-large-language-model-serving-for-rag-with-cached-knowledge-fusion]] 正交可组合（非前缀 KV 融合复用 vs 跨集群 cache 传输）。
- **CacheBlend**（[[cacheblend-fast-large-language-model-serving-for-rag-with-cached-knowledge-fusion]]）：**多 chunk RAG 的 non-prefix KV 复用 + selective recompute 节点**——多 chunk 拼接输入下，full KV reuse 会丢 cross-attention（chunk 间 KV 偏差）。CacheBlend 仅重算每层 5–18% 的 HKVD（高 KV 偏差）token 恢复 cross-attention，并把重算与 KV 加载流水线隐藏。F1/Rouge-L 降 ≤0.02 质量无损下 TTFT 降 2.2–3.3×、吞吐 2.8–5×。构建于 [[efficient-memory-management-for-large-language-model-serving-with-pagedattention]] paged KV 之上（应用层复用）；§7.1 以 [[sglang-efficient-execution-of-structured-language-models-programs]] RadixAttention 识别高频 prefix 为 baseline，定位为 prefix caching 在多 chunk 输入下的推广。HKVD Insight 2（相邻层 KV deviation rank correlation）机制呼应 [[indexcache-accelerating-sparse-attention-via-cross-layer-index-reuse]]（前者挑待重算 token，后者加速 attention）。§9 明确未涉跨节点——与 [[mooncake-a-kvcache-centric-disaggregated-architecture-for-llm-serving]] 跨节点分发互补。是 [[a-survey-on-large-language-model-acceleration-based-on-kv-cache-management]] 中"non-prefix reuse + partial recompute"分支代表。
- **Huawei CloudMatrix384**（[[huawei-cloud-model-as-a-service-on-the-cloudmatrix384-superpod]]）：KV cache 跨 NPU P2P 迁移 + KV INT8 量化（non-RoPE 部分稳定）—— paging 思想在 Ascend SuperPod UB fabric 上的工业实例，对照 GPU/RoCE 系 vLLM/Mooncake。

## 调度谱系
- **SARATHI**（[[sarathi-efficient-llm-inference-by-piggybacking-decodes-with-chunked-prefills]]，#17）：**chunked-prefill 根**——prefill 切 ≤C chunk + piggyback decodes（decode-maximal batching）消 prefill bubble、提 GPU 利用率。decode per-token 12.49→1.2ms（~10×），GPT-3/64×A100 bubble 降 6.29×、端到端 1.91×。原实现用预分配 KV，§7.1 把 vLLM 列为互补（vLLM paged memory 天然吸收 chunk 边界，二者正交可叠加）。
- **Sarathi-Serve**（[[taming-throughput-latency-tradeoff-in-llm-inference-with-sarathi-serve]]，#18）：SARATHI 的 serving 化演进（同团队 MSR India + Georgia Tech），production-grade online server，新增 stall-free scheduling + token budget τ + PP 量化。
- **SGLang**（#43）：多调用间前缀复用调度，与 Sarathi 单 replica 内 prefill-decode 混合调度正交可叠加。

## 推测解码谱系
- **Medusa**（[[medusa-simple-llm-inference-acceleration-framework-with-multiple-decoding-heads]]，#2）→ **EAGLE**（[[eagle-speculative-sampling-requires-rethinking-feature-uncertainty]]，#4）→ **EAGLE-2**（[[eagle-2-faster-inference-of-language-models-with-dynamic-draft-trees]]，#5）→ **EAGLE-3**（[[eagle-3-scaling-up-inference-acceleration-of-large-language-models-via-training-time-test]]，#3）：多头/特征不确定性 → 动态 draft 树 → 训练时测试扩展。
  - EAGLE 是 **feature-prediction 分支 anchor**：复用 target LLM 末层特征、单头 1-layer draft（7B→0.24B 可训练参）+ **shifted-token（超前一拍 token）**消解特征自回归采样二义（Vicuna-7B speedup 1.9×→2.8×）+ Multi-round speculative sampling（§A.2 Alg.1）保 tree draft 下分布无损。上游 Medusa 多头独立预测，EAGLE 改单头特征级自回归链 + shifted-token 补无损 non-greedy 保证，取代 Medusa 成新 anchor。论文自承树结构 "not rigorously optimized"（§A.1）→ EAGLE-2 埋点。
  - EAGLE-2 = **context-aware 动态树**：把 EAGLE-1 静态直觉树换成 confidence-driven 动态树（draft 置信度 = 接受率代理，路径连乘打分 → top-k 扩展 → top-m reranking 保连通树不变式 → ancestor-only attention mask）。无需额外训练，复用 EAGLE-1 draft 模型。3.39×–4.10× @ T=0 vs EAGLE 2.78×–3.09×；τ≈4.6–4.7 vs EAGLE ≈3.7–3.9。confidence<0.05→accept≈0.04、>0.95→≈0.98 是经验基础。
  - EAGLE-3 = **training-time scaling + 多层特征融合**：去掉 EAGLE-1 的 feature prediction loss l_fea（其造成 train/inference 分布失配，1-α 崩到 ~0.25），改 top-layer 单层复用为 low/mid/high 多层 FC 融合 + **training-time test**（训练期执行多步 draft 生成，draft 自输出 a 回喂对齐推理分布）。首次发现 speculative draft 的 speedup-vs-data scaling law（EAGLE-1/2 曲线 flat，l_fea 设的天花板）；V13B T=0 MT-bench 3.07×→5.58×，~1.4× over EAGLE-2。SGLang batch=64 仍 +38%（EAGLE 此处转负）。与 DeepSeek-V3 MTP 双向启发（§2.2）。
  - MoE 局限：Mixtral 8x7B 仅 1.50×（expert 调度削弱算力复用红利），EAGLE 在 dense decoder-only 上最优。
- **Block Diffusion**（#6）→ **DFlash**（#7）/ **DSpark**（#8）：块级半自回归扩散解码分支。
- **DFlash**（[[dflash-block-diffusion-for-flash-speculative-decoding]]）：把 [[block-diffusion-interpolating-between-autoregressive-and-diffusion-language-models]] 从独立生成模型**重构为 speculative drafting adapter**——KV injection（per-layer target hidden-feature 条件化，替换 EAGLE 的 input fusion）+ random anchor sampling + loss decay 改造训练目标，把 block diffusion 限定在 drafting stage 规避 dLLM 质量劣势。单 forward pass 并行起草整 block，Qwen3-8B 上 6.1× 无损加速，比 SOTA [[eagle-3-scaling-up-inference-acceleration-of-large-language-models-via-training-time-test]] 快 ~2.5×；继承 [[eagle-speculative-sampling-requires-rethinking-feature-uncertainty]] feature-level context 思想，用并行 block drafting 替代 [[eagle-2-faster-inference-of-language-models-with-dynamic-draft-trees]] tree drafting、取代 [[medusa-simple-llm-inference-acceleration-framework-with-multiple-decoding-heads]] 串行多 head。固定 block 数 + random anchor 实现有界长上下文训练（4K base + 1.6K 样本微调适配 32K），与 [[jetspec-breaking-the-scaling-ceiling-of-speculative-decoding-with-parallel-tree-drafting]]/[[longspec-long-context-lossless-speculative-decoding-with-efficient-drafting-and-verification]]/[[specextend-a-drop-in-enhancement-for-speculative-decoding-of-long-sequences]] 同道但路径不同。
- **DSpark**（[[dspark-confidence-scheduled-speculative-decoding-with-semi-autoregressive-generation]]）：DFlash 的半自回归演进——DFlash 并行 backbone + 轻量 sequential head 建 block 内 token 依赖以抑制 suffix decay（修复 Medusa 并行 head 的 independence→suffix decay 问题），+ confidence head + STS 校准 + hardware-aware prefix scheduler 把验证长度选择形式化为**全局吞吐最大化**（而非单请求树扩展）。DeepSeek-V4 生产流量 matched throughput 下 per-user 加速 60–85%（Flash）/57–78%（Pro），扩出此前不可达的严格交互性 SLA 前沿。Qwen3-{4B,8B,14B} τ +30.9%/26.7%/30.0% over EAGLE-3。谱系线：Medusa（并行开端）→ DFlash（KV-injected 并行，强 position-1）→ DSpark（半自回归 + load-aware scheduling）；对照 Eagle/Eagle2/Eagle3（autoregressive 谱系）。
- **JetSpec**（#9）：并行树 drafting 破 scaling 上限——与 EAGLE-2 单树动态 shaping 正交可组合（并行动态树）。
- **LongSpec**（#59）/ **SpecExtend**（#60）：长上下文场景的 draft 与上下文增强。
- **Block Diffusion**（[[block-diffusion-interpolating-between-autoregressive-and-diffusion-language-models]]，#6）：**块级半 AR 扩散分支 anchor**——块间 AR + 块内离散扩散，block-causal attention 使 KV cache 兼容（Eq.7），carry-over unmasking 使 NFE≤L，支持变长生成（max 9982 tokens 超训练上下文 1024）。核心发现：L′=1 时扩散 NELBO 与 AR NLL 期望等价但有 ~2 点 PPL gap（根因：半数 token 被 mask 致梯度方差翻倍，NELBO 方差 1.52 vs 全 mask 0.11）→ clipped 调度 U[β,ω] + 数据驱动网格搜索降方差。LM1B PPL 28.23（MDLM 31.78）、OWT 20.73——扩散新 SOTA 但仍逊 AR（OWT 17.54）。纯扩散(L′=L)→BD3-LM→纯 AR(L′=1) 连续插值。
  - → **DFlash**（[[dflash-block-diffusion-for-flash-speculative-decoding]]，#7）：把 BD3-LM 块级半 AR 扩散适配到 flash speculative decoding；JetSpec 继承其 block-parallel draft head + fused target-feature 注入。
  - → **DSpark**（[[dspark-confidence-scheduled-speculative-decoding-with-semi-autoregressive-generation]]，#8）：同属半 AR 家族，confidence-scheduled 调度与 BD3-LM data-driven clipped schedule 同源。
  - 与 MEDUSA/EAGLE 分支互补：BD3-LM 把并行性放块内扩散（非 draft-then-verify 树），KV cache 复用历史块 KV（EAGLE 复用 target 末层特征）。变长生成是 LongSpec 长上下文推测需求的概念前驱。
- **JetSpec**（[[jetspec-breaking-the-scaling-ceiling-of-speculative-decoding-with-parallel-tree-drafting]]，#9）：**并行树 drafting 分支**——破 speculative scaling ceiling。tree-causal mask 把 EAGLE-2 path-conditioning 压进单次 forward（branch-wise 条件 vs DFlash branch-agnostic 边际），forward-KL distillation + tree-causal mask 作对齐机制（替代 EAGLE feature-uncertainty 处理）。budget-256 峰值 MATH-500 9.64×/τ10.76；reverse-KL 掉 36–46%。causal head 对 γ 鲁棒（8.29–8.50×），diffusion head γ 敏感（端点崩）。与 EAGLE-2 正交可组合（动态树形 × causal-parallel head，目前未合）。
- **LongSpec**（[[longspec-long-context-lossless-speculative-decoding-with-efficient-drafting-and-verification]]，#59）：**长上下文 SD 训练路线**——轻量独立 draft（滑窗 self-attn + 无 KV cross-attn 读 target，常数显存）+ Hybrid Tree Attention（Triton `fused_mask_attn`，Flash-兼容，EAGLE 仅 eager 故长上下文反慢于 Vanilla FA）。LC-13B/RepoBench-P 3.26×；QwQ-32B 长推理（32k output）均 2.34×。draft 质量与 prefill 长度无关。
- **SpecExtend**（[[specextend-a-drop-in-enhancement-for-speculative-decoding-of-long-sequences]]，#60）：**长上下文 SD 免训练/drop-in 路线**——Cross-model Retrieval（CMR）让短上下文 draft 适配长输入（target attention 选 top-k chunk 喂 draft）。不及 LongSpec 上限但 drop-in 可叠加；16K 三数据集 2.65/2.70/2.81×。CMR 救回 EAGLE-3 在 >2K 的精度崩塌（16K τ 1.49→3.80）。与 EAGLE feature-level draft 正交（一改 draft 生成、一改 draft context 视野）。
  - **长上下文 SD 路线分野**：LongSpec（training-based 独立 draft）vs SpecExtend（training-free/retrieval draft）。
- **Huawei CloudMatrix384 MTP**（[[huawei-cloud-model-as-a-service-on-the-cloudmatrix384-superpod]]）：vLLM/EAGLE MTP 默认调度有 stall，FlowServe 用 5 步 pipeline 消 CPU bubble；训练专用第二 MTP（28 万样本）使 tokens/step 2.26→2.35。MTP 是 speculative 在工业 serving 的部署形态。

## 训练系统谱系
- **Megatron-LM**（[[megatron-lm-training-multi-billion-parameter-language-models-using-model-parallelism]]，#49）：**模型并行根**——intra-layer tensor parallelism（column-parallel linear → row-parallel linear，fused pair 一次 all-reduce；f/g 共轭 autograd 算子）+ 与 pipeline parallelism 正交声明。无 compiler，原生 PyTorch。沿 MP 轴切分（vs ZeRO 沿 DP 轴切分，可组合）。峰值 15.1 PetaFLOPs @ 8.3B/512 GPU。
- **Megatron-LM 分布式**（#48）→ **MegaScale**（[[megascale-scaling-large-language-model-training-to-more-than-10000-gpus]]，#46）：**10k-GPU 生产 apex**——继承 Megatron TP/PP/DP+SP + interleaved 1F1B，推到 12,288 GPU / 55.2% MFU（1.34× over Megatron，2166 PFlops/s）。算法-系统协同（PTB/SWA/TP·PP·DP overlap）+ 容错（>90% 自动、<15min 恢复）+ 深可观测。DP overlap 直接基于 ZeRO2 all-reduce→reduce-scatter+all-gather 拆分。
- **ZeRO**（[[zero-memory-optimizations-toward-training-trillion-parameter-models]]，#47）：沿 DP 轴切分 optimizer state/grads/params，与 Megatron 沿 MP 轴切分**正交可组合**（Megatron-DeepSpeed 叠加）。MegaScale DP overlap 即基于 ZeRO2。
- **Megatron-Core MoE**（[[scalable-training-of-mixture-of-experts-models-with-megatron-core]]，#12）：在 Megatron MP/DP 拓扑之上的 **expert-parallel 全栈 co-design**——Parallel Folding（子模块级可折叠多维并行，EP 作为第五维与 TP/CP/PP/DP/SP 任意组合，§3.3.1）+ DeepEP/HybridEP（EP all-to-all 带宽优化与重叠，§4.2.2–4.2.3）+ Grouped GEMM/算子融合 + Sync-Free/ECHO/Paged Stashing 全程 CUDA Graph dropless + FP8/NVFP4 低精度。DeepSeek-V3-685B 在 GB30 上 1,230 TFLOPS/GPU（GB20 1,048）、Qwen3-235B 974/919。继承 [[megatron-lm-training-multi-billion-parameter-language-models-using-model-parallelism]] column/row-parallel GEMM + f/g 算子但把并行映射从"层"下沉到"子模块"；推广 [[megascale-scaling-large-language-model-training-to-more-than-10000-gpus]] 通信-计算 overlap 哲学到 EP all-to-all（拓扑比 TP all-reduce 难隐藏，需专用 kernel 非单纯 chunk pipeline）；FSDP-for-MoE 特化 [[zero-memory-optimizations-toward-training-trillion-parameter-models]] 分片（expert 沿 EP/attention 沿 DP，§4.1.7）；延续 [[efficient-large-scale-language-model-training-on-gpu-clusters-using-megatron-lm]] 生产集群定位。是 [[deepseek-v3-technical-report]]/[[kimi-k2-open-agentic-intelligence]] 量级 SOTA MoE 训练开源框架，与 [[huawei-cloud-model-as-a-service-on-the-cloudmatrix384-superpod]] 形成非 NVIDIA 硬件同类 MoE 训练产业对照。⚠️注：repo 内 PDF 仅含 Abstract+TOC（正文未抽取），具体逐节百分比/微基准标记为 not-available 而非臆造。
- **Megatron-LM 分布式**（[[efficient-large-scale-language-model-training-on-gpu-clusters-using-megatron-lm]]，#48）：**PTD-P 三维并行根**——在第一代 Megatron tensor parallelism（f/g all-reduce、column-parallel A / row-parallel B）之上叠加 pipeline 维度，tensor 切分 t 限制在单机 NVLink 内（t ≤ g），构成 PTD-P（inter-node pipeline + intra-node tensor + data parallelism）。**interleaved 1F1B pipeline schedule**（bubble 缩小 v 倍）+ scatter/gather 通信优化。3072 A100 上 1T 参数 GPT 达 502 petaFLOP/s（52% peak），端到端训练约 3 个月。§5.2 实证 PTD-P 在 GPU 翻倍时超 ZeRO-3 70%（根因：ZeRO-3 每层 all-gather 权重跨节点放大 vs PTD-P 权重永久驻留）。→ 启下 [[megascale-scaling-large-language-model-training-to-more-than-10000-gpus]]（interleaved 1F1B + scatter/gather 是 MegaScale 万卡扩展基础范式）；MoE 分支 [[scalable-training-of-mixture-of-experts-models-with-megatron-core]] 在此 3D 基础上加 expert 维扩到 4D；DP 路线常把 ZeRO-1/2 叠到 PTD-P 的 DP 维（vs [[zero-memory-optimizations-toward-training-trillion-parameter-models]] ZeRO-3 跨节点 all-gather）；⊥ 优化器轴 [[muon-is-scalable-for-llm-training]]；对拓扑高度敏感（1T pipeline bisection 892 GB/s、DP 12.9 TB/s）但只给启发式，[[from-atop-to-zcube-automated-topology-optimization-pipeline-and-a-highly-cost-effective-network-topology-for-large-model-training]] 从拓扑侧补齐自动寻优。
- **Muon**（[[muon-is-scalable-for-llm-training]]）：优化器轴——对标 AdamW（element-wise adaptive momentum），Muon 对 2D 权重矩阵经 Newton-Schulz 正交化 momentum。Scaling law ~2× compute efficiency（52% FLOPs 匹配 AdamW compute-optimal）；Distributed Muon 构建在 Megatron TP/PP/EP/DP 之上，ZeRO-1 gather 范围从 global 收窄到 DP group；仅 1 个 momentum buffer，额外内存为 ZeRO-1 AdamW 的一半。Appendix D：RMSNorm gamma 必须加 weight decay。MoE 侧线：Router 权重从 Muon 获益最大（SVD entropy 分析）。Muon 的 gather/compute overlap 与 MegaScale 的 TP/SP overlap 共享"通信-计算重叠"内核。

### 网络拓扑与自动化设计
- **[[from-atop-to-zcube-automated-topology-optimization-pipeline-and-a-highly-cost-effective-network-topology-for-large-model-training]]**（SIGCOMM '25）：**网络拓扑自动化设计分支锚点**——ATOP 把 DCN 拓扑建模为 11 类可搜索超参数 + NSGA-II 多目标进化 + 高保真 flow-level 仿真器（2-stage 评估减少 95% 全量训练仿真），自动涌现出非对称拓扑 **ZCube**（diameter=k，ZCube(128,2) 用 256-port switch 互联 16k GPU，diameter=2）。256–16384 GPU 全尺度比 ROFT/Rail-only/HPN 训练快 3–7%、成本降 26–46%、单 ToR 故障降级 46.9%→2.8%（真实 16-GPU testbed 验证）。上游接 [[megatron-lm-training-multi-billion-parameter-language-models-using-model-parallelism]]/[[megascale-scaling-large-language-model-training-to-more-than-10000-gpus]] traffic 模型（trace 来自 ByteDance 4k GPU ROFT 生产集群），下游对照 HPN/Rail-only/ROFT/BCube/Dragonfly 等"手工对称"拓扑；与 [[huawei-cloud-model-as-a-service-on-the-cloudmatrix384-superpod]] UB SuperPod fabric 形成"工业手工拓扑 vs 自动非对称拓扑"对比；补 [[efficient-large-scale-language-model-training-on-gpu-clusters-using-megatron-lm]]"拓扑敏感但仅启发式"缺口。MoE EP all-to-all objective 关联 [[scalable-training-of-mixture-of-experts-models-with-megatron-core]]，DP all-gather 1GB 目标关联 [[zero-memory-optimizations-toward-training-trillion-parameter-models]] ZeRO-3。优于 Condor（DSL 无法表达端到端 JCT）、adjacency-matrix 暴力搜索、TopoOpt（小规模 + optical switch 限定）。

## 归一化原语谱系
- **RMSNorm**（[[root-mean-square-layer-normalization]]）：**归一化家族根**（BatchNorm→LayerNorm→RMSNorm）——把归一化从 re-centering+re-scaling 缩减到 re-scaling 一项（去均值，仅 RMS+gain γ），7-64% faster、质量相当。现代 LLM 栈（LLaMA/DeepSeek/Qwen）默认归一化原语，"re-centering 非必要"工程共识的起点。
- **与 [[hyper-connections]] 正交可叠加**：残差拓扑承运层间流、RMSNorm 承运层内激活稳定；§7 明示与低精度、kernel fusion 正交。
- **与 [[muon-is-scalable-for-llm-training]] 稳定性耦合**：Muon Appendix D 指出 RMSNorm gain γ **必须施加 weight decay**，否则输出 RMS spike——补上 RMSNorm §4.2 留下的"γ 长期发散控制"缺口。

## KV-cache 架构性压缩谱系
- **GQA**（[[gqa-training-generalized-multi-query-transformer-models-from-multi-head-checkpoints]]）：**KV 架构压缩根**——MHA↔MQA 可调插值（GQA-1=MQA, GQA-H=MHA），分组共享 KV head；uptraining 配方把转换成本压到 ~5% 原预训练算力。GQA-8-XXL 0.28s（MHA-XXL ~18.5%）达 47.1（逼近 47.2），几乎与 MQA 同速且质量更高。
- → **MLA**（[[kimi-linear-an-expressive-efficient-attention-architecture]]）：GQA 思路的更深压缩继任——GQA=分组共享原始 KV，MLA=将 KV 投影到压缩潜空间。谱系：MQA → GQA（分组）→ MLA（低秩）。
- 与 [[efficient-memory-management-for-large-language-model-serving-with-pagedattention]] 正交叠加：GQA 在结构上缩小被分页的 KV 总量，PagedAttention 治理其碎片化分配；二者共构现代 serving 栈支柱。是 [[a-survey-on-large-language-model-acceleration-based-on-kv-cache-management]] 中 architectural KV-reduction 入口。

## RL 系统谱系
- **DeepSeek-R1**（[[deepseek-r1-incentivizing-reasoning-capability-in-llms-via-reinforcement-learning]]，#34）：**outcome-based RL → reasoning 自涌现里程碑根**。R1-Zero（纯 GRPO，无 SFT cold-start）涌现 "aha moment"；R1（cold-start SFT + 多阶段 RL + 蒸馏到 dense）。GRPO 弃 GAE + value model（§A.3）。AIME 15.6%→77.9%；147K H800-h ≈ $294K。建在 [[deepseek-v3-technical-report]]-Base（671B MoE/37B active + MLA + MTP）之上。

- **Search-R1**（[[search-r1-training-llms-to-reason-and-leverage-search-engines-with-reinforcement-learning]]，#25）：R1 + tool/search 扩展——interleaved <search>/<information> token + outcome-RL + **retrieved token masking**（Masked Log-Likelihood 隔离检索文档梯度，7b +25.6% rel）。最早确立 outcome-RL + tool-use rollout + token masking 范式；B=4 action budget 是后续 long-horizon/异步工作要突破的边界。PPO(7b-base 0.431) > GRPO(0.350)。
- **HybridFlow**（[[hybridflow-a-flexible-and-efficient-rlhf-framework]]，#30）：**灵活 RLHF 框架锚点**——single-controller dataflow + 低层 API（AdaptiveReplay/HybridEngine/Overlode）+ placement 自动搜索 + transfer protocol；RL 控制流与分布式计算解耦，几行切算法。连接"对齐 RL"与"推理/智能体 RL"的框架枢纽。1.53×–20.57× 加速。
- **AREAL**（[[areal-a-large-scale-asynchronous-reinforcement-learning-system-for-language-reasoning]]，#33）：**async-RL-system 锚点**——rollout/train 全 decouple + staleness-aware rate limiting + decoupled PPO 目标（Eq.4-5）。针对 R1 式 long-CoT（32K thinking tokens）rollout 长度剧烈波动。1.5B AIME24 42.2/14.8h（vs sync 41.0h），max speedup 2.77×；η=4 naive PPO 崩到 23.3、decoupled 恢复到 42.2（≈oracle 42.0）。75:25 device ratio，512-GPU linear scaling。R1-Distilled-Qwen 1.5B–32B 为 base。
- **R1 多阶段 RL pipeline** 是 HybridFlow §9 "from alignment to reasoning"展望的生产实例（reward model 换 rule-based/可验证 reward module）。
- **GEPA**（[[gepa-reflective-prompt-evolution-can-outperform-reinforcement-learning]]，#16/#19）：反思式 prompt 进化，可超越 RL——与 RL 路线互补对比。GEPA 在**复合多模块系统 + 富 textual feedback** 任务上省 ~35× rollouts 超 RL；但 **AIME 纯数学单步 CoT** 上 GRPO/R1 仍领先（Qwen3 8B: GRPO 38 vs GEPA 32）。GEPA budget 按 MIPROv2 逐基准对齐（≤10.15% 差异），GRPO 固定 24k rollouts——"省 rollout"是样本效率论证非严格同预算赛。GEPA 也可作 RL 系统 prompt 侧增强；与 Search-R1 形成 prompt-space vs weight-space optimization for tool-use 对照对。
- **GAE**（[[high-dimensional-continuous-control-using-generalized-advantage-estimation]]）：**foundational RL primitive 根**——指数加权 advantage 估计器（λ∈[0,1] 在 TD 与 MC 间插值），PPO 默认 advantage estimator。→ **GRPO 算法演化**：[[deepseekmath-pushing-the-limits-of-mathematical-reasoning-in-open-language-models]] 的 GRPO 显式去掉 value model + GAE，改用组内 mean/std 归一化回报作 advantage，是对 GAE 需学 V 这一工程负担的简化反应。R1/Search-R1/AREAL/HybridFlow 的 RL stack 建立在 PPO/GAE 家族或 GRPO 变体之上。
- **Agentic RL 旁系**：
  - **[[single-rollout-asynchronous-optimization-for-agentic-reinforcement-learning]]**（**SAO**：单 rollout async + DIS decoupled importance sampling + value 设计，修正 R1/GRPO group-wise 在异步场景失效；math 97.3/74.8/88.3/74.0，SWE-Bench 23.0→29.8；已部署 GLM-5.2 750B-A40B）。
  - **[[cuda-agent-large-scale-agentic-rl-for-high-performance-cuda-kernel-generation]]**：把 [[deepseek-r1-incentivizing-reasoning-capability-in-llms-via-reinforcement-learning]] 的"RL 激励内在推理"范式从文本推理迁移到 CUDA 优化推理——reward 从答案对错换成执行反馈驱动的离散 milestone {−1,1,2,3}。可扩展数据合成（6K operator-level 样本）+ skill-augmented 非 hackable agent 环境（离散 robust reward + 五重 anti-hacking）+ 三阶段 actor/critic warm-up（解决 BF16/FP16 importance-ratio 爆炸 + Value Pretraining 抗长轨迹 critic 崩塌）。Seed1.6 在 KernelBench Faster-vs-Compile 100/100/92%（L1/L2/L3），首次让 LLM 系统性超越 torch.compile 与 Claude Opus 4.5/Gemini 3 Pro 约 40pts。与 [[areal-a-large-scale-asynchronous-reinforcement-learning-system-for-language-reasoning]] 同处大规模 agentic-RL 工程谱系但走 CPU-GPU 解耦 sandbox + 同步 PPO（1024 batch / 128K context / ≤200 turns），对照同步 vs 异步取舍。继承 DAPO asymmetric clip（ϵ_lower=0.2, ϵ_upper=0.28）。产物（更快的 CUDA kernel）是 [[nanoflow-towards-optimal-large-language-model-serving-throughput]]/[[huawei-cloud-model-as-a-service-on-the-cloudmatrix384-superpod]] LLM serving 的性能底座——"AI 优化 AI 基础设施"闭环。
  - **[[beyond-ten-turns-unlocking-long-horizon-agentic-search-with-large-scale-asynchronous-rl]]**（**ASearcher**）：**long-horizon agentic search 突破 Search-R1 B=4 边界**——直接建在 [[areal-a-large-scale-asynchronous-reinforcement-learning-system-for-language-reasoning]] async-RL 系统底座之上（§1 "Building up on AReaL"），把 rollout/train decouple 从 long-CoT reasoning 推到 long-horizon tool-use：turn limit 128（vs Search-R1 ≤10 / 训练仅 4）、训练中 tool calls >100、output tokens >400k。算法仍用标准 GRPO（Eq.1，继承 R1/DeepSeekMath 弃 GAE+value 路线，见 [[high-dimensional-continuous-control-using-generalized-advantage-estimation]]→GRPO 演化），LRM 训练用 LLM-as-Judge（Qwen2.5-72B-Instruct）。直接对标 [[search-r1-training-llms-to-reason-and-leverage-search-engines-with-reinforcement-learning]]：Search-R1 仅 search tool + retrieved token masking；ASearcher search+browser 双 tool + 网页 summarization 也端到端 RL。134K 合成 QA 的 Injection+Fuzz 数据合成。GAIA/xBench/Frames Avg@4 = 58.7/51.1/74.5（vs Search-R1-32B 28.6/19.5/44.1，+30 abs）；+DeepSeek-V3 summarizer + K=16 test-time search → 71.8/75.0/83.4 逼近 [[kimi-k2-open-agentic-intelligence]] Kimi-Researcher（69.0/78.8/26.9）/o3（70.5/66.7/84.0）/Claude-4-Sonnet（68.3/64.6/80.7）。7B capacity 不足以学 webpage summarization（14B 后期才习得）——给出 end-to-end RL web summarization 的 scale 门槛。AREAL=系统层 async substrate，SAO=算法层 async effectiveness，ASearcher 复用 AREAL 系统底座但未做 SAO 式 decoupled importance sampling 算法层修正，用 LLM-as-Judge 软 reward + dynamic filtering 工程性绕开 staleness。HybridFlow data-future 是 sync 前身。

## 线性/混合注意力谱系
- **Gated DeltaNet**（[[gated-delta-networks-improving-mamba2-with-delta-rule]]）：**delta-rule 分支锚点**——Mamba2（gated decay 分支）与 DeltaNet（delta rule 分支）的合流点。把 Mamba2 对角 gated decay `St=αt St-1+vt kt^T`（标量 αt I）升级为 Householder 转移 `αt(I−βt kt kt^T)`，把"均匀遗忘"细化为"遗忘幅度 + 方向性"。沿用 Mamba2 SSD chunkwise 形式 + DeltaNet WY 表示/UT transform。S-NIAH-1 8K 91.8 vs Mamba2 30.4；DeltaNet 缺 forget gate 致 S-NIAH-2/3 长序列崩塌，GDN 补齐。
- **Gated DeltaNet / Mamba2 / GLA** → **KDA**（[[kimi-linear-an-expressive-efficient-attention-architecture]]）：KDA = GDN + **channel-wise 细门控**（每特征维独立遗忘率，GDN 是 head-wise 粗门控前身）+ DPLR 变体定制 chunkwise 算法。谱系：Mamba2 → GDN → KDA。
- **Kimi Linear** 3:1 混合 KDA 与全 MLA，首次公平对比下（1.4T tokens）混合线性架构**全面超越**全注意力（MMLU-Pro 51.0 vs 47.2、RULER 84.3 vs 81.3），KV cache −75%、1M 上下文 TPOT 6.3×。
- 互补 [[gated-delta-networks-improving-mamba2-with-delta-rule]]：同属 delta-rule 线性注意力改进分支，正交于 [[indexcache-accelerating-sparse-attention-via-cross-layer-index-reuse]] 的跨层稀疏索引复用。GDN 的 chunkwise scan kernel 是 [[parallel-scan-on-ascend-ai-accelerators]] NPU 并行 scan 优化的研究对象。

## 残差/层间拓扑谱系
- **[[hyper-connections]]**（ByteDance Seed, ICLR 2025）是基底方法：把残差连接换成学习的 `(n+1)×(n+1)` 连接矩阵（深度+宽度连接，可选输入自适应动态权重 DHC），是 Pre/Post-Norm → ResiDual/Altup 家族的可学习残差超类。
- **[[hc-manifold-constrained-hyper-connections]]**（DeepSeek-AI, arXiv:2512.24880, #36）/ **[[mhc-manifold-constrained-hyper-connections]]**：HC 的流形约束变体。把 HC 的 unconstrained `Hres_l ∈ R^{n×n}` 用 Sinkhorn-Knopp 投影到 Birkhoff polytope（doubly stochastic 流形），恢复 ResNet identity mapping 守恒性——spectral norm ≤1、矩阵乘法闭包、置换凸包语义。27B MoE 上复合映射 Amax gain 从 HC 的 ~3000 压到 ~1.6（减三个数量级），消除 HC 的 12k-step loss surge，7/8 下游 benchmark 优于 HC（BBH +2.1, DROP +2.3），`n=4` 仅 6.7% 训练时间开销。基座为 [[deepseek-v3-technical-report]]（MoE+MLA+DualPipe），kernel fusion + selective recomputing + DualPipe 扩展控开销。即插即用替换 HC，与 [[root-mean-square-layer-normalization]] 正交叠加。
- **[[attention-residuals]]**（Kimi Team, 2026-03）：HC/mHC 谱系的 **softmax 后继**——把 depth-wise aggregation 从 fixed 单位权重（Standard Residual，M 全 1 下三角 = 1-semiseparable）替换为 **input-dependent softmax attention over depth**（M dense rank-L）。机制上完成"depth 维度的 linear→softmax 过渡"，对偶 sequence 维度 RNN→Transformer。Full AttnRes 在 `O(Ld)` 内存/通信下不可扩展，Block AttnRes（N≈8 blocks）将成本降到 `O(Nd)` 且 per-layer I/O 仅 5.5d（vs mHC m=4 的 34d）；~1.4T-token 48B/3B MoE 上 1.25× compute advantage、GPQA +7.5/Math +3.6/HumanEval +3.1。形式对应 `M_{i→l}^{HC} = β_iᵀ A^{×}_{i+1→l} α_l`（α_l=query, β_i=key, A^{×}=position operator）。被 [[kimi-k3-open-frontier-intelligence]] 采用，与 KDA:MLA=3:1 hybrid（[[kimi-linear-an-expressive-efficient-attention-architecture]]）协同。
- **depth-sequence duality**（[[attention-residuals]] §6.1）：TTT/Fast Weight Programmers `W_t=W_{t-1}−η∇ℓ`（linear 退化为 `S_t=S_{t-1}+k_t v_tᵀ`，与标准 residual 深度累加同形）形式化对偶；DDL↔DeltaNet、MRLA↔GLA（[[gated-delta-networks-improving-mamba2-with-delta-rule]]）是同源对偶实例，AttnRes 是其中 softmax 分支。HC（linear/m-semiseparable）→ AttnRes（softmax/dense）是 depth 维度对 sequence 维度 RNN→Transformer 跃迁的镜像。
- HC 不增推理 KV-cache 开销（早期隐藏态可在下一层前释放），与稀疏注意力正交，可在长上下文部署中堆叠。
- **[[deepstack-deeply-stacking-visual-tokens-is-surprisingly-simple-and-effective-for-lmms]]** 概念相邻：DeepStack 的多层固定残差注入 ≈ HC 学习型拓扑在"视觉→语言"模态路由上的特例；HC 的可学习路由权重或可改进 DeepStack 的启发式注入（作者自列 future direction）。

## 多模态/VLM 谱系
- **Kimi-VL**（[[kimi-vl-technical-report]]）：MoE VLM（Moonlight MoE 上游，类 DeepSeek-V3）+ native-resolution vision encoder + pixel shuffle 2×2 空间压缩 + 2D RoPE。2.8B+0.4B act，128K context（NIAH text 87.0/video 91.7），24 项中 19 项超 Qwen2.5-VL-7B。long-thinking 继承 Kimi k1.5 online policy mirror descent + RL。是 EPD disagg 的典型目标 workload（ViT 与 MoE LLM 解耦天然适合 E/P/D 分离）。
- **Qwen2.5-VL**（[[qwen2-5-vl-technical-report]]）：dense VLM + window-attention ViT（仅 4 层全注意力 {7,15,23,31}）+ MRoPE 对齐绝对时间 + 绝对坐标 grounding + 统一 HTML omni-parsing。MMMU 70.2、ScreenSpot Pro 43.6、Android Control Low-EM 93.7（agent first-class）。Qwen3-VL 后继。与 Kimi-VL 路线对照：dense vs MoE、fixed-size vs native-res encoder。
- **DeepStack**（[[deepstack-deeply-stacking-visual-tokens-is-surprisingly-simple-and-effective-for-lmms]]）：**视觉注入方法锚点**——高分辨率视觉 token 经 2D spatial sampling 后残差注入 LLM 多个早期 decoder 层（DeepStack-L）或 ViT 层（DeepStack-V），context length 不变、架构不变、无新增参数。9-bench 均 +2.7/+2.9，高分辨率红利集中（TextVQA +4.2 / DocVQA +11.0 / InfoVQA +4.0）。可作为 Kimi-VL/Qwen2.5-VL/Qwen3-VL 的视觉 token 路由替换组件。
- 与 [[efficiently-serving-large-multimodal-models-using-epd-disaggregation]] 互补：EPD §C 列 visual token pruning 为未来方向；DeepStack 不 prune 而是把 token 从"输入层 prefix（入 KV-cache 昂贵）"转移到"中间层残差（廉价）"，可叠加共压服务成本。
- **[[kimi-k2-5-visual-agentic-intelligence]]**（见 frontier 谱系）：early-fusion 视觉路线对照——vs [[qwen2-5-vl-technical-report]]/Qwen3-VL 的 late-fusion vision-adapted；vs [[deepstack-deeply-stacking-visual-tokens-is-surprisingly-simple-and-effective-for-lmms]] 同属"简化视觉 token 处理"但 K2.5 走时空 patch-n'-pack、DeepStack 走深度堆叠。MoonViT-3D 继承 [[kimi-vl-technical-report]]（SigLIP-SO-400M + NaViT patch-n'-pack→时间维，弃 contrastive loss）。

## 长上下文模型谱系
- **DeepSeek-V4**（[[deepseek-v4-towards-highly-efficient-million-token-context-intelligence]]）：**百万上下文高效化锚点**——继承 V3 DeepSeekMoE+MTP，把 MLA 演化为 CSA/HCA 双重压缩+稀疏（Lightning Indexer 每层独立计算 indexer query/score）。V4-Pro 1.6T/49B act/1M ctx/33T tokens，V4-Flash 284B/13B/32T tokens。1M-token 效率 vs V3.2：Pro FLOPs 27%/KV 10%，Flash FLOPs 10%/KV 7%。双优化器：Muon 管 attention/MoE/mHC 动态映射，AdamW 管 embedding/RMSNorm/mHC 静态偏置。test-time scaling 承 R1/GRPO 路线延续。
- 与 [[kimi-linear-an-expressive-efficient-attention-architecture]] 对照：长上下文高效注意力两条主流架构解法——Kimi 走线性/混合（3:1 KDA+MLA），V4 走压缩+稀疏（CSA/HCA）。
- 与 [[indexcache-accelerating-sparse-attention-via-cross-layer-index-reuse]] 互补：V4 每层独立 indexer 是 IndexCache 跨层索引复用的潜在优化方向。
- 下游 serving：单 token FLOPs 压到 27%/10%、KV cache 10%/7%，为 [[longspec-long-context-lossless-speculative-decoding-with-efficient-drafting-and-verification]] 类长上下文 speculative decoding 提供低成本基座。

## 推测解码 tree-attention 分支
- **[[medusa-simple-llm-inference-acceleration-framework-with-multiple-decoding-heads]]**：多头并行预测 + tree attention 一次校验多候选，无需 draft 模型（>2.2× 无损 / 2.3-2.8× MEDUSA-2）。
- **[[deft-decoding-with-flash-tree-attention-for-efficient-tree-structured-llm-inference]]**：DeFT 是 attention kernel 层 IO 优化（非 draft/树构造优化），把 Medusa tree-attention 验证 kernel 换成 Flash Tree-attention——给定树拓扑下 attention 1.02-1.70× over Medusa attention，端到端解码最高 2.23×。KV IO 几乎不随候选树规模 `ln` 增长（73-99% KV IO reduction）→ 与 [[jetspec-breaking-the-scaling-ceiling-of-speculative-decoding-with-parallel-tree-drafting]]（并行树起草扩大候选）天然搭档。
- **EAGLE 系列**（[[eagle-speculative-sampling-requires-rethinking-feature-uncertainty]]/[[eagle-2-faster-inference-of-language-models-with-dynamic-draft-trees]]）改进 draft 质量 + 动态 draft tree；DeFT 仅优化给定树的验证 kernel，可作 EAGLE-2 动态树验证阶段的 drop-in 升级。
- **[[sglang-efficient-execution-of-structured-language-model-programs]]** RadixAttention 是 DeFT 最强 decoding baseline；DeFT 基于 paged memory，可作 SGLang attention kernel 的 drop-in 升级。

## 调度/disagg 谱系（第一轮深读补充）
- **[[taming-throughput-latency-tradeoff-in-llm-inference-with-sarathi-serve]]** = [[sarathi-efficient-llm-inference-by-piggybacking-decodes-with-chunked-prefills]] 的 serving 化演进：chunked-prefills + piggybacking 机制源自 SARATHI，Sarathi-Serve 做成 production-grade online server，新增 stall-free scheduling + token budget 调参 + PP 优化。同一团队（MSR India + Georgia Tech）。
- **两种 prefill-decode 干扰解法对比**：Sarathi-Serve 走 **collocated hybrid batch**（同 replica 内 chunk 混合，不需 KV 迁移但 prefill 不能完全高效）；[[mooncake-a-kvcache-centric-disaggregated-architecture-for-llm-serving]] 走 **disagg**（物理分离 + KV 跨节点池化，prefill 高效但需 KV 迁移）。论文 §6 把 disagg 列第三类并讨论 tradeoff。
- 与 [[sglang-efficient-execution-of-structured-language-model-programs]] 正交：SGLang 多调用间 KV 前缀复用，Sarathi-Serve 单 replica 内 prefill-decode 混合调度——可叠加。
- **EPD disagg**（[[efficiently-serving-large-multimodal-models-using-epd-disaggregation]]）：**多模态 disagg 分支**——把 disagg 维度从 2(P/D) 扩到 3(E/P/D)，Encode(vision encoder)/Prefill/Decode 跨资源。15× memory、22× batch、10× images、71% TTFT reduction；<0.7s role switch。Mooncake 是 text PD 根，EPD 是 multimodal E/P/D 扩展。Ascend 910B3 + Ascend-vLLM（同 Huawei 生态），NPU encode 占比更高（+10-20%）→ EPD 在 NPU 收益更大，为 [[huawei-cloud-model-as-a-service-on-the-cloudmatrix384-superpod]] superpod 的多模态 disagg 提供理论依据。
- **disagg 谱系纵深**：vLLM/PagedAttention(block 根) → Sarathi-Serve(collocated) / Mooncake(intra-DC disagg) / CloudMatrix(Ascend UB disagg) / EPD(多模态 E/P/D) / Prefill-as-a-Service(cross-DC)。collocated 与 disagg 在不同负载区间互补（EPD §B 承认 SLO 放松时 collocated 更优）。
- **[[nanoflow-towards-optimal-large-language-model-serving-throughput]]**：**intra-device 算子级重叠分支**——纠正"LLM serving 是 memory-bound"误区（§3.3 实测 compute-bound：Tcomp 114ms >> Tmem 45ms >> Tnet 31ms），用 nano-batching + 两阶段 MILP auto-search 在单 GPU 内重叠 compute/memory/network 三类异质算子。相对 SOTA 平均 1.91× 吞吐、达理论最优 50–72%。与 [[taming-throughput-latency-tradeoff-in-llm-inference-with-sarathi-serve]]/[[sarathi-efficient-llm-inference-by-piggybacking-decodes-with-chunked-prefills]] 正交（前者 iteration 层消 stall，NanoFlow 算子层消 bubble；NanoFlow 直接复用 Sarathi-Serve chunked prefill 做 batch formation）。在 [[efficient-memory-management-for-large-language-model-serving-with-pagedattention]] PagedAttention 之上（contiguous-then-scatter 加载策略为 page 碎片化设计），超 vLLM 4.18×。与 [[huawei-cloud-model-as-a-service-on-the-cloudmatrix384-superpod]] 形成对照——前者单 device 内算子重叠逼近上限，后者跨 device/流级 persistent kernel + overlapping streams；KV-cache CPU+SSD 分层 offloading（LRU + NUMA-aware, 7–10× 加速 copy）是 [[mooncake-a-kvcache-centric-disaggregated-architecture-for-llm-serving]] KV-pool disagg 的单机微缩版。与 [[sglang-efficient-execution-of-structured-language-models-programs]] 正交可叠加。
